# 2026-08-23 — v10src ships a damaged cmd/gcc

## TO FIX LATER: a working gcc

The build no longer needs gcc beyond its preprocessor, and the mkfile now builds
only the `cpp` target.  A working `gcc` — the driver, `cc1` and `gnulib` — is
still wanted, and needs these three files repaired first.

**The damage is upstream, not ours.**  `v10src.tar.bz2` downloaded fresh from
TUHS during this session has md5 `a07490fb33a6d83d4578dadb40a6aef4`, identical
to `work/v10src.tar.bz2`, and its `cmd/gcc/jump.c` and `cmd/gcc/local-alloc.c`
are byte-identical to our extracted copies (sha256 `e3814101…` and `8d3253a2…`).
It was damaged when the tape was written.

**It is filesystem damage, at 4096-byte granularity.**  Of 144 files in
`cmd/gcc`, three are affected:

| file | blocks | what is there instead |
|---|---|---|
| `jump.c` | 3 | a duplicate of block 2; leaves two `#endif` without an `#if` |
| `local-alloc.c` | 0 | the tail of GNU CC's `Makefile` (2691 bytes) then 1405 NUL bytes |
| `local-alloc.c` | 6 | 595 bytes of `rtx_renumbered_equal_p` code, then genuine text resumes |
| `limits.h` | 0 | the whole file — the *same* foreign block that overwrote local-alloc's block 6 |

One lost block was written into two places, which is why `limits.h:1` and
`local-alloc.c:727` both begin ` 0 for the whole things.  */`.  The full line
lives in `jump.c:1360` and `reload.c:769`.

Detection that works: NUL bytes, duplicate 4K blocks, unbalanced `#if`/`#endif`,
and a stray `*/` with no opening `/*`.  Together they find exactly these three
and nothing else.  Comparing against GNU CC 1.21 does **not** work — it flags 35
files, because V9.1's gcc carries real local changes.

**The base is GNU CC 1.21.**  Measured on the intact blocks only, 1.21 scores a
difflib ratio of 0.862 against 0.685 for the next best (1.29 and 1.30) and 0.678
for 1.25.  4.3BSD-Reno's `gcc-1.36.utah` scores 0.628, identical to stock 1.36,
so its local changes do not touch these files; 4.3BSD-Tahoe ships no gcc.

**V9.1's own changes, which any reconstruction must carry.**  In `jump.c`, four,
and the reconstruction in `v10/usr/src/cmd/gcc/jump.c` already carries them —
`diff` against 1.21 is those four hunks and no others.  In `local-alloc.c`,
twenty, visible in the intact blocks: `qty_reg_class` renamed `qty_min_class`;
forward declarations of `reg_meets_class_p`, `reg_class_subset_p` and
`update_qty_class`; the init loop split at `FIRST_PSEUDO_REGISTER` with
`qty_phys_sugg[i] = -1`; an added condition on `general_operand` commented
"Don't inhibit allocation of a \"constant\" register"; `reg_classes_fit`
replaced by `reg_class_subset_p`; and `reg_qty[regno] = -1` becoming `abort()`.
These are 1.25-era changes, but 1.25 fits the intact text far worse than 1.21,
so they were carried back rather than the file being 1.25's.

**State.**  `jump.c` is reconstructed and compiles.  `local-alloc.c` has its
block 0 reconstructed but block 6 is still foreign, and `limits.h` is untouched.
Neither is compiled by the current build.
