# 2026-08-29 — the ship loop that shipped nothing, and the tar of /usr grows teeth

## Twenty-two failures that were mostly one failure

W6 ran the full flow on a clone and 22 directories failed. W7 read the guest's
`libplot/lib4014/mkfile` and found the *old* text — every mkfile repair made
this window had stayed on the Mac. Two gates in updatebuild's ship loop were
wrong, and both failed silent:

- the loop read `/usr/src/build/mkfiles` — the **guest's** manifest, refreshed
  only by the handoff at the *end* of the script, so a row added since the last
  round never shipped;
- the directory gate was `test -d /usr/src/\`dirname $f\`` while the reversal
  made rows /usr-relative — `src/libplot/lib4014/mkfile` tested
  `/usr/src/src/libplot/lib4014`, false for **every** row, and "a missing
  target directory is the skip" is silent by design.

Both fixed: the manifest, casefix and arcfix are now all read from `$REPO`
directly, and the gate lost its stale prefix. The same audit found the manifest
carrying six rows for pre-rename archive-dir paths (`ratfor/old.a/`,
`oldplot/300.c.a/` …) and the regeneration command in its header not matching
its own rows; the header command is now the one that reproduces the file
exactly.

## casefix was broken three ways, found by reading it whole

The reversal converted column 2 of every row to /usr-relative but left
column 3 without the `src/` prefix, so every src rename tried to mv into
`/usr/cmd/...` — loud mv errors, no renames, since the reversal. The applier
read `op a b`, so a row carrying a comment swallowed it into the destination.
And `test -f` guarded mv, which a directory rename can never pass. All three
fixed (col3 repaired by script, applier reads a junk field and admits
directories), plus five rows I appended before reading the file turned out to
duplicate rows 97–101 — removed. The lesson is old: read the file, then write.

## PDP11 builds with make, because it always did

`cd /usr/src/cmd/PDP11; mk` said `don't know how to make ':'`. The mkfile was
ours — phase 6 converted the tree's Makefile, splicing a stray `:` into `all`'s
prerequisites and dropping a `-e` from a sed line. The superset has **no**
mkfile anywhere under PDP11: the tree is a cross-toolchain drop (its `init:`
says "Assumes that c compiler tape already installed") that builds by
recursing `make all ${PATHFLAGS}` into `11as/` and `11c/`. V10 carries make
precisely for trees like this. All four generated mkfiles (top, 11as, 11c,
fpp) deleted, their manifest rows with them; the attempt is now
`make all` against the tape's own Makefile.

## The afternoon: a stale log, and mk's environment

The W9 round was misread wholesale before it was read right: `/usr/tmp/build.log`
on the clone was W8's leftover — W9's ipnxbuild wrote only to the console — and
every "W9 context" pulled from it was a round old.  The console stream had the
truth: the new driver rows ran, and the failures that survived were new layers,
not the old ones.  Evidence files on a reused clone persist across rounds;
timestamp them or read the console.

Three failures fell to one discovery in mk's source.  `dovars()` (run.c:260)
puts `prereq` and `newprereq` into the environment of **every** recipe,
unconditionally.  libc.a's archive rule carries ~430 member names — about 13K
of environment against NCARGS 16K — so any exec whose argv adds the list dies
with `Arg list too long`: membername took it as argv in the tape-idiom rule,
`ar` took `$names` in the first rewrite.  Bell never saw it because their
libc.a always existed and newprereq stayed a handful; clean-then-build is the
novel path.  The rule now expands the list only in the echo builtin and feeds
membername, ar and rm through xargs batches.  Second casualty of cleanliness:
libcc's touch-stamp scheme (compile, archive, delete the .o, touch `<name>.t`)
breaks when a sweep takes libcc.a but not the stamps — ipnxclean now takes the
four stamps by exact name (wwb's `*.t` are tape troff data, so no pattern).
Third: V10's find takes one path; `find $SRC $SYS` answered `missing
conjunction` and swept neither root.

The compiler-family failures were conversion gaps, each named by the tape
itself: eqn's makefile carries `CC = lcc  # you will probably want to remove
this` and the converter dropped the block (restored); awk's converter-added
lex/yacc rules hardcoded `cc` where the file's own rules say `${CC}`; neqn had
a genuine cycle — the make-era `y.tab.h: e.o` materialization hack plus the
converter's real yacc rule — that mk refuses where make silently drops the
edge; gre's driver row passed `-DUSE_STDIO`, a flag the tape's own mkfile
carries commented out; worm's scsi tree selects its compiler in `research.mk`,
whose whole purpose is per-site choice — `CC=pcc` became `CC=lcc` there, pcc
being on no tape.  libdmalloc compiles with cc now: lcc's own stdlib.h
prototypes conflict with the tape's K&R malloc.c, and a probe showed cc takes
it clean.  The driver rows went back to bare `mk` wherever the mkfile already
binds its variables — the variables live in one place.

## divide.c, or the cost of "on no tape"

xref's `divide.s` is PDP-11 assembly — tst/bge/dec, refused line by line by
the VAX as — so the tape's xref never rebuilt on a VAX, and the machine's
untraceable `divide.c` was somebody's working port.  The morning's confident
`rm` row deleted the repair and the build promptly proved why it existed.  The
row is withdrawn, an explicit `divide.o: divide.c` rule settles the
two-source ambiguity, and W10's first act is to cat the file off a fresh clone
of the pristine images so the repository finally carries it.  "On no tape" is
provenance, not a verdict.

## The file that appears twice, and the recipe that may not speak

W10's fresh-clone run cured eqn, neqn, awk, gre and xref and then taught two
more lessons.  libc.a still failed with the OLD rule text because
`build/patch:2019` installs `build/src/libc/mkfile` — the embedded master from
the repair channel — over the tree copy, and the batching fix had gone to the
tree copy only.  A file that appears twice disagrees just like a list.  Both
copies now carry the rule, and the rule itself went through three deaths to
its final shape: mk substitutes `$newprereq` into the recipe TEXT and hands
the whole recipe to sh as ONE argument (besides dovars' unconditional env
export), so a 430-member rule may not name the variable in any form.  The
final recipe picks the members up from the directory (`ls | grep`) into a
temp file and xargs-batches ar and rm, excluding crt0.o, mcrt0.o and goo.o
by name.

pic and grap carried awk's exact converter disease — compat lex/yacc rules
hardcoding `cc ${CFLAGS}` — found only after their mkfiles' tape-instructed
double assignment (`you will probably want to remove this`) was reduced to
the single one the comment asks for.  worm advanced to its true end: tcl 3.3
inside scsi wants `sys/wait.h`, `O_CREAT` and `R_OK`, none of which V10 has —
counted absent from /usr/include — so scsish and jukebox join cfront in the
built-on-a-neighbor class.  backup.old, which only ever needed worm.a, got a
cross-directory rule (`$F/worm.a: cd $F; mk worm.a`) since the driver runs it
before worm's own row.  research.mk and divide.c now ride the mkfiles
manifest — the channel is `files the tree must have', and find can only know
the mkfiles, which the header now says out loud.

Remaining, and named: `cref ign' (make.c rejected by cc for its ANSI-isms and
by lcc for its K&R-isms — rot both ways), struct (0.alloc.c's int/pointer

members.  The jerq `src/lib/c` question stands for the keeper.

## W14, the handover round

libc.a took five rule shapes to build.  The last lesson was total: with ~430
member names in dovars' unconditional environment, `execve(/bin/sh)` itself is
over NCARGS — the rule that carries the list may spawn *nothing*, not even
`:`.  The final shape hangs the list on a recipe-less `:V:` aggregate (the
world target's own pattern, no shell ever spawns) and lets libc.a depend on
that alone, gathering members by glob into a temp file and batching ar and rm
through xargs.  Proven on the host oracle, then on the machine.
