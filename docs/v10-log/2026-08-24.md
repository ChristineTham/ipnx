# 2026-08-24 — why /bin/as faulted, and the one line that fixes it

`as` built from the tape's source died with a memory fault on any input large
enough to sort, while the tape's prebuilt binary assembled the same file. Six
library substitutions found nothing; one trace point found it in a single run.

The defect is in `as`, not in the toolchain: `assyms.c`'s `symcmp` is not
antisymmetric, and `libc`'s 1993 `qsort` recurses on the partition it produces.

## symcmp

    if (p->s_tag >= IGNOREBOUND)	/*p points to a jxxx*/
    	return(-1);
    if (q->s_tag >= IGNOREBOUND)
    	return(1);

The first test fires whichever way the pair is presented, so two jxxx entries
sharing `s_index` and `s_value` compare **−1 in both directions**. The comment
directly above asserts this cannot occur — "Both can't be jxxxes, as they would
have different values" — and nothing enforces it.

`libc/gen/qsort.c` is Bentley and McIlroy's. Its partition loops at `:73` and
`:77` are bounds-guarded by `pb <= pc`, so an inconsistent comparator cannot
walk off the array; what it does instead is make the partition degenerate, and
`:89-90` recurse on it —

    if ((s = pb-pa) > es) qsort(a,    s/es, es, cmp);
    if ((s = pd-pc) > es) qsort(pn-s, s/es, es, cmp);

— so the recursion never shrinks and the **stack** runs out.

Testing both sides restores antisymmetry and keeps the intent: a jxxx still
precedes a plain label at the same address, and two jxxxes now compare equal,
which is what the file's own comment says they are. It is in `build/patch`.

## Why it read as a heap problem and was not

The fault took a long time and left no core, which looks like runaway
allocation. It is neither.

`as` calls no `malloc` at all — every byte it owns comes through `Calloc`,
which is a bare `sbrk` (`assyms.c:164`); the only libc allocation in the program
is the three `fopen` buffers in `asmain.c`. So one trace point in `Calloc`
covers the whole memory history. Instrumented with `write(2)` and a hand-rolled
hex printer — not `fprintf`, since stdio was itself under suspicion — it showed:

    C 00000014 00015d1c 00015d30 00000014
    C 00001008 00015d30 00016d38 0000101c
    C 00001144 00016d38 00017e7c 00002160
    C 000012c4 00017e7c 00019140 00003424
    C 000012c4 00019140 0001a404 000046e8
    C 000012c4 0001a404 0001b6c8 000059ac
    C 000012c4 0001b6c8 0001c98c 00006c70
    C 00000ab8 0001c98c 0001d444 00007728

Eight allocations, every `sbrk` return exactly equal to the previous break,
30,504 bytes, and the break flat from then on. No growth, no interleaving with
malloc. The last block is `0xab8` = 686 × 4, which is `assyms.c:261`'s
`Calloc(nsyms + 2, sizeof *symptrs)` — the symbol pointer array. Markers inside
`sortsymtab` then gave `S2 qsort in` with no `S3`.

No core because `login.c:206` sets `vlimit(LIM_CORE, 1024*1024)` and the stack
had already grown past it.

## What the substitutions proved, and did not

Before the trace, each of these was swapped in and the fault survived all of
them — which is worth recording only because it shows how much a bisection over
components can cost when the defect is in the program itself:

| component | replaced with |
|---|---|
| `ccom` | the tape's `cmd/ccom/vax/comp` |
| `cpp`, `c2`, `ld`, `crt0.o` | the RA81's own, `Aug 21 16:48` |
| `libc.a` | the tape's `libc/libc.a` |
| the nine `as` objects | Bell Labs' own `cmd/as/*.o` |
| `-O` | dropped, so `c2` never runs |
| `:rofix` | skipped, `aspseudo.c` compiled normally |
| stdio | `ostdio.a` first, `__doprnt` linked and confirmed by `nm` |
| the whole library | `liboc.a` first |

Bell Labs' own objects faulting cleared `cpp`, `ccom`, `c2`, every compile flag
and the source tree in one measurement — and pointed at the link, which was
wrong. The objects were innocent; the *source* they were compiled from was not.

## The prebuilt binaries, and why they are prebuilt

The RA81's `/bin/as` is `cmp`-identical to the tape's `cmd/as/as`, so it was
copied in and never built here. Their binary carries `__doprnt` while the tape's
`libc.a` has exactly one `T _fprintf` — `stdio/fprintf.c`, the pANS one — and no
`__doprnt` anywhere; `as.Oct1986` sits in the same directory. Their `as` predates
their own libc, which is precisely why this defect never showed at Bell Labs: it
needs a 1993 sort to bite.

`cmd/ranlib` is prebuilt on the tape for the same era reason, but `ranlib.c` is
on secombe and compiles, so that one is built rather than shipped.
