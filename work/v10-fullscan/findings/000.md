## documented build steps

### `v10/usr/630/` (master makefile, `@(#)makefile 1.1.1.12 (6/5/87)`)

- **Standard targets, stated by the makefile itself** (lines 19-28): `build` — "builds all the
  products specified by PRODUCTS. This is the default for all makefiles."; `install`; `clean` —
  "removes all temporary files (ex. installable object)"; `clobber` — "'cleans', and then removes
  $(PRODUCTS)"; `tape` — "creates a new directory hierarchy for the app dev pack and copies all
  source files to that new dir."
- Default target here is `all` (line 91), *not* `build`: `all: v9support $(DMDCC) $(MC68SGS) $(COREPRODUCTS)`.
- **Ordering is explicitly load-bearing** — line 63: `# WARNING: order of the following macro
  definitions is important!` (guarding `DMDCC=src/dmdcc`, `MC68SGS=src/ccs`, `COREPRODUCTS=…`).
- **`v9support` must run before anything else** (93-95): `cd src/ccs/cmd/sgs/libld/mc68; make`
  then `cd 630mux; make`. The name says these two are the V9-host support pieces.
- Macros must be forwarded by hand to every descendant (58-59):
  `MACROS=MODE775=$(MODE775) MODE664=$(MODE664) TAPEROOT=$(TAPEROOT) ACTION=$(ACTION) MAKE_CMD=$(MAKE_CMD)`,
  because (53-56) "In order for the macro definitions specified on the command line to be passed

- Every descendant is invoked as `cd <dir>; exec $(MAKE_CMD) $(MACROS) $(ACTION)` — **except**
  `src/ccs` (127-130), which gets two explicit targets: `exec $(MAKE_CMD) $(MACROS) ACTION=$(ACTION) all libs`.
- `COREPRODUCTS` (71-88), in order: `src/lib/libj`, `src/lib/startup`, `src/lib/libjx`,
  `src/lib/libfw`, `src/demo`, `src/dmdcat`, `src/dmdld`, `src/dmdman`, `src/dmdversion`,

  `src/wtinit`. Libraries first.
- `tape` = `tape1 tape2 tape3 tape4` (106-119) = `makedir`, `cpmisc`, `src/ccs`,
  `$(DMDCC) $(COREPRODUCTS)`. Requires `TAPEROOT=` on the command line.
- Tools beyond cc/as/ld: `make` (`MAKE_CMD=make`), **`cpio`** (`cpio -pdv`, 27 invocations), `sh`.

- `makeall` (with no argument) runs `./makeman` over `find ?_man -type f -print`, skipping any
  file named `SOURCE`; with `-p` it runs `./pman -h` instead (`pman` is not in this tree).

  `tbl an $i |eqn| nroff -T37 >tmp` — the local `an` macro file is passed to **`tbl` as an input

### `v10/usr/630/bin/` (the installed commands)

- `build` is a `make` front end (`# @(#) build.sh	1.0	84Sep18	mikec`,

  assignment to be in the makefile", Michael Condict 9/84). It finds the makefile along `VPATH`,
  greps `^ *VPATH *=` out of it, `eval`s and exports it, sets `MAKE=/usr/630/bin/build`, then
  execs `/usr/630/bin/build.obj`.

  (modified)`. Needs `$DMD/bin/mc68nm`, `egrep`, `sed`, `sort`, `join`; writes `/tmp/$$symdef`

  `ismpx`, as does `tek4014:1`.
- `dmdman` needs `col`, `greek`, `xerox`, `pcat`, `find`, and honours `$TERM` values

- `630lfk` and `lib/samuel/samuel.sa` require SysV `echo -e`/`echo -n`; `dmdcat`/`wtinit` require

### `v10/usr/630/icons/`

- Icons are **not compiled**. `icons/texture/texture.icon` is a shell archive
  (`# To unbundle, sh this file`) that carries the whole texture set plus its reader,
  `INSPECT.c`, whose `OpLoad()` (65-77) defines the file format: skip to the first `{`, then

- Each icon directory carries two manifests: `ICON.LST` (the icons) and `SOURCE` (icons +
  `ICON.LST` + `SOURCE`, i.e. the `cpio` shipping list).

## contradictions and traps

1. **Three fonts directories, three answers.** `bin/xcip:1` uses `/usr/630/font`;
   `bin/cip:1` and `bin/OLDxcip:2` use `/usr/jerq/font`; `bin/t:42-47` tries
   `/usr/630/termfonts/$fontname` and falls back to `(cd /usr/jerq/font; …)`. Only
   `v10/usr/630/font/` and `v10/usr/630/termfonts/` exist in the tree — **there is no
   `/usr/jerq/font` here**, so `cip` and `OLDxcip` are the stale pair and `xcip` is the
   corrected copy. All three run the same image, `/usr/630/lib/xcip.m` (`cip.m` for `cip`).
2. **Two paths for the same 4014 emulator.** `bin/tek4014:2` → `/usr/630/lib/tek4014.m`
   (present); `bin/term:21` → `/usr/jerq/mbin/tek4014.m` (absent). Both scripts ship together.
