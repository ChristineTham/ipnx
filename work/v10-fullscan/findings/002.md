## documented build steps

### `v10/usr/630/src` — the 630/5620 host mux + loader

Three build files disagree about what this directory builds; each is self-consistent
for its own target.

- **`mkfile`** (Plan 9 `mk`, May 1991 — the newest file in the directory) builds **only
  `630ld`**: `630ld: 630ld.o proto.o pcheck.o` → `cc $LFLAGS -o 630ld …`;
  `CFLAGS = -I/usr/jerq/include`; targets `install:V:`, `clean:V:`, `clobber:`.
  `pcheck.o` gets an explicit `cc $CFLAGS -c $prereq` rule.
- **`makefile`** (`make`) builds the **host mux** from `mux.c` plus a *`proto/`
  subdirectory*: `PDIR = proto`, `INCL = $(PDIR)`, `CFLAGS = -g -I$(INCL) -I$(JINCL)`.
  Four flavours, distinguished only by `-D`:
  `mux` (plain), `smux` (`-DPSTATISTICS -DPSTATSDESC`), `ssmux` (`-DEBUG`),
  `tmux` (`-DTRACING -DEBUG`). The `smux.o`/`tmux.o` rules `mv` `mux.o` aside,
  recompile, and `mv` the result to the flavoured name — so the flavours cannot be
  built in parallel. `lint` target: `lint -I$(INCL) -I$(JINCL) $(SFLAGS) -DTRACING mux.c $(PDIR)/*.c`.
  `print`: `pr *.h *.c`. `pp`: `pp -tmux *.h *.c proto/*.? | dcan`.
  `clean` ends with `cd term; make clean`.
- **`makefile~`** is the previous revision: same as `makefile` but `CFLAGS = -O` (not
  `-g`), and it adds a **second protocol tree** `OPDIR = oproto` and a `630mux` target
  built as `$(CC) $(OCFLAGS) -c mux.c -DT630` then `mv mux.o 630mux.o`.
- **Generated files, provable from the files themselves:**
  - `rom.h` is `sed -f :sed firm.s`. `:sed` rewrites `\t.word\tabs\t\t# Firm[0]` into
    `#define F_abs\t0`; `firm.s:12` is exactly the former and `rom.h:5` exactly the
    latter, for all 158 entries.
  - `pcbs.s` is `sed -f :sed.comm-bss xpcbs.s`. `:sed.comm-bss` turns
    `\t.comm\tistack,256` into `\t.align\t4 / \t.globl\tistack / \t.bss\tistack,256,1`;
    `xpcbs.s:4` is the former and `pcbs.s:4-6` the latter, throughout. Both carry
    `.file "pcbs.c"`, so the chain is `mcc pcbs.c` → `xpcbs.s` → sed → `pcbs.s`.
  - `Pl.s` is generated by `makelocore`: `makelocore Pl.s jpx.h Pl.template mas`
    (usage line 7 spells the arguments). It runs `qed - -x makelocore.q -e $MPXH`
    to renumber the entry table, then `sed "1,/Ken/d …" < $MPXH > /tmp/x$$` and
    `sed "/defont/r /tmp/x$$" < $TEMPLATE > $PLS`. It then writes `notsolow.s`
    inline as a here-document, taking the `jinit` and `exit` entry numbers out of
    `$MPXH` with `grep … | sed 's/[^0-9]//g'`. Extra tools required: **`qed`**,
    `sed`, `grep`. `Pl.template` is not in this chunk.
- **Link map:** `map` is an `ld` `SECTIONS` script pinning `pcbs.o`'s `.data` and
  `.bss` and `proctab.o`'s `.data` at `GROUP 0x71c050:`. `nm.out:419` shows
  `0071c050 O proc_pcb`, confirming the map is the one used.
- **Ordering:** `README:16-20` — "the following depend on jerqproc.h: … files in
  /usr/jerq/src/sys; just "make" there / before make'ing here". So `/usr/jerq/src/sys`
  builds first.
- **Hand-derived constants:** `pl.s:1`/`opl.s:1` `.set CONTROL_STATE, 4516` and
  `pl.s:144` `orw2 &1,proctab+80` are offsets into `struct Proc`; `procsize.c` is the
  three-line program that computes
  `(char *)&proctab[1].state-(char *)&proctab[0]` for that purpose.
- **What actually gets compiled**, from the two `nm` transcripts: besides this
  directory's sources, the link pulls in `acia.c buttons.c cursor.c defont.c display.c
  alloc.c arith.c balloc.c bitblt.c clip.c dellayer.c downback.c gcalloc.c layerop.c
  lbitblt.c lblt.c lbox.c line.c linesub.c lpoint.c lrectf.c lsegment.c ltexture.c
  masks.c menuhit.c newlayer.c ptinrect.c queue.c rectXrect.c rectclip.c rectf.c
  screenswap.c setup.c setvis.c strcat.c strcmp.c strcpy.c strlen.c strwidth.c
  texture.c upfront.c Jrect.c abs.c index.c bram.c` — none of which are here; they
  are the jerq library, consistent with `README`'s `/usr/jerq/src/{sys,lib,mlib}`.
- `v10/usr/630/terminfo/630` is a terminfo **source** description
  (`630|att630|ATT630|630DMD|630MTG|AT&T 630 windowing terminal,` plus a
  `630-24 … use=630` alias). It states no path and names no compiler.
  `terminfo/SOURCE` and `termfonts/SOURCE` are plain manifests of their own
  directories' contents.

## contradictions and traps

**`/usr/jerq` vs `/usr/blit` — the Blit tree was rehomed only halfway.**
`Road.map:118` insists "try to install this tape at /usr/jerq", and `/usr/jerq` in this
distribution is a **different tree** (the 5620/DMD code — `Road.map:2`: "/usr/jerq has
the DMD-5620 code"). Every wrapper in `v10/usr/blit/bin/*` was rewritten to
`/usr/blit/...`, and `.profile:3` sets `JPATH=:/usr/blit/demo/mpx`. But four build
and source files were **not** rewritten and still name `/usr/jerq`:
`demo/src/makefile:1-3,9` (`/usr/jerq/bin/mcc`, `/usr/jerq/bin/mas`,
`/usr/jerq/lib/l.o`), `demo/src/asteroids/makefile:3,10,17`,
`demo/src/mazewar.c:6,38,46`, `demo/src/road.c:21`. Building the demos as shipped
therefore reaches for the *5620* toolchain and installs into the *5620* tree.

**`/usr/jerq/bin` and `/usr/jerq/lib` do not exist in this distribution.** Verified:
`v10/usr/jerq/` contains only `demo/ font/ icon/ include/ mbin/ sgs/ src/`. So every
reference above to `/usr/jerq/bin/{mcc,mas,mld,68ld,32ld,32reloc}` and
`/usr/jerq/lib/{l.o,term,muxterm,notsolow.o,jim.j}` is unsatisfiable as shipped —
`630ld.c:144`, `mux.c:143`, `mux.c:808`, `makelocore:34`, `mazewar.c:38,46`,
`demo/src/makefile:1-3,9`, `asteroids/makefile:3-4`. `/usr/jerq/include` *does* exist
(35 entries), so the `-I` paths are fine.

**`/usr/blit/mbin` is empty.** Verified by `ls`. All nineteen wrappers in
`v10/usr/blit/bin/` load a `/usr/blit/mbin/*.m` or `*.j` that is not present:
`cip.j crabs.m face48.m hp.m icon.m invert.m jf.m joff.m lens.m lsh.m m33.m pen.m
tek4014.m twid.m vitty.m`. Likewise `/usr/blit/lib/` holds only `jimunpack` and `ped`
— not the `joff`, `lsh` or `muxterm` that `bin/joff`, `bin/lsh`, `bin/muxjoff` invoke —
and `/usr/blit/bin/` has no `68ld`, `ismpx`, `jx` or `jcif` even though
`bin/{hp,tek4014,vitty}`, `bin/demo`, `bin/{cip,face,icon,jf,lsh,twid}` and
`demo/mpx/demo:14` all call them by absolute path.

**`asteroids/makefile`'s install path is stale by the mpx→mux rename.**
It writes `/usr/jerq/demo/mpx/asteroids`, but `v10/usr/jerq/demo/` contains
`mux/ src/ stand-alone/` — there is no `mpx`. `Road.map:11-13` states the rename
itself: "the main element is that the main terminal multiplexer is mux(9), not
mpx(9), although both work."

**`/usr/blit/demo/mpx` contains no demos.** `demo/mpx/demo:6` lists that directory to
show the user what is available, and dispatches on `bounce|*ball|a|b`, `jcif`, `clock`,
`road|kbd`, `swar`; the directory holds only `demo`, `jcif` (a CIF data file) and `pi`.
`demo/mpx/pi:1` `cd /usr/tac/pi/demo/host` points at a private home directory that is
not in the distribution at all.

**`v10/usr/630/src`'s `makefile` cannot run: the `proto/` subdirectory was flattened
away.** `makefile:2` is `PDIR = proto` and every rule reads `$(PDIR)/pcheck.c`,
`$(PDIR)/pinit.c`, `$(PDIR)/precv.c`, `$(PDIR)/psend.c`, `$(PDIR)/ptimeout.c`,
`$(PDIR)/{pconfig,packets,proto,pstats}.h`. Those ten files sit **flat** in
`v10/usr/630/src/` and there is no `proto/` (nor the `oproto/` of `makefile~`, nor the
`term/` that both `clean` targets `cd` into).

**Worse, the flattening created a `proto.h` collision.** The flat `proto.h` is the
*68ld/32ld bootstrap* header (`MAXPKTSIZE 128`, `PKTASIZE 4`, `WAIT`/`OK`, `NPBUFS`) —
matched to `proto.c` and `630ld.c`, which `mkfile` builds. But `precv.c`, `psend.c`,
`pinit.c`, `ptimeout.c` and `packets.h` need an entirely different `proto.h`:
they use `P_PTYPE`, `P_CNTL`, `P_seq()`, `P_channel()`, `SBITS`, `MAXPCHAN`, `EDSIZE`,
`Pbyte`, `Pkt_p`, `ACK`, `NAK`, `PCDATA`, and a `struct Packet` with `.header`,
`.dsize`, `.data` members — none of which the flat `proto.h` defines, and its
`struct Packet` (in `proto.c:5-10`) is a flat `char packet[MAXPKTSIZE]`. The mux
protocol's `proto.h` is simply missing.

**`o_proto.h` and `proto.h` disagree on `SEQMASK`, and `o_proto.h` records the bug.**
`proto.h:27` is `#define	SEQMASK		(~PTYP)`; `o_proto.h:29-30` is
`/*#define	SEQMASK		((~PTYP)&0xff) doesn't work */` then
`#define	SEQMASK		((~PTYP)&0x3f)	/* seq. no must be <0100  (why?? dunno) */`.
`o_proto.c`/`o_proto.h` are the "68ld" pair and `proto.c`/`proto.h` the current one;
they also differ in `precv()` ack handling (`SKACK` in `proto.c:85-88` accepts skipped
sequences; `o_proto.c:94-98` retransmits with `NOACK`) and in whether `psend`
decrements `freepkts`.

**`window.c` and four others still carry the pre-flattening include paths.**
`window.c:7` `#include "frame/frame.h"` — `frame.h` is flat, there is no `frame/`.
`window.c:8`, `2control.c:7`, `boot.c:4` and `demux.c:6` all say `#include "../msgs.h"`
while `msgs.h` is a sibling. So the original layout had these sources one level below
`msgs.h` (and one level *above* a `frame/`); the tape's flat directory breaks both.

**Three mutually incompatible `frselect`/`select` implementations sit side by side.**
`select.c` defines `frselect`, `order`, `matchit`, `isalnum`; `nselect.c` defines the
same four with a different `matchit` (no `same[]` table, different null-selection
logic) and no `doubleclickOK`; `safeselect.c` defines `select` and a third `order`.
Compiling more than one into the same image is a duplicate-symbol link failure, and
nothing in `mkfile`, `makefile` or `makefile~` chooses between them.

**`opl.s` and `pl.s` are byte-identical** (5141 bytes each; `cmp` reports no
difference). `x1` is a **partial duplicate** of `pl.s` — exactly `pl.s` lines 11-99,
i.e. the `Sys` jump table with `.word 0` (the `P` slot) and `.word defont` chopped
off the front and no `.globl`/`_start`. Assembling `x1` would produce a `Sys` table
shifted by two entries; it must not be used in place of `pl.s`.

**`v10/usr/630/src/kbd.c` has unbalanced preprocessor conditionals and will not
compile.** `#ifdef ftang` opens at line 25 and closes at 32; a second opens at line 40
and reaches `#else` at 63 — and is never `#endif`-ed. Line 67 opens a third
(`kbdrpt`), line 69 closes *that* one, and the file ends with line 40's conditional
still open. The braces are unbalanced the same way: `auto2()`'s closing `}` exists only
on the `#else` side (line 65).

**`v10/usr/630/src/firm.s` has an e-mail routing line inside the assembler source.**
Line 175, after the last `.word`: `Copies to: ihnp4!research!presotto`. It is not a
comment (`#` is the comment character in this dialect, used throughout the rest of the
file) and would be a syntax error. Line 8 also claims `.file	"vector.s"` while the
file is `firm.s`.

**`v10/usr/blit/demo/src/alphabet/rest.c` is a damaged file.** Lines 182-223 are
interleaved fragments of the surrounding code, mid-token
(`	= 0; count < delay;count++) {`, `(x1,y1,r,384,512,SHOWPOINT,512);`,
`	spiralclp(x2,y2,r,384,512,ERASEPOINT,512);` repeated in pieces) — a tape or editor
corruption inside the `spiral`/`circ` region. It compiles anyway only because the whole
1-389 range is wrapped in `#ifdef GEEWHIZ` and lines 390-393 supply empty stubs
`burst(){} frect(){} ncyl(){} rotor(){}`. Turning `GEEWHIZ` on will not build.

**`alphabet/rom.s` defines `aciainit` twice with different addresses** —
line 11 `set	aciainit,	0x40204` and line 13 `set	aciainit,	0x4128e`, both
followed by `global	aciainit`. It also declares `global	display` at line 62 while its
`set` is commented out at line 61 (`#set	display,	0x40012`), leaving `display`
undefined at link time.

**`alphabet/makefile` cannot build its own target.** `alph:` requires `rom.o`, the only
rule is `.c.o: mcc -c $<`, and `rom.s` is assembler — no rule produces `rom.o`.
`spheres.c` in the same directory also provides `sphere()`, so its symbol collides with
`demo/src/spheres.c`'s (different directories, so harmless in practice, but the two
files are not the same program).

**`v10/usr/blit/demo/src/makefile`'s first target is `clean`.** Lines 5-6 are
`clean:` / `	rm -f *.o`, ahead of every real target, so a bare `make` in that
directory deletes objects instead of building anything. The makefile also has **no
install rule at all** (the only install rule in this chunk's Blit half is
`asteroids/makefile:14`), and three of its targets name sources that are not present:
`w.o`/`newlayer.o` (line 29-30, no `w.c` or `newlayer.c`) and `asteroids.o` (line 20-21
— `asteroids` is a *directory* with its own eight-object makefile, so the parent's
one-object rule for it is wrong).

**`v10/usr/630/src/makelocore` never runs the assembler.** Line 34 is
`echo echo $AS -o /usr/jerq/lib/notsolow.o  notsolow.s` — a doubled `echo`, so the
command is printed twice-removed rather than executed. `notsolow.s` is written but
never assembled or installed.

**`alphabet/graphics.h` and `graphmacs.h` are SUN framebuffer headers, not Blit
headers,** and they collide with `alph.h`. `graphics.h:45` defines `GXfunction` as
`*(short *)(GXUnit0Base+GXothers+(0<<1))` — a Multibus address at `0x100000` — while
`alph.h:22` declares `int	GXfunction;`. Nothing in the twenty `.c` files includes
either header (they all `#include "alph.h"`); `graphmacs.h:9` even flags itself
(`#include "graphics.h"	/* should be framebuf.h! */`). `alph.h:8-9` marks its own
translation of the SUN ops as wrong: `#define	NOT	F_XOR	/* Wrong */` and
`#define	AND	F_XOR	/* Wrong */`.

**`clock.c` is the only demo that includes `<blit.h>`** (line 1) where the other
twenty-seven use `<jerq.h>`. `Road.map:105-109` explains it: "Officially, the terminals
are Blits. To us, they will always be Jerqs. … so for consistency "jerq.h" is linked to
"blit.h"". Both names are present in `v10/usr/blit/include/`, so the link survived —
but it is a link, and a copy-based install would have to preserve it.

**`v10/usr/630/src/nm.out` and `2nm.out` are transcripts of two different links** and
must not be treated as one. They differ in the file-symbol at offset `00000546`
(`nm.out:158` `f control.c`, `2nm.out:287` `f jerq.h`) and in the whole `B`-segment
layout (`ENDAREA` is `0072cbe8` in `2nm.out:10`, `0072d8d8` in `nm.out:10`). Only
`2control.c` is present in the directory; the `control.c` that `nm.out` was taken from
is not.

**`630mon.c` hardcodes a machine roster.** Lines 89-173 list `alice arend bowell coma
crab dutoit encke kwee panther pipe r70 research seki spit swift west westphal wild`
under `nj/astro`, plus `nj/phone`, `nj/mercury`, `ca/xunet/fs`, `nj/garage/europa`,
`nj/vlsi/araki`, `pa/ram/most`. These are menu labels sent to the host as
`M<path>\n` (line 307-318), not paths on this filesystem.

**`v10/usr/blit/lint` is a replacement for the system `lint` driver** and
`Road.map:189` says to copy it to `/usr/bin` — overwriting the stock one. Its only Blit
content is one line: `	-*j*)	P= ;;	# ROB PIKE ADDED THIS` (line 7), which suppresses
the `llib-lc.ln` append. Everything else is the standard 7th-edition driver.

**`v10/usr/630/src/mkfile` installs `630ld` and nothing else.** `muxterm` and
`2muxterm` (218450 bytes each) sit in the same directory, and `mux.c:143` expects a
`muxterm` at `/usr/jerq/lib/muxterm`; no build file in this chunk copies them there.
(Those two files are not in this chunk's list.)
