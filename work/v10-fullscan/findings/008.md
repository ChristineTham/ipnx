# chunk 008

234 files, all under `v10/usr/blit/src/` — the Blit/Jerq (DMD 5620) userland: font
generation (`font/gen`, `font/map`), a CIF plotter (`jcif`), a font editor (`jf`), the
`jim` editor (host + terminal + text-frame library) and the `joff` debugger's shared
top level. None binary; 133 of them are hex character data.

The single most important structural fact: **this tree is split between two install
prefixes, `/usr/jerq/*` (older) and `/usr/blit/*` (newer), and the split runs through
individual programs.** `jim` installs to `/usr/blit/bin` + `/usr/blit/mbin`; `joff`
installs to `/usr/jerq/lib` + `/usr/jerq/mbin`; `jf` and `font/gen` read fonts from
`/usr/jerq/font` while `font/map` writes the same map files to `/usr/blit/font`.

## contradictions and traps

1. **`font/gen/imap.c`+`smap.c`+`map.c` and `font/map/imap.c`+`smap.c`+`map.c` are two
   incompatible versions of the same three programs, with different destinations *and*
   different on-disk formats.** `gen` writes `/usr/jerq/font/{IMAP,SMAP}` with **3-byte**
   entries carrying an explicit code byte (`gen/imap.c:5`
   `char tab[] = "X\\-\055dg\001em\002en\003fi\004fl\005hy\006sc\007";`,
   `gen/imap.c:13` `tab[0] = strlen(tab)/3;`, `gen/map.c:25` `u = &array[3*last];`,
   `gen/map.c:45` `return(l[2]);`). `map` writes `/usr/blit/font/{IMAP,SMAP}` with
   **2-byte** entries and a *computed* code (`map/imap.c:5`
   `char tab[] = "Xdgemenfiflhysc";`, `map/imap.c:13` `tab[0] = strlen(tab+1)/2;`,
   `map/map.c:25` `u = &array[2*last];`, `map/map.c:45`
   `return(1 + (l-array)/2);`). Building both and installing both leaves two
   mutually unreadable map files under two prefixes. The two `SMAP` character tables also
   differ in content: `gen/smap.c:9-10` has `L1`, `Sl`, `\\-`, `\\_` where
   `map/smap.c:6` has `b0`, `Sl`, `\\-`, `\\_` and no `L1`.
2. **`/usr/jerq/Font` vs `/usr/jerq/font`.** `doset:7` installs to capital-F
   `/usr/jerq/Font/`; `mvit:5`, `readme:22`, `newfonts:4`, `jf/jf.9:34` and
   `jf/filesubs.c:61` all use lowercase `/usr/jerq/font`. On a case-sensitive V10
   filesystem these are different directories and `doset` puts fonts where nothing looks
   for them. (Note the repo's own `u_`-prefix collision rule does **not** apply here —
   these are two path *strings* in scripts, not two files.)
3. **`jim/file/makefile` and `jim/file/makefile.5` install the same program to different

4. **`joff/menus.c` cannot compile where it sits.** `joff/menus.c:1-2` is

5. **`joff`'s default make target does nothing on purpose.** `makefile:1-2` is
   `wrong:` / `	pwd` — running `make` in `joff/` prints the working directory and
   builds nothing. A driver that treats "make exited 0" as "package built" will record a
   phantom success for joff. Its only real rules are `install`, which requires

6. **`font/gen/makefile` cannot build its main target.** `makefile:2-3` list

7. **`special` expects an `ar` archive named `newspec.a`; the tree has a `newspec/`
   directory.** `special:1` is `ar x newspec.a C125 C022 …` and `newspec/ORDER` is this
   repository's record of the archive's member order — i.e. `newspec.a` was unpacked into
   a directory by `v10-tree.py`. Any harness running `special` or `doset` as written needs
   the archive re-created (in `ORDER` order) or the script rewritten. Same for `doset:2`
   `ar x `cat where`/$1.a`.
8. **`newspec` has no `C084`, and `C106` and `C134` are byte-identical.** `ORDER` runs
   `… C082 C083 C085 C086 …` — `C084` is genuinely absent from the archive — yet

9. **`where` points into a private directory that will not exist.**

    `r.h:2` `#include "msgs.h"` and `jim/file/jim.c:8` via `#include "msgs.h"`. Any

    protocol. This is one of the two entries in `v10tapes/HARDLINKS`.
12. **`jim/makefile`'s `xnr.m` target depends on someone's home directory.**

14. **`jim`'s host binary must be *named* to pick its terminal program.**
    `jim/file/jim.c:47` switches on `argv[0][0]=='x'`. Built as `xjim` it downloads the
