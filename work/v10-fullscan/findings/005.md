## documented build steps

**`Mcc/` — pcc pass 1 (`comp`, installed as `ccom`)**
Default target `comp` links 15 objects and renames: `makefile:12-14`
`comp: $(OFILES)` / `	cc $(CFLAGS) $(OFILES)` / `	mv a.out comp`. `CFLAGS=-O`,
`I=-I. -I$M`, `M=../mip`, `SDB=$M/sdb.h`. Only `local.c`, `local2.c`, `macdefs`, `stin` and
`g` are local (`makefile:11` `SFILES=	g stin local.c local2.c macdefs`); the other thirteen
objects are compiled straight out of `../mip`. Required ordering, and the only interesting
part of the build: `sty` (a table generator, `yacc $M/sty.y` then `cc $I $(CFLAGS) -o sty
y.tab.c`) must be built first, because `makefile:40-41` is `table.c: sty stin` /
`	sty <stin >table.c`, and `table.o` then compiles **without `-O`** (`makefile:38-39`,
`	cc -c $I table.c` — every other rule passes `$(CFLAGS)`). `$M/cgram.c` is generated into
the *sibling* directory: `makefile:33-35` `yacc $M/cgram.y` / `	mv y.tab.c $M/cgram.c`.
Tools beyond cc/as/ld: **yacc** (twice), **lint** (`lintall`). `clean` removes `comp`,
`*.o`, `mout`, `sty`, `table.c`.

**`Mcc/SHELL` — the compile driver (the "cc" of this toolchain)**
Three stages, no `.o`-preserving intermediate: `/lib/cpp -Dmc68000 -Updp11 -I/usr/m/include`
→ `$CCOMP` → `$NAS $T.s -o $B.o`, then `$LD $LC $ll $LIBS`. Flags it defines:
`-S` stops after assembly source and adds `-l` to ccom (`SHELL:26` `N=no S=-S OTWO=-l`);
`-O` is **link-time only** (`SHELL:62` `$LD -O $LC $ll $LIBS`); `-g` passes `-g` to ccom;
`-c` suppresses the link; `-alone` swaps the startup and library set; `-X` swaps in
`/usr/scj/mcc/comp`; `-[IDU]*` are forwarded to cpp only. The linker is invoked with
`-b 4096` before `libc.a`.

**`cpp/`**
`makefile:3-4` `cpp :	cpp.o cpy.o rodata.o` / `	$(CC) $(CFLAGS) -o cpp rodata.o cpp.o cpy.o`.
Mandatory flags: `makefile:1` `CFLAGS=-O -Dunix=1 -Dvax=1 -DFLEXNAMES` (`-DFLEXNAMES` sets
`NCPS 128` instead of `8`, `cpp.c:1-5`). `rodata.o` needs an extra flag of its own:
`makefile:11-12` `rodata.o : cpy.c` / `	$(CC) $(CFLAGS) -R -c rodata.c`. Tools beyond
cc/as/ld: **yacc** and a table-splitter, `makefile:6-9`
`cpy.c : cpy.y` / `	yacc cpy.y` / `	../pcc/:yyfix yyexca yyact yypact yypgo yyr1 yyr2
yychk yydef` / `	mv y.tab.c cpy.c`. `cpy.o` also depends on `yylex.c`, which is `#include`d
by the grammar (`cpy.y:80` `# include "yylex.c"`), not compiled separately.

**`mas/` — the 68000 assembler**
`makefile:2-3` `mas: mas0.o mas1.o mas2.o mas3.o mas4.o` /
`	$(CC) $(CFLAGS) -i -o mas mas0.o mas1.o mas2.o mas3.o mas4.o` — note **`-i`** (separate
I/D). `CFLAGS=-O -I/usr/blit/include`. `mas0.o` has **no rule and no `mas0.c`**: it comes
from `mas0.y` through make's built-in `.y.o` rule, i.e. yacc is required. The generated
header is copied to a stable name only when it changes: `makefile:4-6` `y.tab.h:	mas.yh` /
`mas.yh:	y.tab.h` / `	- cmp -s y.tab.h mas.yh || cp y.tab.h mas.yh`. `mas4.c:24` is
`#include "ops.c"` — the opcode table is a text include, and `makefile:10` records it
(`mas4.o: mas.h mas.yh mas4.c ops.c`). There is **no install target**. `print` needs `pr`.
The assembler's own language is documented in `manual` (pseudo-ops `space byte short long
data text global set comm lcomm even org pcrel pcrel.w pcrel.l stabs stabn stabd`), with
`addr`, `optim` and `stab` as design notes for the table encodings, the peephole
opportunities the relocation codes leave open, and the sdb stab entries.

**`mc2/` — object-code improver `c2`**
`makefile:6-8` `c2: $(OBJS)` / `	$(CC) -o c2 c20.o c21.o` / `	@echo DONE`, with
`makefile:1` `CFLAGS=` — **deliberately no optimisation**. `makefile:10`
`c20.o c21.o: c2.h`. Source retrieval and cleaning go through SCCS: `makefile:14-15`
`$(SRCS):` / `	sccs get $@` and `makefile:20-22` `clean:` / `	-rm $(OBJS) c2` /
`	sccs clean`. Tools beyond cc/as/ld: **sccs**, **lint**, **pr**/**lpr**
(`makefile:27-29` `print:	$(SRCS)` / `	pr $? | lpr -c` / `	touch print`).
`makefile.5` adds an explicit suffix rule (`.c.o:` / `	$(CC) $(CFLAGS) -c $<`) and a third
object, `index.o`.

## contradictions and traps

1. **Two different homes for the same compiler.** `Mcc/makefile:1` installs `comp` as
   `/usr/jerq/lib/ccom`, but the driver that runs it looks somewhere else:
   `Mcc/SHELL:1-2` `L=/usr/m/lib` … `CCOMP=$L/ccom`. Installing per the makefile leaves
   `SHELL` broken, and vice versa. The rest of `SHELL`'s world is `/usr/m/*`
   (`/usr/m/lib/libc.a`, `/usr/m/include`, `/usr/m/bin`) while `mc2` installs into
   `/usr/jerq/lib` too — so the package set spans two prefixes with no variable tying them.
2. **The driver never runs the optimiser it is packaged with.** `SHELL`'s pipeline is
   cpp → ccom → mas → mld; nothing invokes `c2`/`mc2`, and `SHELL:32` `-O)	OPT=yes` only
   reaches the linker (`SHELL:62` `$LD -O …`). `mc2/makefile:18` nevertheless installs
   `/usr/jerq/lib/mc2`.
3. **`Mcc/bar` is a newer `local.c` that nothing builds and that cannot compile here.**
   `bar` is dated Nov 21 1984 (vs `local.c` Nov 19 1982) and announces itself as
   `bar:1` `static char	SCCSID[] = "@(#) local.c:	2.1 84/10/24";`. No makefile target
   mentions it; `makefile:25-26` compiles `local.c`. Its includes are `bar:3-4`
   `# include "mfile1.h"` and `#include "storclass.h"`, but `../mip` contains `mfile1`,
   `mfile2`, `manifest`, `common` and `sdb.h` — **no `.h` spellings and no `storclass.h`** —
   and `makefile:19-25` names the dependencies as `$M/mfile1`, `$M/mfile2`. `local.c:1` is
   `# include "mfile1"`, matching the tree.
4. **`macdefs` is ahead of the `local.c` the makefile compiles.** `macdefs:53`
   `# define SDB` and `macdefs:66` `# define OUTREGNO(p) …` turn on the debugger hooks;
   only `bar` calls them (`bar:236` `prdef(q, 0)`, `bar:294` `efdebug()`, `bar:321`
   `bfdebug( a, n )`, and `bar:234` guards with `# ifndef NOSYMB`). `local.c` has no
   `prdef`, `bfdebug` or `efdebug` at all. `macdefs:22-26` (`STATSRET`, `RNODNAME`,
   `SRETNAME`) and `macdefs:55` `LONGFIELDS` likewise pair with `bar`'s `commdec`/`incode`,
   which use `ALSHORT`/`SZSHORT` where `local.c:102` uses `SZINT`. Deciding this package by
   its makefile alone silently selects the 1982 code path under 1984 macros.
5. **`mas/opck.c` mis-columns the current opcode table.** `opck.c:71-80` declares
   `struct optab` with **eight** members and `opck.c:84` terminates with
   `0,	0,	0,	0,	0,	0,	0,	0`, but every row of `ops.c` carries **nine** values —
   e.g. `ops.c:9` `0150700,"add",	L,	SIG,	AGEN,	DEA,	AREG+A,	DRGL,	ISL,` (the trailing
   `iflag`) — and `mas.h:120-130` `struct instab` has the ninth member `short	iflag`.
   `opck.c:83` is `#include "ops.c"`. `opck.c` also defines `SMD	2` (`opck.c:69`) and an
   `AGEN` modifier set of only `AM` (`opck.c:28`), where `mas.h:105-109` has just `SIG`/`SD`
   and `mas.h:66-69` has `AM|CT|AL|DA`. It is a stale checker, it is in no makefile, and it
   has its own `main()`.
6. **`ops.c` is a text include with a `.c` name.** `mas4.c:24` and `opck.c:83` both
   `#include "ops.c"`; it is a bare initialiser list with no declarations. Any build that
   globs `*.c` (or a naive `cc -c ops.c`) fails, and `mas/` contains two such files —
   `ops.c` and `opck.c` — that must not be compiled as part of `mas`.
7. **`make clean` in `cpp/` is unrecoverable in this tree.** `cpp/makefile:14-15`
   `clean :` / `	rm -f *.s *.o cpy.c rodata.c` deletes two *committed* sources, and the only
   rule that regenerates them needs `makefile:8` `../pcc/:yyfix …`. There is no `pcc`
   directory under `v10/usr/blit/m/src` (it holds `Mcc cpp mas mc2 mip mld` plus loose
   `mar.c mcc.c mnm.c msize.c mstrip.c bootrom.s README makefile makefile.5`).
8. **The committed `cpy.c`/`rodata.c` are not what that rule would produce.** `:yyfix` is
   invoked for eight tables, but `rodata.c` holds only `yydef` (`rodata.c:1`
   `short  yydef []={`); `yyexca`, `yyact`, `yypact`, `yypgo`, `yyr1`, `yyr2` and `yychk` are
   still *defined* inside `cpy.c` (lines 33, 71, 111, 121, 125, 131, 137), each preceded by
   an `extern` declaration for the *next* table (`cpy.c:29-33`, `70-71`, `110-111` …).
   Reproducing the pair by re-running the rule is not a safe assumption.
9. **This cpp is compiled as a VAX program and predefines `vax` for its input.**
   `cpp/makefile:1` `-Dvax=1`, and `cpp.c:1111-1113` `# if vax` / `	varloc=stsym("vax");`.
   `SHELL:11` must therefore say `-Dmc68000 -Updp11` — and there is no way to unset `vax`
   short of `-Uvax`, which `SHELL` does not pass. `cpp.c:1073` then appends `/usr/include`
   *after* every `-I`, so the VAX host headers stay on the 68000 search path behind
   `/usr/m/include`.
10. **`float.spec` names a routine the code generator does not call.** `float.spec:26`
    `	flsum%%		subtraction`, but `stin:318-319` emits
    `"\tmov.l\tAR,Z2\n\tmov.l\tAL,Z2\n\tjsr\tflsub%%\nZq"`. `float.spec` also documents none
    of the long-arithmetic entry points `stin:304-313` actually calls (`ldiv%%`, `lrem%%`,
    `lmul%%`, `uldiv%%`, `ulrem%%`), saying only `float.spec:9-10` "There are some routines
    for long arithmetic that should be consulted; … dmr or rob can probably direct you to
    the source."
11. **`Mcc/makefile.5`'s yacc rule is corrupt.** The System V variant was produced by
    replacing `cc` with `$(CC)` throughout, and the substitution also hit `yacc`:
    `makefile.5:34-36` `$M/cgram.c: $M/cgram.y` / `	ya$(CC) $M/cgram.y` / `	mv y.tab.c
    $M/cgram.c`. With `makefile.5:4` `CC=Ncc` that command is `yaNcc`. The equivalent rule in
    `makefile:33-35` is correct. `makefile.5` is otherwise identical to `makefile` including
    the same `INSTALL=/usr/jerq/lib/ccom`.
12. **`mc2/makefile.5` needs a source that is not in the package.** `makefile.5:5`
    `OBJS=	c20.o c21.o index.o`, and there is no `index.c` in `mc2/`. The reason is visible
    in `c20.c:697` `char *cp, *index();` / `c20.c:699` `if( p->code && (cp = index(p->code,
    '%')) …` — `index()` is the BSD/V7 name, absent on System V — while the same file uses
    the System V name elsewhere (`c20.c:460` `extern char *strrchr();`, `c20.c:463`
    `cp = strrchr(cp, 'L');`). `makefile` (the V7 variant) lists only `c20.o c21.o`.
13. **`mc2` expects SCCS that is not here, and `install` is destructive.**
    `makefile:14-15` `$(SRCS):` / `	sccs get $@` means a `make clean` (which also runs
    `sccs clean`) followed by `make` tries `sccs get c2.h`; there are no `s.` files in the
    directory. And `makefile:18` is `mv c2 /usr/jerq/lib/mc2`, not `cp` — installing removes
    the local binary, so `make install` twice fails the second time.
14. **`mas/makefile` contains a two-line dependency cycle.** `makefile:4-5`
    `y.tab.h:	mas.yh` / `mas.yh:	y.tab.h`. No `y.tab.h` exists in the directory, so on a
    clean tree the `cmp` in `makefile:6` has nothing to compare; the leading `-` swallows the
    failure and `mas.yh` is silently left at whatever is committed.
15. **`mas/y.tab.c` is a committed build artefact that the build both regenerates and
    deletes.** It is dated Nov 20 1984 against `mas0.y` Nov 17 1984, carries
    `y.tab.c:53` `# line 37 "mas0.y"` and `y.tab.c:93` `# line 511 "mas0.y"`, and is named by
    nothing in the makefile; make's built-in `.y.o` rule will overwrite and then remove it.
    `mas.yh` is older still (Dec 30 1982) — two years older than `mas0.y` — though its token
    numbers `257`…`307` (`mas.yh:1-51`) match `y.tab.c:1-51` exactly, so it is not actually
    stale. Do not infer freshness from the mtimes here.
16. **The assembler manual overstates one instruction.** `manual:350-351`
    `swap halves` / `	swap.w		%AR`, but `ops.c:222` accepts a data register only:
    `0044100,"swap",	W,	SIG,	AREG+D,	DRG,	0,	0,	0,`. (By contrast `manual:288`
    `	pea.L		A` in upper case is harmless — `mas1.c:219-220` folds the size letter with
    `if (isupper(n)) n = tolower(n)`.)
17. **`mc2/x.s` and `mc2/xx` are unreferenced hand-edits of `mc2bug.s`.** All three are the
    same `whichbut()` function. `mc2bug.s:5-7` splits the source name across three stabs
    (`"/usr/dmr"`, `"/mc2bug."`, `"c"`) while `x.s:5` and `xx:5` carry a single
    `stabs	"mc2bug.c",0x15,0,L%13`; `x.s` is largely unindented and uses `br.b	L%14`
    (`x.s:29`) where the others use `br	L%14`; `xx:31` inserts an extra
    `	mov.w	%a0,%a0`. No makefile mentions any of them — they are optimiser test inputs,
    not build inputs, and the three disagree.
18. **Developer home directories baked into two files.** `Mcc/g:1` `M=/usr/scj/mip` (the
    grep helper searches an absolute path) against `Mcc/makefile:2` `M=../mip`; and
    `SHELL:28` `-X)	CCOMP=/usr/scj/mcc/comp`. The tape's own copy of that tree is at
    `v10/usr/blit/m/scj`, not `/usr/scj`.
19. **`cpp.c` is already a locally enlarged copy, not stock.** `cpp.c:107`
    `# define SBSIZE 48000		/* std = 12000, wnj aug 1979 */` and `cpp.c:173`
    `# define symsiz 1000		/* std = 500, wnj aug 1979 */`; `cpp.c:190`
    `/* BB */ STATIC struct symtab *claloc;` with `cpp.c:754-756` adding a `#class`
    control that sets `exfail = CLASS` (27). Diffing it against another V10 cpp will show
    these and they are intentional.

## files with no build contribution

**30 of the 39 files carry no install statement.** Only nine do: the six makefiles,
`Mcc/SHELL`, `Mcc/g` and `cpp/cpp.c`.

Of those 30, **8 are wholly inert** — no install destination, no build instruction, no
contradiction — being pure implementation or design prose: `Mcc/local2.c` (pass-2 machine
dependencies), `cpp/yylex.c` (the `#if` lexer), `mas/mas3.c` (instruction selection and
address emission), `mas/addr`, `mas/optim`, `mas/stab` (notes on the address-type,
peephole and stab encodings), `mc2/c2.h`, `mc2/c21.c`. The remaining 22 carry no install
destination but each supplies a documented build fact or one of the contradictions above.
