## documented build steps

### `doc/` — the manual set
`doc/makefile` is the only build file. Targets: `all: notes.out owner.out manual.out
index.out mans.out`. Tools beyond cc/as/ld: **troff, pic, eqn, ptx, grep, sed**.
- `notes.out`: `pic $T notes.ms | eqn $T | troff -ms $T > notes.out` — pic **and** eqn.
- `owner.out`: depends on `dipsw.pic`; `pic $T owner.ms | troff -ms $T > owner.out`.
- `manual.out`: `troff -ms $T mac manual manpages>manual.out` — three inputs, in that
  order; `mac` defines the `.Po/.Ja/.Jb` macros the other two use, so ordering is required.
- `ptxx`: `grep "^\.Ja" manpages | sed 's/.Ja //' | sed 's/"//' | ptx -r -t -f > ptxx`
  — the permuted index is **generated from `manpages`**.
- `index.out`: `troff $T ptx.mac > index.out`; `ptx.mac:43` is `.so ptxx`. Note the target
  is declared `index.out: ptxx` but the recipe never names `ptxx` — the dependency is real
  only through the `.so`.
- `mans.out`: `troff -man $T *.[1-9]* > mans.out` — a glob, so it picks up `.1 .1g .3x .5
  .6 .9` alike; there is no `.PHONY`/no dependency, so it always reruns.
- `$T` is an unset macro used as a flag pass-through (`make T=-t`). `doc/m.1` is a
  transcript of exactly these five commands with `$T` empty. `doc/m.2` is **empty**.
- No install rule anywhere in `doc/`.

### `m/libc/` — the Blit C library
Two makefiles for the same job: `makefile` (host `ar`) and `makefile.5` (`$(AR)=/usr/jerq/bin/mar`).
Both: `cd crt; make`, then `-mv libc.a old.libc.a`, then
`ar cr libc.a \`mlorder crt/*.o | tsort\``, then `$(CC) -c csu/*.s`.
- Tools beyond cc/as/ld: **mlorder** and **tsort** (there is no `mranlib` — `doc/mcc.1:188`
  says so outright: `mlorder	order library (there is no mranlib)`), so **member order is
  the only symbol resolution** and `mlorder|tsort` is not optional.
- Ordering: `crt` must be made before the `ar`; `crt0.o` is produced by the *last* line of
  the `libc.a` rule (`$(CC) -c csu/*.s`) and installed from the top directory by
  `install`, so `make install` without `make` first has nothing to install.
- `crt/makefile` has only `all:` (23 `.o` names) and `clean:`; it sets `CC` and `AS` but
  supplies **no suffix rules**, relying on make's built-in `.c.o` and `.s.o`.

### `m/libf/` — the Blit floating-point library
`libf.a: $(OBJ)` (20 objects) → `rm -f libf.a; ar rc libf.a \`mlorder $(OBJ) | tsort\``.
`install: libf.a` → `cp libf.a /usr/jerq/lib`. `$(OBJ): fp.h`.
The suffix rule is the interesting part — **four steps per file, and one needs `qed`**:
```
.c.o:
	mcc -S $<
	qed -i -x massage.qed $*.s
	mcc -c $*.s
	rm $*.s
```
Tools beyond cc/as/ld: **qed** (and `mlorder`, `tsort`). `massage.qed` renames the
arithmetic helpers to the `%%` linkage convention (`fladd` → `fladd%%` etc.).
`m/libf/README` is a mail message from `scj` recording the caveat the library ships under:
`My compiler, as / on your tape, will not work if run on the 68000 itself or on / the 3B.`

### `m/src/` — the host-side cross tools
`makefile`: `all: mcc mnm msize mstrip`, one `$(CC) $(CFLAGS) -o X X.c` per tool,
`install: all` / `cp $^ /usr/blit/bin`. `CFLAGS = -I/usr/blit/include`.
`m/src/README` states the only conditional in the package:
`You only need cpp/* and mar.c if you are running UTS. / On a Berkeley system, the system
cpp and ar are what you want.`
So `mar.c` is a UTS-only substitute for `ar`, and a `cpp/` directory is expected — **`cpp/`
is not present in this chunk**, and `mar.c` is in no makefile's `all:`. `bootrom.s` (the
ROM image: memory clear, autovector setup, ACIA download protocol, and the stand-alone
graphics entry-point table) is likewise in no rule.

### `m/scj/`
No makefile. `main.i` is cpp output and `source.s`/`binary.s` are two compilations of the
same `jim/main.c` — plain and `-g` (binary.s carries `stabs`). Reference material, not a
build target; nothing in this chunk references them.

### Constraints that apply to the whole tree
- `include/a.out.h:18` is `char n_name[8]` — **symbols are 8 characters**. `m/scj/source.s`
  shows the truncation in practice (`usualtes`, `scrollli`, `nrequest`, `buttonhi`,
  `deadmous`), and `binary.s:17-19` splits a filename stab into 8-byte pieces.
- `include/blit.h:84-99`: `MPX` selects the mpx world (pulls in `<mpx.h>`, real `Drect`),
  `MPXTERM` the terminal program, and neither gives the stand-alone macros
  (`request`→no-op, `exit()`→`reboot()`, `sleep`→`nap`). `mcc.c:208-209` passes `-DMPX`
  whenever `mflag` — and `mflag=1` is the **default** (`mcc.c:25`).
- `mcc.c:206-207` always passes `-Uvax -Dmc68000`.
- `mcc.c:281-302` link line: `-b 256` for stand-alone; `-R -M -d` for mpx.

## contradictions and traps

1. **`/usr/blit` vs `/usr/jerq` — the tree contradicts its own manuals.**
   `m/src/makefile:1,18` install to `/usr/blit/bin` and compile `-I/usr/blit/include`;
   `m/src/mcc.c:12-16,212,298-302` hardcodes `/usr/blit/lib/*` and `/usr/blit/bin/*`;
   `m/scj/main.i` (real cpp output) names `/usr/blit/include/*` and `/usr/blit/src/jim/*`.
   Against that, `doc/manual:42` (`in the directory /usr/jerq/bin`), `doc/mcc.1:157-179`,
   `doc/mld.1:93`, `m/libc/makefile:1` (`DESTDIR=/usr/jerq`), `m/libc/crt/makefile:1-2`,
   `m/libf/makefile:10` and `m/src/makefile.5:1` all say `/usr/jerq`. Within `m/src` the
   two makefiles disagree with each other on the very same line number.
   **A naive build installs libc/libf under `/usr/jerq/lib` and the tools under
   `/usr/blit/bin`, and then `mcc` looks for its libraries in `/usr/blit/lib` and finds
   nothing.** One of the two prefixes must be a link to the other, or one set retargeted.
2. **`doc/manual:142` says `/usr/include/blit.h`** — a third location, neither
   `/usr/blit/include` nor `/usr/jerq/include`, for the header every Blit program includes.
3. **`blit.h` and `jerq.h` are near-duplicates that are *not* interchangeable.** They
   differ at exactly one line: `blit.h:71` is `#define Rpt(x, y) (short)(x), (short)(y)`
   and `jerq.h:71` is `#define Rpt(x, y) x, y` — the casts are gone. `jerq.h` is the
   *newer* file (Jan 27 1984 vs Jan 4 1984). The docs tell programs to include `<blit.h>`
   (`manual:324`), but the library's own source includes the other spelling:
   `m/libf/printf.c:5-6` is `#include <jerq.h>` / `#include <jerqio.h>`. Both must be
   installed, and they cannot be one link.
4. **`blitio.h` and `jerqio.h` *are* one file** — same inode, link count 2, byte-identical.
   `doc/jx.1:91` documents this (`linked to jerqio.h`) and the tree preserves it. An
   installer that copies rather than links breaks the documented relationship.
5. **`pads.h` is a stale master.** `pads.h` is a `>pri`/`>pub`-marked source from which
   `pads.pri` and `pads.pub` are split, but it is Apr 27 1984 while both outputs are
   Jun 1 1985 and **cannot be regenerated from it**: `pads.h` writes `u_filler[2/20/8]`
   where `pads.pub` has `pub_filler[2/24/8]` (note 20 vs **24**); `pads.h` guards on
   `TERM` where the outputs use `PADS_TERM`; `pads.h` has class `Univ` and
   `NumericCarte`, the outputs have `PadRcv` and `NumericRange`; `pads.h` lacks
   `PADS_VERSION 0x850125`, the `FAKELINE/USERCUT/DONT_CLOSE/NO_TILDE` attributes,
   `Carte::items`/`width`, and its `CARTESIZE(s)` is `(s-1)*sizeof(Index)` against the
   outputs' `(s)*sizeof(Index)`. Regenerating from `pads.h` silently changes an ABI.
   (`u_filler` here is original source, **not** the extractor's `u_` case-collision prefix.)
6. **`mcc.c` and `mcc.1` disagree about `notsolow.o`.** `doc/mcc.1:166-167` says
   `/usr/jerq/lib/notsolow.o	runtime startoff for -m`. `mcc.c:16` makes it the
   **default** (mpx) crt0, and `mcc.c:71` makes `-m` use `crt0.o` instead. The man page
   is wrong about which flag selects which startoff.
7. **`libmj.a` is undocumented.** `mcc.c:300` links `/usr/blit/lib/libmj.a` for every mpx
   compile; it appears in no man page. Conversely `doc/mcc.1:171` lists
   `/usr/jerq/lib/libf.a` but `mcc.c` never links it — `doc/mcc.1:29-32` says
   floating-point needs an explicit `-lf`.
8. **`mstrip.c` cannot be built as the makefile builds it.** `m/src/makefile:14-15`
   compiles it with `-I/usr/blit/include`, but `mstrip.c:1,5` use **absolute** includes to

   `include/a.out.h:20` has `n_dtype`, and `mstrip.c:94-95` use `S_TYID` and `S_DIM`, which
   `include/sdb.h` does not define (it has `S_NARGS` instead). `include/sdb.h` is an older
   generation of the joff header.
9. **`ldiv.s` and `oldiv.s` define the same four globals**, and `m/libc/crt/makefile:4`
   builds **both** into `all:` while `m/libc/makefile:7` archives `crt/*.o`. `ldiv.s:12-15`
   and `oldiv.s:1-4` each `global ldiv%% / lrem%% / uldiv%% / ulrem%%`. `oldiv.s` is the
   superseded one (it aliases `ldiv%%`=`uldiv%%` and `lrem%%`=`ulrem%%`, i.e. no unsigned
   path, and clobbers `%d2/%d3` differently). Which one wins depends on where
   `mlorder | tsort` puts them.
10. **`muldiv.s` uses a single `%` where everything else uses `%%`.** `muldiv.s:12,35,58`
    call `lmul%`, `ldiv%`, `lrem%`; the definitions are `lmul%%` (`lmul.s:3,5`), `ldiv%%`
    and `lrem%%` (`ldiv.s:12-13`), and `m/scj/source.s:278` and `binary.s:307` both emit
    `jsr lmul%%`. `muldiv.s:8` shows it is compiler output from a file called
    `"muldiv%.c"` — a different naming generation. Expect four undefined symbols from
    `muldiv.o`, and note V10's `ld` *writes its output anyway* and only clears the execute
    bits, so this will not look like a failure unless `ld`'s own report is read.
11. **`ctype.o` is never compiled.** `crt/ctype.c` defines the `_ctype[]` table that
    `include/ctype.h:10-22` needs for `isalpha`/`isdigit`/…, but it is **not** in
    `m/libc/crt/makefile:4`'s `all:` list (23 names, `ctype.o` absent). The archive rule
    globs `crt/*.o`, so nothing warns: `libc.a` simply ships without `_ctype`.
12. **`m/src/makefile.5` names sources that do not exist.** Line 6 builds `mcc` from
    `mcc5.c` (the tree has `mcc.c`); line 14 builds `mstrip` from `mstrip.o index.o`
    (`index.c` lives in `m/libc/crt/`, not `m/src/`). It also has **no `install:` rule**
    at all, where `makefile` does.
13. **`m/src/makefile:18` uses `$^`.** `cp $^ /usr/blit/bin` — `$^` is not among V7-era
    make's macros (`$@ $? $< $* $%`). **VERIFY** against V10's `make`; if unsupported the
    install rule copies nothing and exits 0.
14. **`-I/usr/blit/include` shadows host headers.** `m/src/makefile:1` applies it to
    tools compiled by the *host* cc, and `include/` contains `ctype.h`, `types.h` and
    `a.out.h`. `mnm.c:13` `#include <ctype.h>` then resolves to the **Blit's** ctype.h,

    `msize.c:2` `#include <a.out.h>` picking up the Blit's a.out.h is presumably intended;
    `mnm.c:11` uses `"a.out.h"` (quoted) for the same header, so the two tools disagree
    about how to reach it.
15. **`index`, `index.ptx` and `ptxx` are three generations of the same generated file,
    and two are stale.** `doc/makefile:15-16` generates only `ptxx` from `manpages`, and
    `ptx.mac:43` `.so`s only `ptxx`. `ptxx` (279 lines) matches the current `manpages` —
    it has `alarm`, `gcalloc`, `getrect`, `realtime`, `sqrt`, `transform`, `Word`,
    `Point`, `Rectangle`, `Bitmap`, `Texture`, `Font`. `index.ptx` (229 lines) and `index`

    `manpages:355` `display, Drect, Jrect: globals describing display`; `index:34`
    `own: which resources are currently available` vs `manpages:826` `own: which
    resources have data`). No makefile target produces or reads `index` or `index.ptx`.
16. **`font/MISSING` is a runtime log, not source.** `doc/proof.1:33,91` say `proof`
    *writes* `/usr/jerq/font/MISSING` when a font has not been scan-converted. The file in
    this tree is that log, with 1984 dates (`84/2/22`–`84/2/28`) and 30 entries, two of
    them duplicates (`S.24/109` at lines 5, 26 and 30). Meanwhile `doc/proof.1:89` says
    `/usr/jerq/font/*		Blit fonts` — and **`font/` contains nothing but `MISSING`**;
    the fonts themselves are not in this tree.
17. **`mpx.1` and `mux.9` are two multiplexers with two terminal programs.**
    `mpx.1:13,50` → `/usr/jerq/lib/mpxterm`, `mux.9:13,73` → `/usr/jerq/lib/muxterm`.
    They also differ on shell policy: `mpx.1:26` `a separate shell (sh only)` against
    `mux.9:21-23` `the value of the SHELL parameter, or /bin/sh by default`. `mpx` is
    documented in section 1, `mux` in section 9, so `doc/makefile:19`'s `*.[1-9]*` glob
    formats both — a reader gets both as current.
18. **`/usr/jerq/mbin` appears exactly once.** `blitblt.9:54` puts a terminal program at
    `/usr/jerq/mbin/bbterm.m` where `fed.1:71`, `jim.1:231`, `plot.1g:69` and
    `owner.ms:142` all put `.m` terminal programs in `/usr/jerq/lib`. Either a fourth
    directory exists or that line is wrong.
19. **`mcc.c` reaches into a personal directory.** `mcc.c:92` (`-X`) →
    `/usr/scj/mcc/comp`, `mcc.c:134` (bare `-B`) → `/usr/scj/mcc`. `mcc.c:159` (`-t`

    `/usr/c/`. And `mcc.c:176` points profiling at `/lib/mcrt0.o` — the **host VAX's**

20. **`mcc.c` does not implement the documented `-t` letters.** `doc/mcc.1:123` offers

21. **`mas` and `mld` have no source in this tree.** `doc/manual:41`, `doc/mcc.1:186`,

22. **`m/libf/fsqrt.c:8` is `#include <errno.h>`**, and there is no `errno.h` in

    out-of-tree header. (It also never uses `errno`.)
23. **`m/libf/massage.sed` is not equivalent to `massage.qed`, and the makefile uses the
    qed one.** `massage.qed:14` ends with `g;.;s/%%%%/%%/g`, collapsing a doubled suffix;

24. **`m/libf/makefile:7` uses host `ar`** while `m/libc/makefile.5:8` uses

25. **`bootrom.s`'s entry table is not `mpx.h`'s `Sys[]`.** `bootrom.s:40-79` lists 39

27. **`doc/p4.c` is referenced by nothing.** `manual` `.so`s `p1.c`, `p2.c` and `p3.c`;
