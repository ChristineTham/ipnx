## documented build steps

### `blit/src/proof` (host half — `proof/host/`)
- `make` default target `proof` links **`main.o io.o font.o map.o`** only (`makefile:16-17`).
- `CC=cc`, `CFLAGS=-I$(JERQINCLUDE) -DHOST`, `LCLCFLAGS=-g`; explicit `.c.o` rule (`makefile:9-14`).
- Three objects need per-file `-D` of the install paths, so they cannot be built by the generic
  rule: `main.o` needs `-DJERQJ -DJERQM -DJERQFONT -DJLD`, `font.o` needs `-DJERQFONT
  -DJERQMISSING`, `io.o` and `map.o` need `-DJERQFONT` (`makefile:19-33`).
- Targets: `proof`, `clean`, `save`, `install`, `pp`, `lint`. `pp` needs `pp` and `dcan`.

### `blit/src/proof` (terminal half — `proof/term/`)
- `all: proof.j proof.m` (`makefile:29`) — **two** binaries from one source set, built with different
  flags, and each source compiled twice.
- `proof.m` (mpx/layers): `$(MCC) … -o proof.m main.o term.o troff.o scroll.o r.o`, then
  **`mopt proof.m; mv m.out proof.m`** — mopt writes `m.out`, never the name you gave it
  (`makefile:31-33`).
- `proof.j` (standalone): each source recompiled with **`-m`** and the object renamed
  (`$(MCC) -m -c main.c; mv main.o jmain.o`, and likewise term/troff/scroll — `makefile:40-50`), then
  `$(MLD) -o proof.j -b 256 $(JERQLIB)/l.o jmain.o jterm.o jscroll.o jtroff.o $(SYSJC)`. Note
  `-b 256` (load address) and that `r.o` is **not** in the `.j` link.
- Ordering: `proof.j`'s link reads `$(JERQLIB)/l.o` and `$(JERQLIB)/lib{sys,j,c}.a` from the
  *installed* tree, so `blit/src/sys` must be built and installed **before** `proof/term`.
- Non-cc/as/ld tools required: `mcc`, `mld`, `mar`, `mopt`, `mstrip` (`term/` and `tek4014/`), `pp`,
  `dcan`, `lint`.

### `blit/src/sys` (the terminal-side system library)
- Product is the archive **`libsys.a`** (`makefile:1`), members in a fixed list
  (`jinit cursor buttons kbd acia queue resume wait`, `makefile:8-10`).
- `CC=mcc`, `AS=mas`, `AR=ar`, **`CFLAGS=-O -m`** — the `-m` (jerq/standalone) flag is mandatory here.
- Build rule is archive-member pattern rules with immediate `ar r` and `rm` of the object:
  `$(CC) -c $(CFLAGS) $%.c && $(AR) r $L $%.o && rm -f $%.o` (`makefile:16-18`). This needs an
  **augmented make** that understands `$L(%.o)` targets and `$%`; plain V7/SysV make will not run it.
- `l.s` (the interrupt-vector/crt0) is **not** in `$(OBJ)`; it is built separately and installed as
  `$(JERQLIB)/l.o`, which is how `proof/term/makefile:36` consumes it.
- `new:` target additionally needs **`mlorder`** and **`tsort`**.
- No `install:` target at all.

### `blit/src/tek4014` (the 4014 emulator)
- `README:4-5`: `Say "make", and "make install".` — the documented sequence.
- `README:5-6`: `On some systems, the make install will have to be modified, as you may not have
  mopt.  It really doesn't matter; performance and size are enhanced by mopt, but not enough to make
  a big thing about it.` — hence the alternative `binstall` target.
- `CC=mcc`, `CFLAGS=-g`; **no `.c.o` rule** — objects come from make's built-in suffix rule, which

- `README:26-28` states a *platform* prerequisite: `You must be running the December '82 (or later)
  release of mpx, since tek uses the alarm() mechanism, and assumes that the cursor dissappears
  during F_CLR mode operations.`
- `README:12-14`: the font files are reusable — `tiny.c, bigapl.c, and tinyapl.c contain the fonts as
  C declarations, and can be used by an program which is willing to say "extern Font xxxx", where
  xxxx is one of tinyfont, bigaplfont, and tinyaplfont.`
- `README:16-19`: `Only dsegment is included, and the arguments are just like segment, with an extra
  Word argument at the end.  This all works under layers/mpx.`

### `blit/src/term` (the ROM terminal, `vitty`)
- Four link targets with different addresses: `ramterm` (`-b 256`), `romterm`
  (`-b 262144 -B 153600`), `testrom` (`-b 262144 -B 153600`), and `vitty` (`$(CC) -o vitty -j
  vitty.o`). `262144` = 256K text base, `153600` = 150K bss base, matching `bootrom.s:26-32`
  (`display` base `156*1024`) and `bootrom.s:15` (`long 156*1024-4` reset SP).
- `bootram.o` is generated: `sed -f romtoram < bootrom.s > goo.s; $(AS) -o bootram.o goo.s; rm -f
  goo.s` (`makefile:15-18`). `romtoram` comments out the `#IF ROM` block and un-comments the
  `##IF RAM` block — i.e. **one assembler source, two variants, selected by sed, not by cpp**.
- `makerom.sed` is a *separate* one-line-insert script (`1i\ long 0\ long main`) that is referenced
  by **no rule in the makefile**.
- ROM images: `strip romterm; dd if=romterm of=bits0 bs=32 skip=1 count=256` and two more
  `dd`s at `skip=257` and `skip=513` (`makefile:32-36`) — 256 blocks of 32 bytes = 8 KB per
  bit file, i.e. three files for six ROMs.
- `romterm.nm: romterm` → `mnm romterm > romterm.nm` (`makefile:46-47`); the installed copy is
  `sort +2` of it (`makefile:49-50`).
- Documented ROM procedure, `README:45-56`: `To make new ROMs:  1) Copy someone else's.` … `2) rom.?
  are the bits for the roms.` … `3) Use the makefile …  To test the new terminal, make ramterm
  instead of romterm.`
- `README:32-37` explains why `bootrom.s` carries a bare list of `long` symbol addresses: `this list
  serves two purposes:  first, it forces loading of library stuff (such as the allocators and the
  layer code) that would not otherwise make it into rom, and secondly it provides a
  version-independent interface to the roms.` — deleting any entry silently shrinks the ROM.
- Non-cc tools: `mcc`, `mas`, `mld`, `mnm`, `mstrip`, `sed`, `dd`, `strip`, `sort`, `push` (remote
  copy), `dodbits` (PROM burner, remote), `pp`, `dcan`.

## contradictions and traps

### 1. `/usr/blit` vs `/usr/jerq` — one tree, two install roots
`proof/` installs under `/usr/blit` (nine `JERQ*` macros, `host/makefile:1-7`,
`term/makefile:1-9`), while `sys/`, `tek4014/`, `term/` and `twid/` install under `/usr/jerq`
(`sys/makefile:2`, `tek4014/makefile:10`, `term/makefile:1`, `twid/makefile:21`). This is not
cosmetic: `proof/term/makefile:20,36` links against `$(JERQLIB)/l.o` and `$(JERQLIB)/lib{sys,j,c}.a`
= `/usr/blit/lib/…`, but `blit/src/sys` — which *builds* `libsys.a` and `l.o` — has no install rule
at all and compiles against `/usr/jerq/include`. **Building `proof/term` after `blit/src/sys` links
against files that nothing in this tree ever puts in `/usr/blit/lib`.**

### 2. The transcript disagrees with the makefile it came from
`proof/test/debug:23` records `probe(/usr/jerq/font/S.15/ALL) returns 21` — a live `proof` run
asking for a font under `/usr/jerq/font`, while `proof/host/makefile:5` compiles
`-DJERQFONT="/usr/blit/font"`. The committed transcript is evidence the shipped binary was built
from a `/usr/jerq` variant of this makefile. Treat the makefile, not the transcript, as the spec —
but do not use the transcript to "confirm" the font path.

### 3. `proof/host` as committed does not link
`host/makefile:16-17` links exactly `main.o io.o font.o map.o`. `main.c` calls
`readhunk()` (`:121`), `swallow()` (`:112`), `sendpkt()` (`:128`), `getjerq()` (`:130`),
`oflush()` (`:166,168`); `io.c:115` calls `readpage()`. Across all nine files in `host/`,
**`readhunk` is defined only in `conv.c` — which the link line omits — and `swallow`, `sendpkt`,
`getjerq`, `oflush` and `readpage` are defined nowhere in the directory.** `conv.c` appears only in
the `pp:` documentation target (`makefile:47`). Five to six undefined symbols. Per CLAUDE.md, V10's
`ld` **writes its output anyway** and merely clears the execute bits — so a harness that tests for
`proof` existing will pass on a broken binary. Ask `ld` what it said.

### 4. `proof/host/io.c` cannot compile as written
`io.c:73-81` declares `int pages[NPAGES];` inside `static struct { … } input;`, then `io.c:111`
does `input.pages[n].offset == 0` — a member selection on an `int`. Hard error in any C compiler.

| `proof/host/freq.c` | — | own `main()` (`:145`), `#include "dev.h"` (`:94`) which does not exist in the proof tree; in no rule |

### 6. Build-rule output name never matches the install name
- `tek4014`: the compile target is **`jek.m`** (`makefile:5`), `mopt` rewrites it to **`m.out`**
  (`:9`), and the install copies `m.out` to **`/usr/jerq/mbin/tek4014.m`** (`:10`). Three names for
  one artefact. The `binstall` path skips `mopt` and copies `jek.m` directly (`:14`). A harness that
  looks for `tek4014.m` in the build directory will never find it.
- `twid`: builds **`twid`**, installs as **`twid.m`** (`makefile:7` vs `:21`).
- `term`: builds **`romterm`**, and the artefacts that leave the directory are `bits0/1/2` and a
  *sorted* `romterm.nm` (`makefile:32-36, 49-50`).

### 7. `tek4014/README` names a file that is not in the tree
`README:1-3` says to install everything under `/usr/jerq/src/tek4014` `except for the file that
belongs in /usr/jerq/bin -- the file that 68ld's tek4014`, and `:8` says to `chmod
/usr/jerq/bin/tek4014` executable. `git ls-files v10/usr/blit/src/tek4014` returns exactly thirteen
files (`MEMO README bigapl.c dclip.c dline.c dline.h dlsegment.c flash.c jdlineto.c jek.c makefile
tiny.c tinyapl.c`) — **there is no `tek4014` driver script.** The `/usr/jerq/bin/tek4014` the README
and MEMO both depend on is missing from the corpus; the makefile only produces the `.m` for
`/usr/jerq/mbin`. Anything that runs `tek4014` will fail until that wrapper is written.

### 8. `term/README` warns you off the very files beside it, in shouted caps
`README:52-54`: `The output will be in bits[012], which are the bits to roms [01], [23], [45].  The
bits? in this directory are NOTNOTNOTNOTNOT the bits of the TTY roms.` `bits0`, `bits1` and `bits2`
**are committed** (`git ls-files v10/usr/blit/src/term`) — as are `romterm` and `vitty`, the linked
binaries. So the directory holds committed build products that the README explicitly says are not
the shipped ROM contents, sitting next to `rom.0`…`rom.5`, which are (`README:48`: `rom.? are the
bits for the roms.`). Using `bits[012]` as ROM images is the documented mistake. Note also
`makefile:31` `bits: bits0` — the `bits` target depends on only the first of the three, though the
`bits0` recipe makes all three.

### 9. `romterm.nm` is committed in the *wrong* sort order for its destination — deliberately
`README:51` `(it must be sorted)` and `makefile:50` `sort +2 romterm.nm -o $>`. The committed
`v10/usr/blit/src/term/romterm.nm` is in **address** order (`:1` `ffffffea a crcF`, `:3` `0000 a
A_RDRFBI`, `:93` `40012 T display`), i.e. raw `mnm` output. That is correct *here*; the name-sorted
form belongs at `/usr/jerq/src/mpx/term/romterm.nm`. Copying this file to the mpx tree unsorted is
the trap. (`$>` in the recipe is an augmented-make macro; SysV make does not define it.)

### 10. `term/makefile` reaches off the machine
`makefile:27,29,39,41` run `push panther …` and `panther "cd /usr/guest/aek/bits; dodbits …"` —
`make prom` and `make testprom` require a *remote host named `panther`* and a personal home
directory on it. These targets are unrunnable and must not be in any build plan. `makefile:24-26`
also does `cp testrom junk; mstrip junk; dd if=junk of=testbits …` — a temp file named `junk` in the
source directory.

### 11. `term/makefile` sets `CFLAGS` and never uses it
`makefile:4` `CFLAGS=-j`, but every rule spells its flags out (`:10` `$(CC) -o vitty -j vitty.o`).
Setting `CFLAGS` on the command line changes nothing here — and in `tek4014/makefile` and
`twid/makefile`, which have **no `.c.o` rule**, overriding `CC` on the command line silently
compiles 68000 terminal source with the host VAX compiler.

### 12. `sys/makefile`'s `new:` target belongs to a different library
`makefile:20-22`:
```
new:	$(FILES)
		$(AR) uv libj.a `mlorder $(FILES) | tsort`
		$(AR) ma clip.o libj.a line.o
```
The file's product is `libsys.a` (`:1`); this target updates **`libj.a`** and orders `clip.o` and
`line.o`, neither of which exists in `blit/src/sys`. It is a copied rule from the `libj` directory.
Per CLAUDE.md, `ar cr`/`ar r` accept object names that do not exist — so this would "succeed".

### 13. `l.s` has a bug fix that only exists because the ROM is optimised
`sys/l.s:23`: `mov.l	mouse, mouse+4		# BUG FIX FOR OPTIMIZED CURSOR.C IN ROM!!` — inside the
level-1 autovector, before `introutine`. The RAM-side `cursor.c:138-140` sets `mouse.xy` and
`mouse.jxy` itself; this line patches around the *ROM's* mopt'ed copy. Rebuilding `cursor.c` into
ROM without `mopt` and leaving this line in, or removing it while running against a stock ROM,
breaks the cursor either way. `bootrom.s:99-105` (the ROM's own level-1 vector) does **not** have
the line — the two vector tables differ by exactly this instruction and by
`add.l &1,ticks0` / `realtime` (`l.s:24,193-200`), which the ROM lacks entirely.

### 14. `dline.h` defines, not declares
`dline.h:4-10` — `short Jdmajor; short Jdminor; short Jxmajor; short Jslopeneg; Point PtCurrent;
Word DotMask;` with **no `extern`**. It is included by `dclip.c:2`, `dline.c:11`, `dlsegment.c:3`
and `jdlineto.c:2` — four tentative definitions of six symbols. This links only because the era's
`ld` merges commons. Add `-fno-common` semantics (or a strict linker) and `tek4014` stops linking.

### 15. `tek4014`'s fonts are the wrong type on purpose
`jek.c:149` and `flash.c:52` both declare `extern Font tinyfont, bigaplfont, tinyaplfont;`, but
`tiny.c:44-53`, `bigapl.c:83-92` and `tinyapl.c:46-55` define them as anonymous
`struct { short n; char height; char ascent; long unused; Bitmap *bits; Fontchar info[129]; }`.
`jek.c:1052-1059` then stores `&tinyfont` into `Font *font[8]`. The struct is layout-compatible with
`Font` by hand, not by declaration; K&R C never checks. Do not "fix" the type without checking
`font.h`.

### 16. `dline.c` embeds inline assembly that depends on the compiler's stack layout
`dline.c:27` `Word dotmask; /* must compile as -16+S%1(%fp) */`, and eleven `asm("	rol.w
&1,-16+S%1(%fp)")` / `ror.w` statements (`:180,189,196,211,218,229,236,246,253,263,270,280,287,297,304`).
Adding, removing or reordering **any** local in `_dline` silently corrupts the texture mask. The
comment is the only thing that says so.

### 17. `usr/include/shares.h` is not from the tape
`shares.h:5-9`: `RECONSTRUCTED BY ipnx.  Not in the v10src tarball, although six libc members
include it. … Every constant below is measured out of Bell Labs' own 1989 objects in libc.a -- see
v10/src/PATCHES.md.` Verified: `git ls-files v10superset | grep shares` returns the sources, man
pages and objects but **no `shares.h`** — it is the only header in this chunk with no superset
counterpart. Two consequences:
- CLAUDE.md's "Current state" says `v10/` currently reports **zero** deviations from the tapes. This
  file is a deviation, committed at `39c00e7f`.
- The file's own pointer, `v10/src/PATCHES.md`, is stale: that overlay is gone, and the surviving
  file is `v10/usr/src/build/PATCHES.md`.

The header is nonetheless the best record of a real ordering constraint, and states it as a cost
already paid (`:21-24`): `Getting this wrong cost a run: without it,
"/usr/include/sys/lnode.h":22:syntax error / saw NAME on 'u_short l_flags;' -- line 22, not the
uid_t line above it, which is the detail that named the cause.` — i.e. `<sys/types.h>` must precede
`<sys/lnode.h>`, and `shares.h` is the file that has to do it because `setlimits.c` and `getshput.c`
include `<shares.h>` and nothing else.

### 18. `label.h` includes a header that does not exist
`label.h:46-48`:
```
#ifdef KERNEL
#include "sys/jlabel.h"
#endif
```
`git ls-files 'v10/usr/include/sys/*label*' 'v10/usr/include/*jlabel*'` returns **nothing**. Any
kernel compile that defines `KERNEL` and reaches `label.h` fails. (`label.h:50` also closes with
`#endif L_BITS` — a trailing token after `#endif`, which strict cpp rejects.)

### 19. `tr.h`'s kernel branch addresses a directory layout this tree does not have
`tr.h:1-13` includes nine headers as `"../h/param.h"`, `"../h/dir.h"`, `"../h/user.h"`,
`"../h/tty.h"`, `"../h/buf.h"`, `"../h/proc.h"`, `"../h/systm.h"`, `"../h/clist.h"`,
`"../h/file.h"` — the V7 `sys/h/` layout. There is **no `v10/usr/sys/h/`** (`git ls-files` count: 0);
V10's kernel headers are under `v10/usr/sys/sys/`. `v10/usr/include/sys/tty.h` and
`v10/usr/include/sys/clist.h` do not exist either. `tr.h` under `KERNEL` is dead as shipped.

### 20. `a.out.h` and `nlist.h` are an incompatible pair, and `a.out.h` carries the wrong comment
Both define `struct nlist` and all of `N_UNDF N_ABS N_TEXT N_DATA N_BSS N_COMM N_FN N_EXT N_TYPE
N_STAB N_FORMAT` and `#define n_hash n_desc`. The structs differ:
`a.out.h:50-59` uses `union { char *n_name; long n_strx; } n_un;` (string-table form);
`nlist.h:6-12` uses a bare `char *n_name;` (in-core form). Including both is a redefinition error and
the two layouts are not interchangeable. Worse, `a.out.h:45-49` carries verbatim the comment that
belongs to `nlist.h`: `this file is included by <a.out.h> and should be used if you aren't
interested the a.out header` — inside `a.out.h` itself, where it is false. A linear read of
`a.out.h` is told it is `nlist.h`.

### 22. Conditional headers where a linear read takes the wrong branch first
- **`mp.h:7-17`** — the `#ifndef vax` branch comes **first** and line 9 is not C at all:
  `{	short high; 	big-endian assumed (also check ifdefs in .c)`. It compiles only because
  the VAX `#else` (`:13-16`) is the branch taken. Anyone reading top-down, or compiling with `vax`
  undefined, hits a syntax error. The stray prose is also an instruction: *"also check ifdefs in
  the .c"*.
- **`values.h:47-82`** — three mutually exclusive blocks in the order `u3b||u3b5||u3b2`, then
  `pdp11||vax`, then `gcos`. A linear read gets the 3B20's IEEE constants first; the VAX ones are
  second. `values.h:83-87` then makes `_LENBASE` depend on `u370`.
- **`db.h:87-96`** — `SAVE_LEN` is `10` under `vax`, `3` under `pdp11`, and if neither is defined
  the file contains `@ "SAVE_LEN not defined"` (`:95`) — a **deliberate syntax error** so the
  compiler reports the message. Do not read that line as a directive.
- **`fio.h:36-48`** — `COUNT` is `long` under `GNOT`, `int` otherwise, and `SEEK` maps to `seek`
  vs `lseek`, but only when `FIO_IMP` is defined. Two of the three settings are invisible to a
  normal include.
- **`cin.h`** — 243 lines, every declaration duplicated inside
  `#if defined(__STDC__) || defined(__cplusplus)` / `#else`. Nine of the pairs are *identical* on
  both sides (`cin_quit`, `cin_reset`, `cin_return`, `cin_step`, `cin_stepin`, `cin_stepout`,
  `cin_system`, and `cin_info`'s `void` form) — the conditional buys nothing there and hides that
  the prototypes were machine-generated.

- `dumprestor.h:26` — `} spcl;` defines the object, not just the type.
- `fb.h:64-74` — `struct fb { … } fb;` and `char *progname;`.
- `picfile.h:39-49` — `char *PIC_command; char *PIC_error;` and `struct PIC_conf { … } PIC_conf[];`.
- `saio.h:40,50-54` — `struct devsw devsw[]; char b[NBUFS][BSIZE]; daddr_t blknos[NBUFS]; struct iob

### 24. `saio.h` and `pagsiz.h` disagree about what `BSIZE` is
`saio.h:22` and `:50` use `BSIZE` as a **constant** (`char i_buf[BSIZE];`, `char b[NBUFS][BSIZE];`).
`pagsiz.h:7` defines it as a **function-like macro**: `#define BSIZE(dev) (BITFS(dev)? 4096: 1024)`.
Include `pagsiz.h` before `saio.h` and the array declarations become bare macro names. `saio.h` must
get its `BSIZE` from the kernel's `sys/param.h`, never from `pagsiz.h`.

### 25. `class_object.h` is one byte
`wc -c v10/usr/include/class_object.h` → `1` (a lone newline). It is 1 byte in `v10superset` too, so
this is authentic, not a local loss. `class_task.h` defines `class object` itself (`:105-120`),
so nothing is missing — but any rule that treats a non-empty header as the marker of a present
dependency will mis-read this one. Related: per CLAUDE.md, *"an object file is not evidence a
compiler ran"*; here, a header file is not evidence a declaration exists.

### 26. `float.h` vs the tree's other `float.h`s
`v10/usr/include/float.h` is the VAX-D set (`DBL_MANT_DIG 56`, `DBL_MAX_EXP 127`). `git ls-files`

`string.h`, `time.h`, `assert.h`, `dir.h`, `fio.h`, `libc.h`, `regexp.h`, `signal.h`, `ipc.h`,
`getflags.h`, `fstab.h`, `grp.h`, `pwd.h` — every one of which exists at top level **and** under
`CC/`, `lcc/`, `oCC/`, `olcc/` or `libc/`.

### 27. `make clean` deletes a committed source? — checked, no
Every `clean:` in this chunk is safe: `proof/host/makefile:35-36` (`*.o proof`),
`tek4014/makefile:17-18` (`*.o m.out lens core` — `lens` is not built here, a harmless leftover

### 28. `curses.h` is BSD, and dates itself
`curses.h:1` `/* 5/15/81 (Berkeley) @(#)curses.h	1.8 */` — a 1981 Berkeley header inside a 1989
distribution, whose `#include <sys/ttyio.h>` (`:6`) has been retargeted from BSD's `<sgtty.h>`.
It uses `SGTTY`/`struct sgttyb` and `TIOCSETP`/`TIOCGETP` throughout (`:26,131-140`), so it needs
V10's `sys/ttyio.h` to keep providing the V7 sgtty names. `sgtty.h` (`:1-4`) exists only to say so:
`compatibility hack` / `#include <sys/ttyio.h>`.

### 29. `sys.s` documents system calls that are gone
`sys.s` is an assembler `.set` table, and five entries are commented out with their reason:
`:39` `#	.set	switch,38		# inoperative`, `:41` `#	.set	tell,40			# obsolete`,
`:55` `#	.set	reboot,55`, plus `# USG 49/50/57/58` (`:49-50,57-58`) and `# LOCAL 62` (`:62`).
It also gives `utime` and `smdate` the **same** number 30 (`:30-31`) and `signal` 48 with no `sigsys`.
Any assembler source that assumes a dense table, or that `switch`/`tell`/`reboot` exist, breaks.
`errno.h:39-40` similarly carries `ECONC 36` and `EGREG 37` with no comment, and `EHASF`/`ENOTBLK`
share 15 (`:19-20`).
