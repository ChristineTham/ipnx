## documented build steps

**None. Nothing compiles, assembles or generates these files, and nothing in `v10/` installs
them.** Specifically:

- `git ls-files 'v10/usr/jerq/icon/'` shows exactly two non-icon files in the whole tree:
  `v10/usr/jerq/icon/README` and a stray `v10/usr/jerq/icon/foo`. There is **no makefile,
  mkfile, `Mk`, `dest`, `SOURCE` or `ICON.LST` anywhere under `v10/usr/jerq/icon/`** — so
  `usr/src/cmd/Admin/Mk` and `Admin/dest`, the tape's command build system, never see this
  directory. These are data shipped as-is.
- The only face48 packaging rule in the entire repository belongs to a **different tree**:
  `/Users/christie/Repositories/Unix/ipnx/v10/usr/630/makefile:291` (`		mkdir ./icons/face48; \`)
  and `:368-369` (`	@cd icons/face48; \` / `	cpio  -pdv $(TAPEROOT)/icons/face48 < ./SOURCE`).
  That rule copies `v10/usr/630/icons/face48/` — 34 files — to `$(TAPEROOT)/icons/face48`,
  obeying the file list in `v10/usr/630/icons/face48/SOURCE`. It has nothing to do with the
  869-file jerq tree this chunk belongs to.
- The face server reads the directory **live**, at run time, by `opendir`/`readdir`
  (`v10/usr/src/cmd/face/file.c:450-488`, `filldir()`), and decides whether to rebuild by the
  directory's **mtime** (`newdata()` at `:186-195` stats `bp->extname`). So the install is a
  plain recursive copy, and the directory mtime is load-bearing: a copy that back-dates the
  directory suppresses the rebuild.
- Which names matter is decided **outside this tree**: `people.tab` (`astro/pjw=pjweinberger`,
  per `faced.9:143-149`) names the source file, and `file.c:94-96` links `builtins[]` entries
  into the per-person directory. Presence in this directory is necessary, not sufficient.

## contradictions and traps

1. **`ches` and `njit_bc` are ONE INODE — and the pair spans chunks 016 and 017.**
   `ls -i` in `v10/usr/jerq/icon/face48/` gives inode `166824001` for both. A file-by-file
   install (`cp` per name, or a per-chunk restore) breaks the identity and writes two
   independent 1056-byte files. Only two hardlink pairs exist in the whole 869-file directory
   and this is one of them; the other is `gale`≡`wag`, whose members are in **016** and
   **018** (checked against the chunk lists) — so the brief's note that `gale`≡`wag` spans
   016 and *this* chunk is wrong about the second half; the pair that spans 016/017 is
   `ches`≡`njit_bc`.
   `v10tapes/HARDLINKS` records **zero** face48 entries (`grep -ci face48` → 0) and
   `v10tapes/CASEMAP` likewise 0: those files track case-collision kept/dropped pairs only, so
   they are no help here and do not contradict the two real links.

2. **`nohup.out` is a committed accident, and it is EMPTY.** git blob
   `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391`, 0 bytes, 0 lines — the shell's `nohup` redirect
   file left in the icon directory. `face`'s `filldir()` skips only `.` and `..`
   (`file.c:467-469`), so it enters `nohup.out` into the served `48x48x1` directory as a
   zero-length "face". The only other empty file in the directory is `faceS` (chunk 016),
   identical by blob hash. Neither is a face; neither should be installed.

3. **Wrong-dimension data in a directory whose readers hardcode the size.**
   `v10/usr/jerq/src/face/face.c:6-8` fixes `#define ICONSIZE 48` / `ICONBYTES (48*(48/8))` =
   288 / `ICONWORDS (48*(48/16))` = 144 — 48 rows, three words each. Five files in this chunk
   do not have exactly 48 rows of three comma-terminated words:
   - `p.collinson` — **47** data rows (1034 B): one row short.
   - `linda_o`, `lindaca` — **49** data rows (1078 B each); row 49 is all-zero.
   - `kre` — 48 data rows but a **trailing blank line** (1057 B).
   - `phoneca` — 48 rows, but **no trailing comma** on any row (1008 B); a parser that eats a
     comma per word rather than tolerating end-of-line will stop at row 1.
   A reader that reads `ICONBYTES` and stops silently truncates the 49-row files and runs off
   the end of `p.collinson`.

4. **A partial duplicate tree elsewhere holds the only packaging rule, and its copies
   DIFFER.** `v10/usr/630/icons/face48/` carries 34 of these names with its own `SOURCE`
   manifest and the `cpio` rule above. Of the 30 names it shares with the jerq tree, `cmp`
   says 25 are byte-identical and **5 differ**: `dan`, `ecc`, `rob`, `unknown` (630 = 1056 B,
   jerq = 1152 B in each case). **`rob` is in this chunk.** Installing the 630 copy over it,
   or resolving the name from the wrong tree, changes the image. The two trees are separate
   destinations (`$(TAPEROOT)/icons/face48` for the 630, `/usr/jerq/icon/face48` for this one)
   and must not be reconciled.

5. **The 630 `SOURCE` manifest is stale against its own directory.** `SOURCE` has 34 lines
   including `ICON.LST` and `SOURCE` itself; `ICON.LST` beside it has 32 and omits both. The
   `cpio -p` at `makefile:369` therefore copies its own manifest into the product, and any
   name added to that directory without editing `SOURCE` is silently not shipped. (Not a
   defect in this chunk's files, but it is the rule a packager searching for "how is face48
   installed" will find first, and it is the wrong tree.)

6. **`v10/usr/jerq/icon/README` is stale against the program's own search path.** The README
