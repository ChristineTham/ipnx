## documented build steps

**`joff/host`** — builds `a.out` (installed as `joffhost`). BSD variant (`makefile`):
`CFLAGS= -g`, `YFLAGS=` empty; `a.out` is 23 objects plus `/usr/tac/trace/trace.o`,
linked by `cc *.o` (line 10). Targets: `go` (build then run against
`../term/a.out` and `/usr/jerq/lib/mpxterm`), `bin` (install), `lint`, `clean`,
`print`, `e` (a separate expression-parser test binary from `egram.o alloc.o names.o
environ.o expr.o`), `oh` (regenerates the header-dependency block at the foot of the
makefile), `menus.c` (copies `../menus.c`). System V variant (`makefile.5`): `CC=Ncc`,
links with `Ncc`, uses `environ5.o`, and hand-rolls yacc because of a documented
compiler bug — `makefile.5:10-12` *"this is a kludge to get round a bug in 5.0 UNIX
yacc which under certain input conditions, found in gram.y, will produce defines like
`# define  0 48`  etc. C does not like that"*, then `yacc gram.y` / `sed -e "/^#  *define
*[0123456789]  */d" y.tab.c > gram.c` / `rm y.tab.c` / `$(CC) -c gram.c`. Tools beyond
cc/as/ld: **yacc**, **lint**, **sed**, **oh**, **Ncc** (SysV variant).

**`joff/term`** — the 5620 side. `CC=mcc`, `CFLAGS= -g`. `a.out` from seven objects
compiled and linked with **`mcc`**, then run through **`mopt` twice** (makefile:8-13):
`mopt a.out|grep "%"` / `rm a.out` / `mv m.out a.out`, repeated. Ordering is explicit —
each `mopt` pass consumes `a.out` and produces `m.out` which is renamed back. `lint`
needs `-I/usr/jerq/include -DMPX`. `menus.c` is copied from `../menus.c`.

**`jplot`** (top) — `all: jplot jplot.m jplot.j unplot`. Every rule starts by extracting
an **`ar` archive**: `ar x blit.c.a jcom.h` (line 3) for `unplot`; `libblit.a` is built by
`mkdir xplot` / `cd xplot;ar x ../blit.c.a` / `cc -c -O *.c` / `ar rc libblit.a *.o`,
then `ranlib libblit.a` (lines 7-15); `jplot.m` and `jplot.j` extract `inblit.a` plus
`jcom.h` from `blit.c.a` and compile with `/usr/blit/bin/mcc [-j] *.c -lmj`. The scratch
directory `xplot` is created and removed each time. Tools: **ar**, **ranlib**, **mcc**;
libraries **`-lm`** (host) and **`-lmj`** (68000).

**`jplot/blit`, `jplot/inblit`, `jplot/ojplot`** — each carries an **`ORDER` file**
recording the `ar` member order of the archive it was unpacked from
(`blit/ORDER` 31 names, `inblit/ORDER` 4, `ojplot/ORDER` 19). `ojplot/ORDER` includes
`plot.sh` and `makefile`, so the makefile itself was an archive member.

**`jplot/ojplot`** — a complete second build. `CFLAGS = -O`, `LDFLAGS = -s`, `INS = cp`,
`MCC = mcc`, `MCFLAGSJ = -j`, `MCFLAGSM =` (empty), `MSTRIP = mstrip`.
`all: $(LIBNAME) jplot jplot.j jplot.m plot`. Library: `ar r libjplot.a $(OFILES)` then
`ranlib`. Terminal programs: `$(MCC) $(MCFLAGSJ) jplot.c -o jplot.j` then `$(MSTRIP)
jplot.j` (and the `.m` equivalent) — stripping is part of the build, not the install.
`plot` is `cp plot.sh plot`. `install: all`. Tools: **ar**, **ranlib**, **mcc**, **mstrip**.

**`jx`** — `all: jx sysint`, both compiled with the **host** `cc -g`. `comm.h` is

**`kbd`** — `kbd.m: $(KBDSYS); mcc -o kbd.m $(KBDSYS)`, objects via `mcc -c -g`.

**`lens`** — `CC=mcc`, `AS=mas`, `CFLAGS=-g`. `lens` links seven objects with `mcc`.

## contradictions and traps

1. **`jplot.m`/`jplot.j` have two different destinations, and one of them is wrong by
   the package's own header.** `jplot/makefile:33-34` copies both to `/usr/blit/mbin`;
   `jplot/ojplot/makefile:56-57` (`$(INS) jplot.m $(LIBDIR)`, `LIBDIR = /usr/blit/lib`)
   copies both to `/usr/blit/lib`. Both `jplot/blit/jplot.h:1` and
   `jplot/ojplot/jplot.h:1` hardcode `#define JPLOT "/usr/blit/mbin/jplot"`, and both
   `openpl.c`s build the `68ld` command from that macro — so **ojplot's install rule puts
   the file where ojplot's own source will not look for it**.

2. **The installed `plot` cannot find the installed `jplot`.** Both makefiles install
   `jplot` into `/usr/blit/bin`, but `ojplot/plot.sh:1` sets
   `PATH=/bin:/usr/bin:/usr/jerq/bin` and line 13 execs bare `jplot`. `/usr/blit/bin` is
   not on that path.

3. **`68ld` lives in two places.** `/usr/blit/bin/68ld` in `joff/host/main.c:10`,
   `jx/jx.c:15`, `jplot/blit/openpl.c:61`, `jplot/ojplot/open.c:56,59`; but
   `/usr/jerq/bin/68ld` in `jx/sysint.c:15`. The sysint one is a **dead variable** —
   `load` is declared and never referenced anywhere in the file — so it is stale text,
   not a live disagreement, but it is the only `68ld` path the reader of that file sees.

4. **`mpxterm`: source says `/usr/blit/lib`, both makefiles override to `/usr/jerq/lib`.**
   `joff/host/main.c:21` defaults to `/usr/blit/lib/mpxterm`; `joff/host/makefile:4` and
   `joff/term/makefile:4` both pass `m=/usr/jerq/lib/mpxterm`. The makefiles are the later
   word and they say `jerq`.

5. **`lens`: makefile installs to `/usr/jerq/mbin/lens.m`, README says
   `/usr/jerq/lib/lens.m`.** `makefile:19` vs `README:36-37`. The README's line is a
   fallback for machines without `mopt` (`README:35` *"In the makefile, mopt is currently
   local"*) — so the documented fallback silently changes the destination directory as
   well as the tool chain.

6. **`lens`: three spellings of the generated table header, and nothing includes any of
   them.** `README:13` calls it `bytables.H`; `makefile:11-12` names the target and the
   output `bytable.h`; the file on the tape is `bytable.H`. No `.c` or `.C` in the
   directory references it (verified: `bytable` appears only in `README` and `makefile`) —
   `magn.c` builds its tables at run time in `ngen()` (`magn.c:42-63`) and `makefile:8-9`
   makes `magn.o` depend on `magn.c` alone. On a case-insensitive filesystem `bytable.h`
   and `bytable.H` are the same file, so `make bytable.h` would overwrite the committed
   `bytable.H`.

7. **`lens`: the `.C` files are not the build inputs; the hand-edited `.s` files are.**
   `README:15-18` (quoted above) plus *"You probably don't want to look at the .s files
   except to hand-tune them."* The makefile has no rule for `mag2.o`/`mag3.o`/`mageven.o`/
   `magodd.o`, so make's built-in `.s.o` rule with `AS=mas` picks up the `.s`. `.C` is not
   a suffix any make of the period knows. **A build that compiles the `.C` files instead
   loses the hand-tuning silently and still produces working objects.**

8. **`lens/mageven.s` exports a truncated symbol.** Line 9 `global magbyeve`, line 10
   `magbyeve:` — 8-character truncation of the `magbyeven` that `magn.c:15` declares and
   `magn.c:131` calls. Line 6-7 likewise splits the stabs source-file name into two
   entries, `"mageven."` then `"c"`. Consistent with `a.out.h:13`'s `char n_name[8]`, but
   any tool that compares symbol strings without truncating will report an undefined
   `magbyeven`.

9. **`lens/makefile:17-20` — `install:` depends on `lens` and ships `m.out`.** The
   artefact copied to `/usr/jerq/mbin/lens.m` is `mopt`'s output, not the `lens` that make
   just verified. `clean:` (line 23) removes `m.out`, `*.o`, `core` and `magtbl` but **not
   `lens`**, so `lens` survives a clean while its installed form does not.

10. **`lens`: `safemagn.C` and `unsafemagn.C` are documented alternates the makefile never
    builds, and `unsafemagn.C:48` calls `Bitblt`, which is not in this tree.**
    `README:31-33` names it: *"require a bitblt they can trust, and thus call Bitblt,
    which is just Bart's bitblt with a capital B. You can find it in
    /usr/jerq/src/lib/bitblt.C"*.

11. **`layer/makefile:25-26` — a rule whose output name never matches its target.**

    never created, so the target is never satisfied, and each attempt silently replaces
    the real library (`L=layer.a`, line 1) with a topologically re-ordered one.

12. **`layer`: one archive, two copies of `layer.h`.** `makefile:13` makes every member
    depend on `$(INCL)/layer.h` = `/usr/jerq/include/layer.h`, but `dellayer.c:2`,
    `lblt.c:2`, `lrectf.c:2`, `newlayer.c:2` and `upfront.c:5` say `#include "layer.h"`
    (the local copy in this directory) while `layerop.c:2`, `lbitblt.c:2`, `lbox.c:2`,
    `lpoint.c:2`, `lscroll.c:2`, `lsegment.c:2`, `ltexture.c:2` and `debugblt.c:2` say
    `#include <layer.h>`. Two definitions of `struct Layer`/`struct Obscured` end up in
    one `layer.a` if the copies ever diverge.

13. **`layer/debugblt.c` is a second definition of `lbitblt()` and is not in the
    makefile.** `SOURCE` and `OBJ` (makefile:5-8) list `lbitblt.c` and omit `debugblt.c`;
    `debugblt.c:73` defines `lbitblt` too, guarded only by `#ifdef DEBUG` around the
    *reporting*, not the function. Its `MAXAREA` is 50 (`debugblt.c:13`) against
    `lbitblt.c:4`'s 75. Building the directory with a wildcard rather than `$(OBJ)` yields
    a duplicate symbol and a shorter work list.

14. **`layer` has no install rule at all.** The only destination it names,
    `/usr/jerq/include`, is a directory it *reads*. Where `layer.a` goes is stated nowhere
    in this chunk.

15. **`kbd/Makefile:21-24` says its own sources belong somewhere else, from somewhere
    else again.** `ikeya pull sola /usr/luca/kbd/kbd.c /usr/jerq/src/kbd` and three more:
    the sources are named as living at **`/usr/luca/kbd`** on host **`sola`** and
    installing to **`/usr/jerq/src/kbd`** — while in this distribution they sit at
    `/usr/blit/src/kbd`. Neither of the makefile's two path claims agrees with where the
    files actually are.

16. **`kbd/Makefile:19` moves rather than copies.** `mv kbd.m /usr/jerq/lib` — after
    install the build directory has no `kbd.m`, so the `save:` target (lines 13-16), which
    copies `kbd.m` to `o.kbd.m`, must run *before* install or it copies nothing. Line 20
    then re-reads the binary from its new location.

17. **`jx/comm.h` is a generated file committed as source.** `makefile:18-19` regenerates
    it from nine `../libj/*.c` files with grep and sed. The committed copy is that output;
    if `../libj` changed, the header in the tree is stale and the makefile will silently
    rewrite it.

18. **`jx/jx.c:84` bakes the build directory into the shipped binary.**
    `execv("/usr/blit/src/jx/sysint",args)` under `-x`. This is positive evidence the tree
    belongs at `/usr/blit/src/jx` — and it directly contradicts `kbd`'s claim
    (`/usr/jerq/src`) for a sibling directory of the same tree.

19. **`jx/makefile:29` cleans a `hello` that no rule builds.** `rm -f core *.o hello
    sysint jx`; `hello.c` has no target anywhere. `MLD` (line 2) is defined and never
    used, and `all:` (line 7) never invokes the `.c.o` rule the makefile defines.

20. **`jplot/makefile` reads archives that this tree does not contain.** Lines 3, 7, 9,
    16, 18-19, 24, 26-27 all extract `blit.c.a` or `inblit.a`. Neither file exists —
    `ls v10/usr/blit/src/jplot/` gives `blit inblit jcom.h makefile ojplot unplot.c`. The
    archives were unpacked to directories, their member order preserved only in
    `blit/ORDER` and `inblit/ORDER`. **As it stands the makefile builds nothing.**
    Note also that `libblit.a` is rebuilt with `ar rc … *.o` (line 11) from a shell glob,
    which ignores `ORDER` outright, and then `ranlib`'d (line 13).

21. **`jplot/jcom.h` is a build artefact, not an original.** It is byte-identical to
    `jplot/blit/jcom.h` (verified with `cmp`) and is exactly what `makefile:3`'s
    `ar x blit.c.a jcom.h` deposits in the top directory so `unplot.c:4`'s
    `#include "jcom.h"` resolves. Treating it as a source file duplicates a member of
    `blit.c.a`.

22. **`jplot/makefile:5-6` — prerequisite and command name different files.**
    `jplot: libblit.a ../driver.o` then `cc driver.o libblit.a -lm -o jplot`. The
    prerequisite is one directory *up*; the command names the current directory. The only
    `driver.c` in the tree is `ojplot/driver.c`, one directory *down*.

23. **`jplot/blit` and `jplot/ojplot` are two complete, incompatible plot libraries with
    the same entry points.** Both define `openpl`, `closepl`, `move`, `box`, `circle`,
    `arc`, `erase`, `point`, and a `subr.c` exporting `graphic`/`alpha`/`flush`/`xysc`;
    both ship a `jplot.h`. The headers are not interchangeable — `blit/jplot.h:28-45` is
    the `struct penvir` double-precision environment, `ojplot/jplot.h:45-54` is the flat
    `float boty/botx/scalex` version — and the wire protocols differ: `blit/jcom.h:3`
    makes `OPEN` `0360` where `ojplot/jplot.h:3` makes it `033`. `blit` is the successor
    (`nline.c` replaces `line.c`, and `whoami.c`, `ctype_.c`, `cfill.c`, `spline.c`,
    `parabola.c` have no ojplot counterpart), but **nothing in the tree says so**, and
    both `install:` rules write a `jplot` to `/usr/blit/bin`.

24. **`joff/host/menus.c` and `joff/term/menus.c` are generated copies of `../menus.c`.**
    Both makefiles carry `menus.c: ../menus.c` / `cp ../menus.c menus.c`
    (`joff/host/makefile:37-38`, `joff/term/makefile:24-25`). The two committed files are
    byte-identical to each other (verified with `cmp`) and to `v10/usr/blit/src/joff/menus.c`
    (2229 bytes each). **Any edit to either copy is overwritten by the next build.** The
    trap is sharper than it looks: both say `#include "common.h"`, but
    `joff/host/common.h` is 49 lines of VAX-host declarations while
    `joff/term/common.h` is a single line, `#include <jerq.h>` — the same source text
    compiles against two entirely different headers.

25. **`joff/host/makefile` and `makefile.5` do not build the same program.** `makefile:6-9`
    links 23 objects plus `/usr/tac/trace/trace.o`; `makefile.5:4-6` links 18 and drops
    `graphics.o`, `functions.o`, `srctext.o`, `zdc.o` and `trace.o` (and swaps
    `environ.o` for `environ5.o`). But `gram.y` calls into every one of the dropped
    files — `gram.y:154` `zdc( $4, $6 )`, `gram.y:144` `searchdirc( $4 )`, `gram.y:140-141`
    `cdc( $4 )`, `gram.y:138` `srclinec( $4, $6 )` — so the System V build has undefined
    references unless something outside this chunk supplies them.

26. **`joff/host/environ.c` and `environ5.c` are two definitions of the same three
    functions, and they behave differently on interrupt.** Both define `wrap()`,
    `settty()`, `resettty()`. `environ.c:10-14` adds `breaksig()`, which sets `clean = 1`
    before calling `wrap()`, and `environ.c:27` installs it as the `SIGINT` handler.
    `environ5.c:23` installs `wrap` itself — so on System V an interrupt reaches
    `environ5.c:15` `if( !clean ) abort();` with `clean` still zero and **the program
    dumps core instead of exiting**.

27. **`joff/host`: the deliverable has three names.** Every rule builds `a.out`
    (`makefile:6,10`); `makefile:17` `lint: joffhost` depends on a file no rule makes;
    `makefile:22` renames `a.out` to `joffhost` at install; and `main.c:53` prints
    `use: joff [-ofile]`. Also `makefile:10` is `cc *.o` — a glob, so any stale object in
    the directory is linked in, `egram.o` (from the `e:` target, line 33, built from a
    `egram.y`/`egram.c` that is not in the tree) included.

28. **`joff/host/makefile:11` — the trace object is required but not linked.** Line 9
    lists `/usr/tac/trace/trace.o` as a prerequisite of `a.out`; line 10 links `cc *.o`,
    which cannot reach it; line 11 is the commented-out form that would,
    `# cc *.o /usr/tac/trace/trace.o`. So the build **demands a file it does not use**,
    and on a machine without `/usr/tac` it fails before compiling anything.

29. **`joff/host/makefile`'s tail is machine-generated and self-appending.**
    `makefile:13-15` `oh:` / `echo "#########" >>makefile` / `oh *.h ../*.h >>makefile`.
    Everything after line 41 is `oh`'s output; running `make oh` twice duplicates it.
    That block also lists *sources* as targets — `makefile:42` `stab.h :a.out.h`,
    `makefile:44` `... traps.c :expr.h`, `makefile:49` `... user.h :stab.h`,
    `makefile:53` `common.h :../protocol.h` — which no compilation rule can satisfy.

30. **`/usr/tac/` is a personal tree, not a system path.** `joff/host/makefile:9,21,22`.
    Alongside it, `format.c:15` carries `/* ikeya!<ctype.h> is wrong */` and
    `lens/README:39` is signed `Mark (rabbit|research|ikeya ! msm) Manasse` — `ikeya` is
    also the tool name in `kbd/Makefile:20-24`. These files were cut from working
    directories on named machines, and their absolute paths reflect that, not a
    distribution layout.

31. **The two `openpl()` implementations disagree about how to find the terminal.**
    `jplot/blit/openpl.c:37,50-53` hardcodes `char plotty[] = "/dev/tty"` and exits if the
    open fails; `jplot/ojplot/open.c:46-51` prefers `ttyname(1)` and falls back to
    `/dev/tty`. The newer (blit) code has the stricter requirement.

32. **`blit/ORDER` puts headers and one source out of alphabetical run.** Lines 29-31 are
    `jcom.h`, `jplot.h`, `parabola.c` — after `whoami.c`. `parabola.c` defines
    `parabola()`, which `spline.c:31,36,49` calls, so its position at the end of the
    archive matters to a one-pass linker. The makefile's own `ar rc … *.o` path discards
    that order.

33. **`joff/term/makefile:8-13` runs `mopt` twice and greps for `%`.** `mopt a.out|grep
    "%"` — the grep is the only check that the optimiser said nothing; nothing tests its
    exit status, and `rm a.out` follows unconditionally. If `mopt` fails, `mv m.out a.out`
    moves a stale or absent file and the next pass compounds it.

## files with no build contribution

**107 files.** These are plain C sources, headers, and assembler that name no
destination, state no build step, and carry no path string: the joff host debugger's
internals (expression evaluator, stab reader, 68000 disassembler, stack walker, trap
and breakpoint handling, menu/scratch machinery, symbol tables), the joff terminal's
graphics and line editor, the `jplot`/`ojplot`/`inblit` plot primitives (arc, box,
circle, fill, spline, text, coordinate scaling), the `layer` window primitives, the

kernels. The largest are `keyboard.c` (24 KB), `expr.c` (19 KB), `joff.c` (14 KB),
`snap.c` and `traps.c` (13 KB each), `lens.c` (10 KB).
