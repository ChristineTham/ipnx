# chunk 001

150 files, all under `v10/usr/630/man/src/` — the **AT&T 630 MTG (DMD 5620 successor)
cross-development man pages**: `p_man/man3` (116 pages + SOURCE), `p_man/man4` (font.4),
`p_man/man5` (ascii.5, math.5, values.5), `u_man/man1` (26 pages + SOURCE).

No makefile, mkfile, shell script or build transcript is present in this chunk. Every
statement below comes from man-page prose — `.SH FILES` sections, `.SH SYNOPSIS` lines,
and option descriptions. Everything installs relative to **`$DMD`**, the environment
variable naming the root of the 630 software tree, not to a fixed absolute path.

## documented build steps

**`p_man/` and `u_man/` (this chunk, as a package).** Nothing in the 150 files builds
them. The only machine-readable artefact is a `SOURCE` file per directory, which is
verbatim the directory's own listing *including `SOURCE` itself* — verified identical for
all four directories (`p_man/man3` 117 entries, `p_man/man4` 2, `p_man/man5` 4,
`u_man/man1` 27). No file in this chunk says how `SOURCE` is consumed. The install target
is `$DMD/man/?_man/man[1-8]/`, packed (`dmdman.1:52-56`).

Formatting requirements, read off the source: these are **`man` macros plus AT&T
extensions that are not in stock `-man`** — `.XE` (index entry, used ~200 times), `.ds ZZ
DEVELOPMENT PACKAGE` (a page-footer string set at the top of most 3R/3L pages), `.SK`,
`.Ee`, `.S -4`/`.S +4`, `.DS`/`.DE`, `.IT`, `.P`, and the `'\"macro stdmacro` /
`.nr X` / `.if \nX=0 .ds x} … .TH \*(x}` preamble on every page whose SCCS id is
`ccsman:` (atof, bsearch, conv, ctype, ecvt, frexp, lsearch, memory, qsort, rand,
ssignal, str, strtol, swab, ascii.5, math.5, values.5, and the `.3m` set). Additional
preprocessors are required: **`tbl`** (`.TS`/`.TE` in keyboard.3r, matherr.3m, setupval.3r,
version.3r, dmdversion.1, loadfont.1, mc68conv-free pages) and **`eqn`** (`.EQ`/`.EN` in
drand48.3l, erf.3m, gamma.3m, norm.3l). `matherr.3m:134-179` is a boxed, expanded `.TS`
that will not set without `tbl`.

**`dmdcc` (the compiler driver these pages describe).** Documented behaviour, in case the
build must reproduce it (`dmdcc.1:12-29`): it defines `DMD630`, sets include path to
`$DMD/include`, library path to `$DMD/lib`, links the 630 startup `crtm.o`, and passes
`-r`-equivalent to `mc68ld` so relocation survives for download. `-#` prints the exact
`mc68cpp`/`mc68ccom`/`mc68as`/`mc68ld` command lines. `-Z n` sets process stack, floor
2048. `-g` is required for `dmdpi`, `mc68dis -F`, `mc68dump -z/-n`, and for `mc68nm`'s
TYPE/SIZE/LINE columns; `-O` must **not** be combined with `-g`-style debugging
(`dmdpi.1:660-663`, `dmdcc.1:82-85`).

**Archive construction.** `mc68lorder.1:36-45` gives the one concrete build command in
the chunk:

    mc68ar cr library `mc68lorder *.o | tsort`

and states it is *not* required — `mc68ld` makes multiple passes over a portable archive
(`mc68ld.1:42-49`, `mc68lorder.1:23-34`). `mc68ar.1:147-154` and `mc68strip.1:81-96`
require `mc68ar s` to rebuild an archive symbol table after `mc68strip` touches an
archive, *before* `mc68ld` can use it.

**Tools needed beyond cc/as/ld:** `m4` (via `mc68as -m` / `dmdcc -Wa,-m`), `tsort`,
`pack` (implied by "Packed manual entries"), `tbl`, `eqn`, `col` (`dmdcat -b`),
`cat`(`dmdcat` is a shell program that calls it), and `layers`/`xt` for anything that
downloads.

**Example compile line, for a cached application** (`cache.3l:207-213`):

## contradictions and traps

1. **`mc68cpp` documents `/usr/include`; `dmdcc` documents `$DMD/include`.**
   `mc68cpp.1:288-293` FILES says `/usr/include` / `standard directory for #include
   files`, while `dmdcc.1:19` says `it sets the include search path to $DMD/include`.
   `mc68cpp.1` is a lightly-edited copy of the host `cpp(1)` page (its DESCRIPTION even
   says `use of mc68cpp other than in this framework is not suggested`). A build that
   trusts `mc68cpp.1` will resolve `<dmd.h>` against the host's `/usr/include` and get
   the VAX headers. `dmdcc.1` is the authority.

2. **`mc68as.1` names two different temp directories.** FILES (`:68-70`) says
   `/tmp/mc68a[A-L]AAaXXXXXX`; the WARNING (`:94`) says `/usr/tmp/mc68asXXXXXX`. The
   WARNING is inside `.if 'mc68'3b' \{ … \}`, so for the `mc68` build it does not render
   at all — but the string is in the file and will match any naive path scan.

3. **`mc68ld.1` and `mc68as.1` are one source formatted per target, gated on string
   comparisons.** `mc68ld.1` carries branches for `'mc68''` (empty → generic UNIX:
   `/lib`, `/usr/lib`), `'mc68'b16'`, `'mc68'x86'`, and number registers `\nC \nD \nF \nG
   \nH`. Line 254 is `.ie 'mc68'' /lib/lib?.a` with `.el $DMD/lib/lib?.a` on 255; lines
   257-261 wrap `/usr/lib/lib?.a` in `.if 'mc68''`. **The 630 paths are the `.el`
   branches.** Reading the file linearly yields `/lib` and `/usr/lib` first and they are
   wrong here. Same shape in `mc68as.1` (`'mc68'x86'`, `'mc68'3b'`, `'mc68'b16'`) and
   `mc68strip.1:11-13,51-59`, and `mc68nm.1:55-61,93-100` where the *live* `-f`
   description and a *commented-out* `-a` description both claim "full output".

4. **`icon.1` has a stale path fossilised in its tab-stop string.** `icon.1:151` is
   `.ta \w'$DMD/src/icons/texture/*     'u` — the width is measured off
   **`$DMD/src/icons/texture/*`**, a path that appears nowhere in the FILES list two
   lines below (`$DMD/lib/icon.m`, `$DMD/icons/*`). The FILES list was shortened and the
   measuring string was not. Do not install icons to `$DMD/src/icons/texture`.

5. **`$DMD` is required at *runtime*, not just build time.** `dmdversion` reads
   `$DMD/VERSION` (`:27`), `dmdman` reads `$DMD/man` (`:27`), `loadfont` reads
   `$DMD/termfonts` (`:23`), `layers` reaches for `$DMD/bin/wtinit` (`wtinit.1:13`), and
   `mc68dis -l` and `mc68ld -l` resolve against `$DMD/lib`. Installing the tree without
   setting and exporting `DMD` leaves every one of these silently reading the host's
   directories instead.

6. **`$DMD/termfonts` must contain exactly nine files.** `loadfont.1:114-115` says so and
   `:22-24` says *every* file name in that directory becomes a Load-submenu item — so a
   stray `.orig`, `README` or backup file in the install directory becomes a font in the
   menu and fails on download.

7. **Man pages install *packed* and one directory shallower than they live.** Source is
   `man/src/{p_man,u_man}/manN/`; `dmdman` looks in `man/{p_man,u_man}/manN/` for
   `Packed manual entries` (`dmdman.1:55`). A naive `cp -r src/* $DMD/man/` produces
   `$DMD/man/p_man/...` correctly only if `src` is stripped, and leaves the entries
   unpacked, which `dmdman` does not document handling.

8. **`dmda.out` vs `mc68a.out`.** `dmdcc` defaults its output to `dmda.out`
   (`dmdcc.1:159-160,199`) but the underlying `mc68ld` defaults to `mc68a.out`
   (`mc68ld.1:29,144,263`). Two different default names in the same toolchain; a build
   rule that calls `mc68ld` directly gets the second.

9. **`mc68ar` may add the same member twice.** `mc68ar.1:164-166`: `If the same file is
   mentioned twice in an argument list, it may be put in the archive twice.` Consistent
   with this repository's existing rule to assert member counts.

10. **`mc68lorder` silently drops non-`.o` members.** `mc68lorder.1:57-63`: `Object files
    whose names do not end with .BR .o , even when contained in library archives, are
    overlooked. The global symbols and references are attributed to some other file.` So
    an ordering computed for an archive holding oddly-named members is wrong, not empty.

11. **A version number baked into prose, not a name.** `version.3r:53-54` states
    `0x080806` `corresponds to Release 1.1 of the 630 MTG`, and `dmdversion.1:59-65`
    keys on `'8;8'` = 630 vs `'8;7'` = 5620. These pages document 630 firmware 8;8;6.
    No `$DMD/VERSION` content is given anywhere in the chunk, so the host-side version
    string is not recoverable from these files.

12. **`jx` and cached applications are mutually exclusive in part.** `jx.1:120-121`:
    `\fIJx\fR does not work with application cached with \fBA_SHARED\fR, \fBA_BSS\fR or
    \fBA_DATA\fR`, and `jx.1:117-118` `does not work in the nonlayers environment`.
    Relevant if anything in the build smoke-tests a downloaded program through `jx`.

13. **`.SH FILES` in `structures.3r` lists three headers but the page's own SYNOPSIS
    includes only those three, while sibling 3R pages include `<menu.h>`, `<label.h>`,
    `<object.h>`, `<setup.h>` and `<dmdio.h>` with no page in this chunk stating their
    install path.** `menu.h` (cmdcache.3l:10, tmenuhit.3r:11), `label.h` (labelon.3r:12),
    `object.h` (cache.3l:10, cmdcache.3l:12, decache.3l:34), `setup.h` (setupval.3r:8).
    Their destination is `$DMD/include` only by analogy — the chunk does not say it.
