## documented build steps

- **A cross-compiler, not `cc`.** `CC=/usr/jerq/bin/3cc`, `CFLAGS=-J -DJERQ`. `cc`, `as` and
  `ld` never appear anywhere in either Makefile.
- **Three mutually exclusive configurations, selected by uncommenting** (`Makefile:1-29`):
  - Blit stand-alone — `#CFLAGS=-O -j`, `#CC=/usr/blit/bin/mcc`, `#I=/usr/blit/include`, `#CYFLAGS=`
  - 5620 mux — `#CFLAGS=-DJERQ`, `#CC=/usr/jerq/bin/3cc`, `#CYFLAGS=-DJERQ -jm -Dlint`, and in
    pengo only `#LDFLAGS=-g`
  - 5620 stand-alone — `CFLAGS=-J -DJERQ`, `CYFLAGS=-DJERQ` — **this is the block left active
    in both directories**
  `README:8-10`: "To make the version desired / just remove the comment '#'s from the makefile
  lines of the version required. / do a 'make clean' if another version's .o files are present
  and do 'make' / or 'make pengo'."
  `README:4-6` warns the outputs are not interchangeable: "The makefile is for a stand-alone
  Blit version, and both a stand-alone / and mux version suitable for the 5620. The Blit
  version is too large to / run under mux."
- **Default target `pengo`** (`Makefile:63-64`), prerequisites `pengo.h $(OFILES)`, recipe
  `	$(CC) $(CFLAGS) $(LDFLAGS) $(OFILES) -o pengo`. `LDFLAGS` is undefined in the active
  configuration (its only definition, `#LDFLAGS=-g`, is commented and only in pengo), so it
  expands empty.
- **`-DJERQ` and `-J` are load-bearing at source level, not just flags.** `pengo.h:5-14`
  switches the whole header on `JERQ`: it picks `jerq.h` vs `blit.h`, and redefines
  `sbits(x)` as `x, 0x0000` (32-bit rows) versus `x` (16-bit rows). `bitmap.c:18-24` pairs
  that with `#define MUL 32` vs `MUL 16` for indexing `char_0_9`/`char_A_Z`. So `chars.c`'s
  one data table serves both machines only because the macro doubles it — while `digits.c`,
  `header.c`, `water.c` and all 53 icons are raw hex with no such adaptation.
- **`MPX` selects mux behaviour independently of `JERQ`.** It is never defined by any Makefile
  in this chunk; the mux config's `CFLAGS=-DJERQ` alone does not set it. `pengo.h:8-10` only
  re-defines `MPX` if `MUX` is already defined (`#ifdef MUX` / `#define MPX MPX`), and nothing
  defines `MUX` either. The `#ifdef MPX` branches — `pengo.c:71-77`, `init.c:34-45,58-85,506-509`,
  `mouse.c:104-108`, `endgame.c:55-58`, `globals.c:51-53` — therefore all compile as the
  stand-alone variant under every configuration the Makefiles actually offer.
- **`cyntax` is a fourth tool** beyond the compiler — a lint-like C checker whose source is at
  `v10/usr/src/cmd/cyntax/`. `Makefile:79-80` `%.O:	%.c` / `	cyntax -c -I$(I) $(CYFLAGS) $%.c`,
  and `Makefile:82-83` `cyntax:	pengo.h $(CYFILES)` / `	cyntax -jm $(CYFILES) && touch cyntax`.
  It is off the `pengo` dependency path — an optional check, and the **only** place `-I$(I)` is
  ever passed (see trap 5).
- **Three objects are insisted on with `-g`, in pengo only** (`Makefile:72-77`): `walrus.o`,
  `player.o`, `globals.o` each get `		$(CC) $(CFLAGS) -g -c <file>`. These are exactly the
  auto-player, its caller, and the globals it reads — the code that was newest.
- **sapengo strips the execute bits after linking** (`sapengo/Makefile:64` `	chmod 644 pengo`),
  which is right for a loadable that `32ld` reads rather than execs. pengo's Makefile dropped
  that line.
- **`make clean`** — `	rm -f $(OFILES) $(CYFILES) core jim.recover cyntax`. It deletes no
  committed source. `jim.recover` is the `jim` editor's crash file; `cyntax` here is the stamp
  file, not the tool.
- **`make print`** — `	@pr -n Makefile pengo.h $(CFILES) $(ICONS)`. Note it lists neither
  `README` nor `goo1`.
- **`ICONS`** (`Makefile:47-61`) names 53 icon files, used only as prerequisites of `shapes.o`.

## contradictions and traps

1. **`sapengo` cannot link: it calls a function whose only definition it does not ship.**
   `v10/usr/jerq/demo/src/sapengo/player.c:78-79` is
   `		if(autoflag)` / `			push = TRUE, scott();`, with `:10` `extern int autoflag;`.
   `scott()` is defined only in `walrus.c` (`v10/usr/jerq/demo/src/pengo/walrus.c:16`), and
   **sapengo has no `walrus.c`** — verified with `git ls-files -s`, not `ls`, because the
   filesystem lies about case here. Its Makefile omits the file from `CFILES`, `CYFILES` and
   `OFILES` too. `scott` is the *only* walrus symbol reached from outside `walrus.c`;
   everything else in that file (`dorule`, `to_wall`, `kill_seed`, `x_wall`, `stun_x`,
   `y_wall`, `stun_y`, `to_corner`, `togoal`, `avoid_bee`, `avoid_block`, `do_move`,
   `go_right/left/up/down`) is called only from within it.
   **sapengo is an inconsistent snapshot**: it took the *newer* sources — `mouse.c` with the
   `Auto` menu entry, `player.c` with the `scott()` call — but neither the file that implements
   the feature nor the Makefile that builds it. Its Makefile is the *older* shape (no walrus,
   no `install:`, no `-g` rules, `chmod 644` still present). Under V10's `ld`, which "writes its
   output even with symbols undefined … reports them and clears the execute bits", this
   produces a `pengo` file that looks built and is not — and sapengo's own `chmod 644` then
   masks the one signal `ld` gives.
2. **`README:11-12` flatly denies the install rule that is right there in the same directory.**
   "No 'make install' is present as different machines would / most probable have the loadable
   in different place." Both Makefiles have `install:` at line 66. The README is byte-identical
   in both directories (blob `8a7f4638`) and is the author's upstream text; the `install:` rule
   is a *local* Bell Labs addition — it is absent from the pristine Makefile inside `goo1`.
   The README is the wrong authority on the destination; the Makefile and the launcher agree
   with each other against it.
3. **The active configuration builds the stand-alone loadable and installs it into the mux
   directory.** `Makefile:22-26` labels the uncommented block `#	5620 Version (stand alone)`

   `CYFLAGS=-DJERQ -jm -Dlint`) is the one commented out. `README:5-6` says the versions are not
   interchangeable. Either the flags or the destination is wrong, and the file cannot say which.
4. **`/usr/jerq/bin` does not exist in this tree at all.** `git ls-files v10/usr/jerq/bin`
   returns 0 paths, and `v10/usr/jerq`'s only subdirectories are `demo font icon include mbin
   sgs src`. So `CC=/usr/jerq/bin/3cc` names a compiler that is absent — its source is at
   `v10/usr/jerq/sgs/3cc.c`, its man page at `v10/usr/man/man9/3cc.9`, and it must be built and

   ships. This is not local to pengo: `v10/usr/jerq/demo/mux/demo:1` puts `/usr/jerq/bin` on

6. **`shapes.o` depends on the wrong source.** `Makefile:69-70`:

7. **`$%` in the cyntax pattern rule expands to nothing.** `Makefile:79-80`

   to build any `.O` at all. This does not affect `make pengo`, which is the default target.

20. **`init.c:15` sizes the maze backtrack stack from constants the board does not obey.**

21. **`event.c:29-30` searches the event table with no bound.**

## binary files

**None.** All 99 files are ASCII text.

The 53 files under `pengo/icons/` are ASCII-hex bitmap data and are reported as a count and a
format rather than quoted. Each holds **exactly 64 `0x....` values** — a 32×32 monochrome
bitmap as 32 rows of two 16-bit shorts — as a bare comma-separated initialiser list with no
declaration, consumed by `shapes.c`'s `short char_X[] = { #include "icons/X" };`. Two
formattings are used and explain the only size differences: 47 files are 32 lines of 2 values
(480 bytes), and 6 — `0diamond` (536), `block` (544), `blank`, `egg`, `fblock`, `null` (520
each) — are 8 lines of 8 values.

They carry no text. Per file, `tr -d '0-9a-fA-FxX, \t\n' < f | wc -c` is **0** for all 53, and
over the 53 concatenated it is **0**; a `grep -nvE` for any line that is not a pure hex list
matches nothing in any of them. Two are uniform by value rather than truncated or empty:
`icons/null` is 64 × `0x0000` (the all-clear pattern `put_char` falls back to,
`pengo.c:235-237`) and `icons/blank` is 64 × `0xFFFF` (the board is drawn black-on-white,
cf. `pengo.c:12`). Neither is a zero-byte file.

`chars.c`, `digits.c` and `header.c` are C sources that are likewise almost entirely hex.
`chars.c` (298 lines) is read and quoted in full above — it carries no bare hex lines at all,
every value being wrapped in the `sbits()` macro. `digits.c` is 337 lines of which 320 are pure
hex (`short N[]`, ten 32×32 numerals at 64 shorts each, indexed by `score.c:29`
`bit32.base = (Word *)&N[(score % 10) * 64];`) and 17 are the include, the comment "These are
bitmaps for the big numerals that are used to display / the score." and the ten `/* n */`
labels. `header.c` is 208 lines of which 203 are pure hex (`short char_header[]`, the digitised
penguin, 13×16 by 203 rows per `pengo.h:20-21` `HEAD_X`/`HEAD_Y`, wrapped as a `Bitmap` at
`endgame.c:3-7`) and 5 are the include and the declaration. Stripping hex from the data lines
of all three leaves **0** characters, so no prose is hidden in them.
