## documented build steps

### `mux/term/` — the mux terminal program (68000, cross-built)
- Tools: `CC = mcc`, `AS = /usr/blit/bin/mas`, linker `mld`, stripper `mstrip`, symbol lister
  `mnm`, lorder helper `mlorder`, plus `qed`, `sed`, `sort`, `join`, `pr`, `lint` — **none of the
  cross tools is cc/as/ld**.
- Flags it insists on: `CFLAGS = -g -O -m -DMPXTERM -I$(PDIR) -DBlit` (`makefile:3`); lint adds
  `-Dmc68000 -Uvax -Dvoid=int`.
- Link line (`makefile:25-26`): `mld -o muxterm -b 256 Pl.o $(OBJS) frame/frame.a rom.o -llayer
  -lsys -lj -lc` — `-b 256` sets the base address; library order is significant.
- Ordering is a three-stage generation chain that must run before any link:
  1. `rom.s` from `romroutines` + `romterm.nm` + `romsed.f` (`makefile:39-40`):
     `sort romroutines | sed 's/\(........\).*/\1/' | join -j2 3 - romterm.nm | sed -f romsed.f > rom.s`
     — note the `sed` truncates every symbol to **8 characters**, which is why `romterm.nm`
     carries names like `jstrwidt`, `cursinhi`, `rectXrec`.
  2. `goo.s` from `makelocore` + `/usr/blit/include/mpx.h` + `$(JERQPROC)` + `Pl.template`
     (`makefile:43-44`).
  3. `Pl.o` from `goo.s` via a **size back-patch** (`makefile:46-49`):
     `$(CC) -S procsize.c` then
     `sed 1s/999/\`sed -n '/short/s/.*\t//p' < procsize.s\`/ < goo.s > Pl.s` then `$(CC) -c Pl.s`
     — `Pl.template:1` is the literal `set PROCSIZE,999`; the compiled `sizeof(struct Proc)`
     replaces the 999.
- `pcheck.c` is compiled **twice from the same source** under different flags:
  `-DROMCRC` → `pcheck.o` (`makefile:73-74`), plain → `pcheck.o` then renamed
  `norompcheck.o` (`makefile:75-77`).
- Two link targets: `muxterm` (uses ROM CRC, links `rom.o`) and `Muxterm` (uses
  `norompcheck.o`, links **no** `rom.o`). The commented assertion `# : Should be 0106`
  (`makefile:36`) is a check on `mnm -g muxterm | grep Sys`.
- Non-obvious tool: `makelocore:10` runs `qed - -x makelocore.q -e $MPXH` — a **`qed`
  script**, and `makelocore.q:3` uses a literal control-Z (`\cz`) in its substitution.
- `README` states the whole cross-tree invalidation graph — see the install table. Two
  hard rules: changing `P` or `Sys` invalidates `jerqproc.h`, `mpx.h`, `boot.c`, and the
  jerq `sys`/`mlib` libraries; adding `mpx.h` entry points **at the end** is safe, adding
  them **in the middle** makes "all `mcc -m` binaries wrong".

### `mux/term/frame/` — the frame text library
- `L=frame.a`, `CFLAGS=-gOmDMPXTERM -I..` (`makefile:2` — one concatenated argument, not
  separate flags), `CC=mcc`, `AR=ar`.
- Members are added one at a time and the object deleted (`makefile:23-24`):
  `$(CC) -c $(CFLAGS) $%.c && ar r $L $%.o && rm -f $%.o`.
- Member **order** has its own target (`makefile:19-21`): `rm frame.a; ar cr frame.a
  \`mlorder $(FILES) | tsort\`` — cross-`mlorder`, not the host's.

### `ompx/` — the 4.1BSD host multiplexor
- `CFLAGS = -I$(INCL) -I$(JINCL) $(SFLAGS) -O`, ordinary `$(CC)`/`$(LDFLAGS)`.
- Targets: `mpx` (the product) and `tmpx` (`-DTRACING`). The tracing target does a
  save/restore dance around the shared object name (`makefile:17-20`):
  `-mv mpx.o smpx.o` … `$(CC) $(CFLAGS) -DTRACING -c mpx.c && mv mpx.o tmpx.o` … `-mv smpx.o mpx.o`.
- Protocol objects are compiled individually from `$(PDIR)` (`makefile:28-39`); `pcntrl.o`
  has a rule but is in neither `POBJS` nor any link line.
- `files` (`ompx/files`) is the package's own manifest — 36 paths including a `proto/`
  and a `term/` subtree that **do not exist under `ompx/`**.
- Conditional compilation switches named in the source but never set by the makefile:
  `TRACING`, `PSTATISTICS`, `PSTATSDESC`, `PDEBUG`, `MPXSTATS`, `MONITOR`.

### `ompx/sys/` and `ompx/sys/4.2bsd/` — kernel patches
- No makefile. Placement and build are stated in prose and includes only: `readme:1`
  ("modified Berkeley 4.1bsd kernel source files"), the `../h/` include convention, the
  `mx1.c` installation comment, and the mail Subject lines in `4.2bsd/`.
- Each driver expects a **config-generated count header**: `dk.c:5` `#include "dk.h"`,
  `dz.c:3` `#include "dz.h"` plus `dz.c:10` `#include "bk.h"`, `tty_pty.c:16` `#include "pty.h"`.
  None of these is in the chunk; they are produced by the kernel config step.
- Machine/version switches the sources branch on: `VMUNIX`, `PDP`, `vax`, `VAX`, `KERNEL`,
  `MONITOR`, `DTRACE`, `NDK`, `NDZ`, `NBK`, `NPTY`, `BTL_BLIT`, `CCA_PAGE`, `COMPAT`,
  `TRACE`, `_USESTAT`. `4.2bsd/*` needs `BTL_BLIT` defined for any Blit support at all.
- `ttynew.c` / `ttyold.c` both contain a `#ifdef vax` inline-assembly fast path
  (`asm("	scanc	r9,(r10),_partab,$077")`) guarded by an explicit warning:
  `ttyold.c:415-417` `THE POSITIONING OF CP, CC, AND CE ARE CRITICAL AND MUST NOT BE
  CHANGED WITHOUT PATCHING THE 'ASM' INLINES BELOW.  WATCH OUT.` — a register-allocation
  dependency on that compiler.

### `pads/` — the Pads window system (C++ host + 68000 terminal)
- Three makefiles, **no recursion between them**. Build order is therefore manual:
  1. `pads/Makefile:1-3` generates `pads.pri` (and `pads.pub`) from `pads.h` with
     `/usr/jerq/bin/cleave +E pads`, then `touch pads.pri`.
  2. `host/` builds `libpads.a` with **C++**: `CC +E -I.. -I/usr/include -c \`pwd\`/$*.c`
     (`host/Makefile:12`) — `CC` (cfront), the `+E` flag, and an **absolute source path via
     `\`pwd\``**. `trace.c` alone is built with plain `cc` (`host/Makefile:8-9`).
     Archive: `ar ruv libpads.a $(OFILES)` then `ranlib libpads.a`.
  3. `term/` builds `pads.m` with `/usr/blit/bin/mcc -g -I..`, runs
     `/usr/blit/bin/mopt a.out|grep "%"`, then `mv m.out pads.m` (`term/Makefile:5-8`).
- Every `host/*.o` and `term/*.o` depends on `../pads.pri`, so step 1 must precede 2 and 3.
- `term/univ.h:3` defines `PADS_TERM` **before** including the header; `term/protocol.c:1`
  does the same. Compiling the terminal side without `PADS_TERM` selects the C++ `class
  Index` instead of `typedef unsigned short Index` and cannot work.
- Version handshake at runtime, not build time: `pads.h:6` `#define PADS_VERSION 0x850125`,
  checked in `term/host.c:67-69` — `ProtoErr( "host/term versions differ - regenerate. " )`.
  Host and terminal must be built from the same `pads.h`.
- `.hcy` files (`pads/.hcy`, `pads/term/.hcy`) are plain source lists for some
  hardcopy/print tool; they name no destination.

### `proof/` — troff previewer (this chunk holds only the shared headers, docs and ship scripts)
- No makefile in this chunk (`proof/host/makefile` and `proof/term/makefile` are in the
  next chunk). The build/ship steps present are `shipit` (one `ship` line) and `torabbit`
  (seven `push rabbit <src> <dst>` lines) — a **manual distribution script**, not a build.
- `proof.mm` documents the design, including that the terminal side "is a direct steal of
  the code from `mpx`" (`proof.mm:38`) and that troff mode is entered by sending
  ACK = `017` (`proof.mm:39`, matching `comm.h:7`).

## contradictions and traps

1. **`/usr/blit` vs `/usr/jerq` inside one package.** `mux/term/makefile` is entirely
   `/usr/blit` (include, `mas`, `libsys.a`, install to `/usr/blit/lib`), but
   `mux/term/README:5-22` names only `/usr/jerq/src/sys`, `/usr/jerq/src/mlib`,
   `/usr/jerq/include`, `/usr/jerq/src/lib`, and `mux/term/makelocore:34` writes
   `/usr/jerq/lib/notsolow.o`. `mux/term/frame/makefile:17` lints against
   `-I/usr/jerq/include` while its parent uses `-I/usr/blit/include`. A linear read
   picks up whichever root it hits first and is wrong half the time.

2. **`ompx/mpx.c` names a path this distribution does not have.** `ompx/mpx.c:24` and
   `ompx/sys/4.2bsd/mpx.c:35` both hardcode `/usr/jerq/lib/mpxterm`; verified with
   `git ls-files`, `v10/usr/jerq/lib/` is **empty (0 files)** and the file actually exists
   as `v10/usr/blit/lib/mpxterm` (alongside `v10/usr/blit/lib/muxterm`). Same for
   `/usr/jerq/bin/68ld` (`ompx/mpx.c:784`, `4.2bsd/mpx.c:828`) — absent; `68ld` is at
   `v10/usr/blit/bin/68ld`. And `/usr/jerq/bin/cleave` (`pads/Makefile:2`) — absent;
   `cleave` source is at `v10/usr/jerq/src/cleave`.

3. **`ompx`'s build target is `mpx`; its README says the binary is `ompx`.**
   `ompx/makefile:11` builds `mpx` (and `:14` `tmpx`); `ompx/README:4` says the artefact is
   distributed as `/usr/jerq/bin/ompx`. There is no install rule at all in `ompx/makefile`,
   and no rename. `v10/usr/jerq/bin/ompx` does not exist. The output name never matches the
   documented install name.

4. **`ompx/files` is a manifest for a different directory.** It lists `proto/…` (13 paths),
   `term/…` (13 paths) and `test/…` (2 paths) as if they were under `ompx/`. `git ls-files`
   shows `ompx/` has no `proto/`, `term/` or `test/` at all. The `term/` entries match
   `v10/usr/blit/src/mpx/term/` — including `term/notsolow.s`, `term/char.h` and
   `term/windowproc.c`, which exist under `mpx/term/` (notsolow.s, windowproc.c) or nowhere.
   Reading `files` as a description of `ompx/` produces phantom rows.

5. **`mux/term` and `mpx/term` are two near-identical trees, and `ompx/README` points at
   the other one.** `git ls-files` confirms both `v10/usr/blit/src/mux/term/` (this chunk,
   50 files, has `frame/` and `window.c`) and `v10/usr/blit/src/mpx/term/` (46 files, has
   `windowproc.c`, `goo.s`, `notsolow.s`, `x.c`, `x.s`, and a committed `mpxterm` binary).
   `ompx/README:2` says `../mpx/term`, which from `ompx/` resolves to the **other** tree.
   Their `Pl.s`, `Pl.template`, `README`, `bigrom.s`, `rom.s`, `romterm.nm`, `makefile` and
   most `.c` files are same-named. Confusing them is easy and silent.

6. **Committed build products sitting beside their sources, in five places:**
   - `mux/term/Pl.s` — generated by `makefile:46-49` from `Pl.template`. It has the
     back-patch already applied: `Pl.s:1` is `set PROCSIZE,2312` where `Pl.template:1` is
     `set PROCSIZE,999`, and lines 14-88 are the generated `mpx.h` entry table ending in a
     stray `#endif	MPX_H` (line 88) that leaked out of the header.
   - `mux/term/procsize.s` — generated by `$(CC) -S procsize.c`; `procsize.s:7` is
     `short	2312`, the value baked into `Pl.s`. Both go stale the moment `struct Proc`
     changes, and nothing in the makefile notices, because `Pl.o`'s rule regenerates them.
   - `mux/term/rom.s` — generated by `makefile:39-40` from `romroutines`/`romterm.nm`.
   - `pads/pads.pri` and `pads/pads.pub` — generated by `pads/Makefile:1-3` from `pads.h`
     via `cleave`.
   - `proof/temp` — a **zero-byte** file, and `proof/temp` is not referenced by anything
     in the chunk.

7. **`mux/term/bigrom.s` is a stale sibling of `rom.s` with no build rule.** Both are
   generated `set`/`global` tables of ROM addresses. `rom.s` (184 lines) is what the
   makefile produces and what the link uses; `bigrom.s` (186 lines) is referenced by
   nothing. They disagree: `bigrom.s:57-58` comments **out** `defont` and `:119-120`
   comments out `menuhit`, both of which `rom.s` (`:57-58`, `:119-120`) enables — and
   `Pl.template:13` needs `defont` (`long defont` / `# Sys[1]==pointer to default font`)
   while `control.c:342` calls `menuhit`. `bigrom.s` also lacks `crc16t_3`, `cursbm`,
   `curtabp`, `usercurt`, `interrup`, `Lblt`, `Lrectf`, `Lsegment`, `Ltexture`, `Rlayerop`
   that `romroutines:103-119` requests, and it enables `newlayer` (`:127`) where `rom.s`
   comments it out (`:125-126`) because `control.c:221` links its own. Assembling
   `bigrom.s` instead of `rom.s` produces undefined symbols **and** a duplicate
   `newlayer`.

8. **`mux/term/makefile` names four files that do not exist in the tree.** Verified with
   `git ls-files --error-unmatch`: `texture.s` (needed by the `texture.o` rule,
   `makefile:92-94`), `goo.s`, `norompcheck.o`'s source path is fine but the object and
   `frame/frame.a` and the `muxterm` output are all absent — expected for objects, but
   `texture.s` is a **source** the makefile has a rule for and the tree does not carry.
   The three `-l` libraries the link needs (`/usr/blit/lib/liblayer.a`, `libsys.a`,
   `libj.a`) are also absent from `v10/usr/blit/lib/`, so this package cannot link until
   `src/layer`, `src/sys` and `src/libj` are built and installed first.

9. **`makelocore`'s install line is double-echoed and never runs.** `makelocore:34` is
   `echo echo $AS -o /usr/jerq/lib/notsolow.o  notsolow.s` — two `echo`s, so the script
   prints the *text* `echo /usr/blit/bin/mas -o /usr/jerq/lib/notsolow.o notsolow.s` and
   assembles nothing. `notsolow.s` is written by the heredoc at `:15-33` and then left in
   the build directory. A build that trusts this script gets no `notsolow.o`, and
   `boot.c:55` depends on it (`these get set as arguments to main in notsolow.o`).

10. **The `4.2bsd/` files are mail messages, not compilable C.** All five
    (`ioctl.h`, `jioctl.h`, `mpx.c`, `sys_machdep.c`, `tty_pty.c`) begin with eight lines of
    RFC-822 headers — `From research!ulysses!smb  Sat Jan 28 18:10:55 1984` through
    `Subject: h/ioctl.h`. Line 1 is not valid C. The header must be stripped before use,
    and the `Subject:` line is simultaneously the only statement of where the file goes.
    `jioctl.h:57` also ends `#endif _JIOCTL_` with a bare token after `#endif`.

11. **`pads/Makefile`'s `install` copies two files it cannot build.** Lines 6 and 10 copy
    `host/libpads.a` and `term/pads.m`, but the top-level makefile has no rule for either
    and does not descend into `host/` or `term/`. Running `make install` in `pads/` on a
    clean tree fails; the subdirectories must be built first, by hand.

12. **`pads/term/Makefile` has no rule for the `pads.m` its `install` copies… almost.**
    `term/Makefile:5-8` does build `pads.m`, but `install` (`:16-17`) does **not** depend on
    it — `install:` has no prerequisite, unlike `host/Makefile:14` (`install: libpads.a`).
    So `make install` in `term/` will copy whatever stale `pads.m` is lying around.

13. **`term.c` needs a `/usr/jerq` build of `pads.m` that no makefile produces.**
    `pads/host/term.c:18` selects `"/usr/jerq/bin/32ld /usr/jerq/mbin/pads.m"` for
    `$TERM` in {5620, jerq, JERQ, Jerq, DMD, DMD5620}, but `pads/term/Makefile` compiles
    with `/usr/blit/bin/mcc` (68000) and installs only to `/usr/blit/mbin`. The WE32100
    build lives in the parallel `v10/usr/jerq/src/pads/` tree — a separate package.
    Both `v10/usr/blit/mbin/pads.m` and `v10/usr/jerq/mbin/pads.m` exist in the
    distribution; only the first is reachable from this chunk's makefiles.

14. **`term.c:31-37` has a fall-through default that a linear read gets backwards.**
    `loadcmd = MapTERM[0][0]` sets the **jerq** command as the default *before* the `$TERM`
    scan; the Blit command is only chosen if `$TERM` matches one of `blit`/`BLIT`/`Blit`.
    So on a Blit with `TERM` unset or misspelled, Pads downloads with `32ld`, not `68ld`.

15. **`/usr/blit/include/pads.h` is a stale duplicate that must not be used.** Verified
    with `cmp`/`diff`: the installed copy is dated **1984-04-27** and the source
    `pads/pads.h` **1985-05-31**. The old one has **no `PADS_VERSION`** (so
    `term/host.c:68`'s version check will not compile), no `PADS_TYPES`/`SRCFILE`, guards
    on `#ifndef TERM` instead of `#ifndef PADS_TERM`, spells the filler field `u_filler`
    instead of `pub_filler`, and defines `PRINTF_COPY` with `fmt?fmt:"0"` (the string
    `"0"`) where the source has `fmt?fmt:""`. `pads.pri` and `pads.pub` in
    `/usr/blit/include` **are** byte-identical to the source-tree copies, so only `pads.h`
    diverged — and only `pads.h` is the one nothing includes, which is why it rotted
    unnoticed. Do not resolve `pads.h` through `/usr/blit/include`.

16. **`pads/host/protocol.c` is dead code in its own package.** `host/Makefile:1-2` lists
    `OFILES=cache.o pad.o term.o menu.o remote.o sf.o padrcv.o stats.o help.o libC.o
    trace.o popen.o` — **no `protocol.o`**. `host/protocol.c` defines `RcvLong`/`SendLong`
    etc. as free functions calling `PutRemote`/`GetRemote`, which exist only on the
    terminal side (`term/host.c:14,26`); the host uses `Remote::rcvlong`/`sendlong` in
    `host/remote.c` instead. `host/protocol.c` and `term/protocol.c` are near-duplicates
    (the term one includes `<pads.pri>` with `PADS_TERM` defined and calls
    `ProtoErr("")`; the host one has no `PADS_TERM` and calls `ProtoErr()`), and only the
    term one is built.

17. **`proof/comm.h` and `proof/ocomm.h` are byte-identical** (verified with `cmp`). The
    `o` prefix implies "old", but there is no difference to choose between; both are
    52 lines and both `#define DEBUG` unconditionally at line 45, with the comment
    `/* define this for debugging */`.

18. **`proof/proof.mm` and `proof/comm.h` disagree about the wire encoding.**
    `comm.h:16-34` gives `C_PAGE 228`, `C_FONT 229`, `C_BSIZE 240`, `C_ABSH 241`,
    `C_ABSV 242`, `C_DEV 243`, `C_DRAW 244`, `C_EXIT 245`, `C_SCALE 246`, `C_WINDOW 247`,
    `C_SIZE 248`. `proof.mm:136-149` documents `239 (B) set point size`, `240 (N) move
    relative horizontal`, `241 (N) move relative vertical`, `242 (...) device control`,
    `243 (...) draw`, `244 change into a terminal`, `245 exit`, `246-255 set point size`.
    Every code from 239 up is shifted by one between doc and header, and `244` is "draw"
    in the header and "change into a terminal" in the document. The header is what
    compiles; the document is a design note that the code moved past.

19. **`proof/shipit` and `proof/torabbit` say `/usr/jerq/Font`; `proof.1` and `proof.mm`
    say `/usr/jerq/font`.** Verified case-exactly with `git ls-files`: only
    **lowercase** `v10/usr/jerq/font/` exists, and it does hold `IMAP`, `MISSING` and
    `SMAP` exactly as the man page and the design note describe. The ship scripts'
    `Font` spelling matches nothing. This is precisely the kind of case claim a
    case-insensitive `ls` would confirm falsely.

20. **`mux/term/README`'s paths are one directory level off for this distribution.**
    It names `/usr/jerq/src/lib/ellipse.c`, `/usr/jerq/src/lib/elarc.c`,
    `/usr/jerq/src/lib/menu.c` and `/usr/jerq/src/sys/{resume.s,cursor.c}`. `git ls-files`
    shows `v10/usr/jerq/src/sys/` is **empty** and the actual files are
    `v10/usr/jerq/src/lib/j/ellipse.c`, `.../lib/j/elarc.c`, `.../lib/j/drek/menu.c`,
    `.../lib/sys/cursor.c` (with `/usr/blit` twins at `src/libj/`, `src/libmj/`,
    `src/sys/`). `/usr/jerq/src/mlib` is empty too; its content is
    `v10/usr/jerq/src/lib/mj/` (blit: `src/libmj/`).

21. **Case-collision artefacts are live in the neighbouring trees.** `git ls-files` shows
    `v10/usr/jerq/sgs/as/u_Expand1.c`, `u_Gencode.c` and the whole
    `v10/usr/jerq/src/lib/u_C/` directory — `u_`-renamed twins from the extractor. None
    is inside this chunk, but any grep for `C/` or `Gencode` across the blit/jerq trees
    will miss or double-count them.

22. **`ompx/sys/mx2.c` and `mx1.c` both define the same globals.** `mx1.c:35-37`
    declares `struct chan chans[NCHANS]; struct schan schans[NPORTS]; struct group
    *groups[NGROUPS]; int mpxline;` and `mx1.c:43` `char mcdebugs[NDEBUGS];`; `mx2.c:51-53`
    re-declares `chans`, `groups`, `mpxline` and `mx2.c:69` re-declares `mcdebugs`. These
    are tentative definitions that a 1980s loader merges silently, but they are not
    `extern` and a stricter linker will reject linking both — and both must be linked
    (`mx1.c` has `mpxchan()`, `mx2.c` has `mxopen`/`mxread`/`mxwrite`/`mxioctl`).

23. **`ompx/sys/mx1.c:360-364` has broken indentation that misreads as a bug.**
    `if((gfp->f_flag&FMP)==FMP)cp = addch(gip, 0);` followed by an *unindented* `if(cp ==
    NULL){` — the second `if` is **not** inside the first. The `NULL` check runs
    unconditionally, which is the intent, but the layout invites "fixing" it into a nested
    block that would fall through with `cp` uninitialised.

24. **`ompx/mpx.c:20` and `4.2bsd/mpx.c:30` bake a constant that must match the
    terminal.** `#define NLAYERS 8	/* Same as in jerq itself */` — and the terminal side's
    `NPROC` (used throughout `mux/term/control.c`, `comm.c`, `task.c`) comes from
    `jerqproc.h`. Two component lists that will disagree.

25. **`ompx/sys/4.2bsd/mpx.c:31` caps file descriptors at 16 and uses the fd number as the
    layer index.** `#define NSELFD 16`, `struct layer layer[NSELFD]`, `enabled |= 1<<i` —
    the `select` mask is an `int` bitmask over fds, so this host program cannot serve more
    than 16 descriptors and the layer array is indexed by fd, not by layer number. The
    4.1BSD `ompx/mpx.c` indexes by `map()`ped mpx channel instead. The two `mpx.c` files
    are not interchangeable despite the shared name.

26. **`boot.c:30` is a no-op typo in an error path.** `if(argv==0) address==0;` — `==`
    where `=` was meant, so a failed `Ualloc` leaves `address` uninitialised and the
    download loop at `:40-47` writes through it.

27. **`comm.c:32` documents its own magic number as wrong.** `ticks=60;	/* really HZ */`
    — the constant is hardcoded rather than taken from a header.

28. **`pads/host/Makefile:9,12` compile with `\`pwd\`/$*.c`.** Absolute source paths are
    baked into the objects (and into cfront's generated `.c` intermediates), so the build
    is not relocatable and `-I..` is resolved relative to the *makefile's* directory while
    the source path is absolute. This is the C++ analogue of the in-tree-build constraint.

29. **`pads/host/libC.c` supplies the C++ runtime by hand.** It defines `operator new`,
    `operator delete`, `_vec_new`, `_vec_delete` and **`void _main() {}`** (`:123`) — i.e.
    the package replaces cfront's own runtime support. Linking it alongside a real
    `libC.a` will collide on all five symbols. It is also the one `host/` file with no
    `#include` of `pads.pri`/`pads.pub`, so it does not depend on step 1 of the build.

30. **`pads/host/term.c:45` closes fd 2 during initialisation.** `close(2);` at the end of
    `PadsInit` — after which every `perror`/`fprintf(stderr, …)` in the package
    (`popen.c`, `stats.c`, `test.c`) writes to a closed descriptor. Debugging this
    package by adding stderr output does not work.

31. **`pads/host/test.c` is a test program that the library archive must not absorb.**
    `host/Makefile:1-2` correctly leaves `test.o` out of `OFILES`; the only rule that uses
    it is `a.out: test.o libpads.a` (`:21-22`), built with plain `cc` (not `CC`). It has
    its own `main()` (`test.c:152`), so archiving it would break every link.

32. **`ompx/pconvs.adb` is an `adb` script, not source.** Five lines of `adb` format
    directives (`./"pkt0 "68b` …). It is in `ompx/files` (line 5) as if it were a build
    input; it is a debugger macro and contributes nothing to a build.
