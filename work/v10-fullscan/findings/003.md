## documented build steps

### `demo/src/pacman/`
- `CC = mcc -g` (makefile:2) — the compiler variable **carries `-g`**; `CFLAGS` is empty
  and `DFLAGS = -DBLIT` is a separate variable, applied only by the `.c.o` rule
  (`$(CC) -c $(CFLAGS) $(DFLAGS) $*.c`, line 19).
- Sources built: `blt.c board.c blitfonts.c fruit.c host.c main.c monsters.c pacman.c
  prf.c sched.c sounds.c` (line 7). `bits2blit.c`, `fonts.c`, `oblt.c` and
  `fontaddr.c68` are **not** in `CFILES`.
- Two-stage font generation, and the first stage runs on the **host**, not the jerq:
  `bits2blit: fonts.c bits2blit.c` → `cc -o bits2blit -DBLIT bits2blit.c fonts.c`
  (line 16, plain `cc`), then `blitfonts.c: bits2blit` → `-bits2blit >blitfonts.c`
  (line 13). `-DBLIT` on line 16 is mandatory: `fonts.c` wraps *every* array element in
  `#if BLIT` (fonts.c:7,19,31,… and 118,142,166,…), so without it `chr24[]` and
  `chr40[]` are empty and `bits2blit` emits zeroed bitmaps.
- Other targets: `strip` (`mstrip pacman`), `shrink` (`rm -f *.o`), `clean`,
  `lint: lint -pc $(CFILES)` (line 36), `list: oprl -x makefile … ; oprl -x -C …` (39-40).
- Tools beyond cc/as/ld: **`mcc`**, **`mstrip`**, **`lint`**, **`oprl`**.
- `pacman.h` demands exactly one machine be selected: `SCtoMEM` is defined only under
  `#if BLIT` (242-244), `#if V1_25` (245-247) or `#if V1_76 | V2_0` (248-250), and
  `#if BLIT #include <jerq.h>` at 17-19.

### `demo/src/pacman/fonts/`
- `all: mkfont24 mkfont40 rot fonts rl` (makefile:7). `mkfont24`, `mkfont40`, `rot`, `rl`
  are host programs built with plain `cc` (lines 9-19); `rl.c:6` repeats the recipe in a
  comment: `* compile with: cc rl.c -o rl`.
- The font array source is generated: `fonts: $(FONTS) mkfont24 mkfont40 mk_fonts` →
  `mk_fonts > ../fonts.c68` (25-26).
- `mk_fonts` (a `:`-shell script) greps the constants out of the header and then loops:
  `egrep '#define[ \t]*FONTSIZE|…' ../pacman.h` (line 6), `mkfont24 -b font24_$i` for
  `a b c d e f g h i` (13), `mkfont40 -b font40_$i` for `a b c d e f g h i j k l m n o p
  q r s t u v w x` (22,27), wrapping each in `#if BLIT` / `#endif` (12,14,26,28). Its own
  comment records why: `# relies on the fact the -DV2_0 defines V2_0 to 1` (line 4).
- Derived font pictures: `mk_corners` makes `font24_c/e/f` from `font24_d` with
  `awk`+`rev`+`rl`; `mk_faces` makes `font40_e..m` from `font40_b/c/d` with
  `awk`+`rev`+`rot`. Both master files are hand-drawn.
- `.c68` suffix rules (41-66) are the BitGraph path and are elaborate: hard-link `.c68`
  to `.c`, `$(CC68) -DV2_0 -S`, then **`sed -e 's/\\"/\\042/g' -e 's/\\\\/\\134/g'`** the
  assembler output through `/tmp` before `as68 -o $*.o20 $*.s`. Three variants:
  `.o20` (`-DV2_0`), `.o125` (`-DV1_25`), `.O125` (`-O -DV1_25`).
- Tools beyond cc/as/ld: **`cc68`**, **`ld68`**, **`as68`**, **`awk`**, **`rev`**, **`sed`**,
  plus the locally built `rl`, `rot`, `mkfont24`, `mkfont40`.

### `demo/stand-alone/` (runtime, not a build)
- `demo` is the launcher, not a makefile. It dispatches per demo name to **`68ld`**
  (download-and-run) or **`jx`**, and prints how to exit each one: `68ld $1` for
  `smiley|ack|bounce|munch|moire|one|asteroids` (line 10), `jx spheres` (16),
  `jx $1` for `mazewar|toroids` (22) and `elevator` (26), `68ld $1` for `fake|win|fly|life`
  (13), `*ball` (19) and `alphabet` (25).
- Tools: **`68ld`**, **`jx`**, `egrep`, `pr`, `ls`, `sleep`.

### `diag/`
- Suffix rules are jerq-only: `.c.o: mcc -m -c $<` and `.c.s: mcc -S $<` (Makefile:1-5).
  The `-m` flag is specific to this directory.
- `diag: diag.o` → `mcc -o diag -b 256 diag.o -lj` (10-11) — **load base 256**, library `-lj`.
- ROM path is a three-step chain and must run in order:
  `romdiag: diag.s` → `sed -f makerom.sed < diag.s > romdiag.s ; mcc -c romdiag.s ;
  mld -o romdiag -b 262144 romdiag.o -lj /usr/jerq/lib/libc.a` (16-19) — **load base
  262144**, i.e. 256K, not 256;
  `bits: romdiag` → `strip romdiag ; dd if=romdiag of=bits bs=32 skip=1 count=256` (21-23)
  — exactly 8 KB, skipping the 32-byte a.out header;
  `prom: bits` → push to `r70` and run `dobits` there (25-28).
- `makerom.sed` is the whole ROM transformation, and it is two edits: prepend a reset
  vector, and turn the compiler's call into the entry label —
  `1i\` / `	long	0\` / `	long	START` and `/jsr	START/c\` / `START:`.
  This is why `diag.c:36` calls `STARTOFMAIN();` and defines it empty at 348-350 with the
  comment `/* Used by the code generator */`.
- `loop: loop.c` → `cc -o loop loop.c` (7-8) — the only host-compiled target here.
- Tools beyond cc/as/ld: **`mcc`**, **`mld`**, **`sed`**, **`dd`**, **`strip`**,
  **`push`**, **`r70`**, **`dobits`**, **`fortune`**.

## contradictions and traps

1. **`/usr/jerq` vs `/usr/blit` for the same binary.** `smiley/makefile:8` installs to
   `/usr/jerq/demo/stand-alone`, but `demo/stand-alone/demo:2` sets
   `JPATH=/usr/blit/demo/stand-alone` and line 6 lists that directory as the catalogue of
   available demos — and `smiley` is named in its dispatch table (line 8). The build puts
   the file in one tree; the launcher looks in the other. Nothing in this chunk reconciles
   them, and the source tree itself is rooted at `/usr/blit`.
2. **The smiley link line never produces a file called `smiley`.**
   `smiley/makefile:6` is `$(CC) $(CFLAGS) -o $(OBJ)`, which expands to
   `-o smiley.o smileyf.o explode.o` — `smiley.o` is consumed as the **output** name and
   the target `smiley` is never created, yet `install` (line 8) copies `smiley`. Running
   `make` here also destroys `smiley.o`.
3. **`fonts/makefile:26` writes a filename that no longer exists.**
   `mk_fonts > ../fonts.c68`, but the file in the tree is `../fonts.c` and
   `pacman/makefile:7` lists `fonts.c`. The whole pacman directory was renamed out of
   `.c68` (every header comment still says so: `blt.c:5` `File: blt.c68`,
   `board.c:5` `board.c68`, `main.c:5` `main.c68`, `monsters.c:5` `monsters.c68`,
   `pacman.c:5` `pacman.c68`, `sched.c:5` `sched.c68`, `fruit.c:5` `fruit.c68`,
   `host.c:5` `hostscore.c68`) and this makefile did not follow. Regenerating fonts writes
   a file the build then ignores.
4. **`FONTS` covers a seventh of the inputs.** `fonts/makefile:23` is
   `FONTS=font24_a font24_b font24_c font24_d font24_e font24_f font24_g` — but `mk_fonts`
   reads `font24_a..i` *and* `font40_a..x`. `font24_h`, `font24_i` and all 24 `font40_*`
   are not dependencies of the `fonts` target, so editing a pacman/monster picture does not
   trigger a regenerate.
5. **`mk_faces` is never invoked by any makefile.** It is the generator for
   `font40_e f g h i j k l m` (from `font40_b c d`), yet no rule mentions it —
   only `mk_corners` has a rule (28-31). Those nine files are therefore checked-in
   derivatives with no live dependency.
6. **`all:` orders `fonts` before `rl`, and `mk_corners` needs `rl`.**
   `fonts/makefile:7` is `all: mkfont24 mkfont40 rot fonts rl`; `mk_corners:5-6` pipe
   through `rl`. `rot` was placed before `fonts` for exactly this reason and `rl` was not.
   Building `all` from scratch can run `mk_corners` before `rl` exists.
7. **`-DBLIT` is not optional, and the makefile only passes it in two places.**
   `fonts.c` guards every initialiser with `#if BLIT`; `pacman/makefile:16` passes
   `-DBLIT` to the host `cc` and `DFLAGS` passes it to `mcc`. Any other invocation
   compiles `chr24[][72]`/`chr40[][200]` as empty arrays — which compiles clean and
   produces a blank game.
8. **`blitfonts.c` is generated with errors ignored, and it is committed.**
   `pacman/makefile:13` is `	-bits2blit >blitfonts.c`: the leading `-` means a failing
   `bits2blit` still leaves a truncated or empty `blitfonts.c` and `make` carries on to
   compile it. The committed file (822 lines) is the only good copy.
9. **`blt.c` and `oblt.c` define the same two globals.** Both provide `blt24()` and
   `blt40()`; only `blt.c` is in `CFILES`. `oblt.c` is the pre-BLIT version — its `#ifdef
   BLIT` arm still pokes video memory via `SCtoMEM(row+22,col+5)` (oblt.c:44) where
   `blt.c:67,126` call `bitblt(&Bitmap24,…)`/`bitblt(&Bitmap40,…)`. Adding `oblt.c` to the
   build collides at link time; the two also disagree about the screen origin.
   `oblt.c:93-116` additionally has `REPLACE` and `PAINT` commented out, so it implements
   only `INVERT` for 40-bit fonts.
10. **`fontaddr.c68` is an orphan.** It is the only file in `pacman/` that kept the `.c68`
    suffix, it is in neither `CFILES` nor `HFILES`, and `pacman/makefile` has no `.c68`
    suffix rule at all (only `fonts/makefile` does). It is a BitGraph font-address probe
    (`printf("Font %d at %x\r\n",i,save);`, line 20) for a machine this directory no
    longer targets.
11. **`diag/Makefile` builds a target with no source.** Lines 13-14 are `foo: foo.o` /
    `mld -o foo -b 256 /usr/jerq/lib/l.o foo.o -lsys -lj /usr/jerq/lib/libc.a`. There is no
    `foo.c` in the directory. It survives as the only record of the full explicit link
    line (`l.o` first, `-lsys`, `libc.a` by absolute path) — the `diag` target at line 11
    uses `mcc -lj` and gets none of that.
12. **`diag/Makefile` has no `install` target.** The only deployment is `prom:`, which
    pushes to another machine and burns silicon. Nothing in `diag/` installs into a
    filesystem, so `diag` and `loop` are build-directory-only binaries.
13. **`diag.s` and `romdiag.s` are checked-in compiler/sed output.** `romdiag.s` is
    byte-for-byte `diag.s` with `makerom.sed` applied (`long 0` / `long START` prepended,
    `jsr STARTOFM` at diag.s:17 replaced by the `START:` label at romdiag.s:19); `diag.s`
    is itself `mcc -S` output. Rebuilding either needs `mcc`, so on a machine without it
    the committed copies are the artefact — and `make romdiag` will overwrite `romdiag.s`
    from `diag.s` without warning.
14. **Two different load bases for the same program.** `diag` links at `-b 256`
    (Makefile:11) and `romdiag` at `-b 262144` (line 19), while `diag.c` hardcodes the
    frame buffer at `0x6000` (lines 9,12,16,21,39,44) and sets the stack to
    `256*1024-4` (line 93). The RAM-resident and ROM-resident builds are not
    interchangeable.
15. **`diag.1` is named as a man page but is not roff.** No `.TH`, no macro of any kind —
    it is 32 lines of numbered prose ("1)  Munching squares (continuous run)."). Filing it
    into `/usr/man/man1` would install something `nroff -man` cannot format.
16. **`diag.1` and `manual` disagree about the test sequence, and both disagree with
    `diag.c`.** `diag.1` lists seven numbered tests; `manual:27-29` describes a phase
    neither of the others has — "Next, 10 horizontal lines are drawn, again using byte
    write." `diag.c` implements only `stripe()` (long, line 8-11) and `bstripe()` (byte,
    15-18), both vertical, and `autotest()` (115-141) runs five phases
    (keyboard, int-keyboard, mouse, int-mouse, bounce1). `diag.1`'s item 4 ("Rings the
    bell and counts to 127 using the keyboard lights") is the `putkbd` loop at
    diag.c:120-124, not a separately terminated test. Take `diag.c` as the authority.
17. **The demo launcher has an unreachable arm.** `demo:27` is the catch-all `*)`, and
    `ball)` follows it at line 31 — dead code. `*ball)` at line 17 already matches `ball`
    anyway, so the two arms disagree about the exit key (`type a character` vs
    `type any character`) and neither of them is the one that runs.
18. **Personal home directories baked into the build.**
    `fonts/makefile:5` `-I/usr/rlb/m68k/bitgraph/bg1.25` (rlb = Bob Brown, the pacman
    author) and `diag/Makefile:26,28` `/usr/rob/jerq/bits`. Neither path can be assumed to
    exist. `fonts/makefile:4` `SYMBOLS125=/usr/lib/m68k/bgsym_1.25` is assigned and then
    used by **no rule in the file** — the `.o125`/`.O125` rules never reference it.
19. **`swar`'s installed binary is not the one `make` produced.** `swar/makefile:7` runs
    `mopt swar` inside the `install` target, mutating the file in place before the copy.
    Nothing records that the optimiser ran, so a subsequent `make` sees `swar` newer than
    `swar.o` and does nothing.
20. **`swar/makefile:1` defines `CC=mcc` and then line 4 hardcodes `mcc`.** The variable
    is only honoured by make's built-in `.c.o` rule, so overriding `CC` changes how
    `swar.o` is compiled but not how `swar` is linked.
21. **`fonts.c`'s first three lines duplicate `pacman.h`.** `mk_fonts:6` greps
    `FONTSIZE`, `BYTESIZE` and `BIGFONT` out of `../pacman.h` and re-emits them, so
    `fonts.c:1-3` is a copy of `pacman.h:29,30,218`. `bits2blit.c:2-3` then hardcodes the
    same dimensions a third time as `chr24[][72]` / `chr40[][200]`, and `bits2blit.c:7-8`
    a fourth time as `N24 10` / `N40 26` with its own warning:
    `/* Make sure that these are even, or else nothing works */`. Four copies of one set
    of constants.
22. **Trailing ruler lines in the font pictures are load-bearing only by accident.**
    `font24_a`, `font24_b`, `font24_g`, `font24_h` and `template` are 25 lines — the 25th
    being the column ruler `123456789012345678901234`. `mkfont24.c:28` reads exactly
    `SIDE` lines with `gets()`, so the ruler is silently dropped. Likewise `font40_r` is
    41 lines with an `x` marker in column 41 of every row and a full row of `x` at line 41,
    and `font40_p` is 79 lines (39 of art, 40 blank) — `mkfont40.c` reads 40 rows and 40
    columns and discards the rest. Any tool that validates these files by shape rather
    than by `mkfont`'s actual read will reject valid inputs.
23. **`mkfont24.c` and `mkfont40.c` are the same file twice.** They differ in exactly two
    lines: `#define SIDE` (24 vs 40) and the line-break modulus at line 67
    (`i%3 == 2` vs `i%2 == 1`). Verified by `diff`.
24. **`font40_w:17` has a stray `e` in the bitmap:**
    `xx xxxxxxe   xxxxxx xxxxxxx   xxxxxxxxxx`. `mkfont40.c:46` tests `!=' '` so the `e`
    sets the bit like an `x` and the picture renders correctly — but it is not the `x` the
    rest of the file uses, and any strict `[ x]`-only validator will flag it.
25. **`font40_o` uses upper-case `X`** where every other 40-bit picture uses lower-case
    `x`. Same non-blank test, same result, different convention.
26. **`pacman/makefile:18` attaches prerequisites to a suffix rule.**
    `.c.o:	$(HFILES)` — intended to make every object depend on
    `host.h pacman.h style.h`, but a suffix rule with prerequisites is not portable and
    older `make` ignores them, so a header edit may not rebuild anything.
27. **`fork.c:11` calls `fprintf` with a format as its first argument:**
    `fprintf("fork: can't open %s\n", buf);` — the `FILE *` is missing. `fork.c` is in no
    makefile in this directory, so it is never compiled and the bug is dormant.
