# chunk 020

Scope: `v10/usr/jerq/sgs/as/` — the AT&T SGS (Software Generation System) COFF
cross-assembler for the WE32000/32100 (BELLMAC-32), hosted on the VAX and targeting the
DMD 5620 "jerq" blit terminal. All 40 files in the chunk were read in full. The directory
also holds `u_Gencode.c`, which falls in the next chunk; it is referenced below only where
it is a fact about a file in this chunk.

tree that V8 and V10 share, with V10 carrying a 1986 debugging session on top.

## documented build steps

- **Two makefiles for one program.** `makefile` is the live one; `oneproc.mk` is the stale
  sibling (see traps). Neither declares `all` — the default target is `as`.
- Link line, identical in both: `$(CC) -o as $(OFILES) -lm`. **`-lm` is required**:
  `float.c:229-236` calls `log()` and defines its own `log2()`, and uses `floor()` and
  `ldexp()`.
- `OFILES` (makefile:10-12), twenty objects:
  `pass0.o parse.o code.o errors.o pass1.o strings.o instab.o gencode.o swagen.o
  expand1.o expand2.o float.o addr1.o addr2.o codeout.o getstab.o pass2.o obj.o
  symlist.o symbols.o`.
- **yacc is a required tool beyond cc/as/ld**, with `YFLAGS = -d` — load-bearing, since
  `parse.h` (the token numbers) is consumed by `instab.c`, `gencode.c` and `swagen.c`.
- **The generated parser is V10's own yacc output.** `parse.c`'s driver, from
  `# ifdef YYDEBUG / # include "y.debug"` (parse.c:840) through `goto yystack;` (2462), is
  byte-identical in structure to `v10/usr/src/cmd/yacc/yaccpar` — the same
  `y.debug`/`yytoknames`/`yystates` debug hooks, which stock System V yaccpar does not have.
  So regenerating `parse.c` with V10's own yacc reproduces this skeleton.
  `parse.c`'s `# line` markers also line up exactly with this `parse.y`
  (`# line 2`, `# line 76` at `%union`, `# line 1388` at the second `%%`), so the committed
  `parse.c` was generated from the committed `parse.y`.
- **`ops.out` is C source, not a build product.** Despite the name it is `#include`d as
  text — `instab.c:6-9`:
  `instr instab[] = {` / `#include "ops.out"` / `0` / `};`. It is declared a dependency
  (`makefile:28  instab.o:	instab.h ops.out symbols.h parse.h systems.h`) and **no rule in
  the directory produces it**. The bare `0` after the include is the table terminator that
  `symbols.c:240` scans for (`for (ip = instab; ip->name[0] != '\0'; ++ip)`).
- Configuration is entirely `-D` flags (makefile:2-8): `-DAR32WR` (target byte/word order),
  `-DFBO`, `-DONEPROC`, `-DNOCALLPCREL`, `-DFLEXNAMES`, `-DABWORMAC`.
  `ONEPROC` is what makes this one binary rather than `as` + `/lib/as1` + `/lib/as2`;
  `FLEXNAMES` swaps the 8-char in-struct symbol name for a `realloc`ed string table
  (`symbols.c:256-279`).
- **Feature switches live in `systems.h`, not the makefile**: `DEBUG 0`, `TRANVEC 0`,
  `DCODGEN 0`, `M4ON 1`, `FLOAT 1`, `MACRO 0`. `FLOAT 1` selects `NINSTRS 394` over `358`
  (`symbols2.h:11-15`), enables `INSTRD` (`instab.h:11-13`), `fdexpval2` in `rexpr`
  (`instab.h:94-96`), the 36 FP rows of `ops.out` (lines 77-112), and all of `float.c`
  (whose body is one `#if FLOAT` from line 5 to 340).
- `MACRO 0` means **m4 is off by default** (`pass0.c:127  static short macro = MACRO;`);
  `-m` toggles it on (`pass0.c:236-238`), which then forks `/usr/bin/m4`.
- Include search is `-I. -I$(INC) -I$(USRINC)`. **`USRINC` is never assigned** in either
  makefile, so one `-I` gets an empty argument.
- Command-line flags the finished assembler accepts (pass0.c `getargs`): `-o file`,
  `-m` (toggle m4), `-dl` (drop line numbers), `-V` (version), `-n` (no optimise),
  `-nf` (no chip-bug workarounds), plus `-R`/`-r`/`-O`/`-TL`/`-tv`/`-j`/`-t<n>` behind
  compile-time switches.

## contradictions and traps

### The directory is a 1986 debugging session, frozen

- Everything is 6 Jul 1984 except `obj.c` (19 Oct 1984) and `oneproc.mk` (3 Jun 1985) —
  and then, in one two-night burst: `gencode.c` 25 Jul 1986 01:38:47, `u_Expand1.c`
  02:36:46, `u_Gencode.c` 02:54:33, `makefile` 03:56:53, then `gendefs.h` 26 Jul 02:23:57,
  `parse.h` 02:25:32, `parse.c` 02:25:53. Reading this as a released distribution misreads
  it.
- **`v10`'s makefile differs from `v8/jerq/sgs/as/makefile` in exactly two settings, and
  both are debugging leftovers:**
  ```
  -CFLAGS	= -O -I. -I$(INC) -I$(USRINC) \        (v8)
  +CFLAGS	= -g -I. -I$(INC) -I$(USRINC) \        (v10)
  -PCCALL	= CALLPCREL                            (v8)
  +PCCALL	= NOCALLPCREL                          (v10)
  ```
  `-O`→`-g` costs optimisation. `CALLPCREL`→`NOCALLPCREL` is **not cosmetic** — it changes
  the emitted target code. `expand2.h:6-28` keys off it: `#ifndef CALLPCREL` gives
  `NITYPES 6`, `#else` gives `NITYPES 8` with the extra `PCBRELCALL`/`PCHRELCALL` span
  types; `gendefs.h:65-70` adds a 27th action routine `CALLNOPT` only `#ifdef CALLPCREL`;
  `addr2.c:227-242` compiles `callnopt()` only then; `expand2.c:20-23,39-42,58-61` add
  three table rows only then; and `gencode.c:786-850`'s whole PC-relative-call
  optimisation in `callgen()` collapses to `#ifndef CALLPCREL / addrgen(insptr,dest,NOTYPE,2);`.
  Building `v10`'s makefile as-is therefore yields a debug assembler that will not shorten
  PC-relative calls. `oneproc.mk` (byte-identical to v8's) still says `CALLPCREL`, so
  **the two makefiles in this one directory now generate different target code.**
- The 1986 session's diagnosis is legible: the two `u_` files comment out exactly the
  PC-relative-call and undefined-symbol span optimisations, and the makefile turns
  `CALLPCREL` off. Only the makefile change is in effect.

### The `u_` files are newer than what gets compiled

- **`u_Expand1.c` is a newer, patched `expand1.c` that the build does not compile.**
  `expand1.c` (1984-07-06) is byte-identical to `v8/jerq/sgs/as/expand1.c`; `u_Expand1.c`
  (1986-07-25) differs in exactly one hunk, in `shortsdi()` at line 310:
  ```
  	if (sym && ((sym->styp & TYPE) == UNDEF)) {
  /*			if (dot->styp != TXT)
  /*				return(L_SDI);
  /*			sditype = U_SDI;
  /*			newsdi(sym,const,itype);
  /*			PCmax += idelta[itype];
  /*			dot->maxval = PCmax;
  */
  			return(L_SDI);
  ```
  — span-dependent optimisation disabled for undefined symbols, always emit the long form.
  `OFILES` names `expand1.o`, so the 1984 file wins and the 1986 repair is dead.
- `u_Gencode.c` (30549 bytes) vs `gencode.c` (30514 bytes) is the same story in `callgen()`:
  `diff` shows one hunk commenting out the byte-PC-relative call path (`generate(8,NOACTION,0xCFL,…)`)
  and its `if (opt) { if (sdi(…, PCBRELCALL) == S_SDI) { … } }` wrapper. `u_Gencode.c` is
  in the next chunk; `gencode.c` here is the one `OFILES` builds.
- **The `u_` prefix is this repository's case-collision rename, not a tape name.** The tape
  names are `Expand1.c` and `Gencode.c` (capital initial), renamed because `expand1.c` and
  `gencode.c` already hold the lowercase spellings. Verified with `git ls-files`, which
  lists all four under both `v10/usr/jerq/sgs/as/` and `v10superset/jerq/sgs/as/`. A grep
  for `expand1.c` will not find `u_Expand1.c`, and on this case-folding filesystem
  `ls Expand1.c` answers for the wrong file.
- The comment style used in both patches (`/*` at the head of every line, no interior
  `*/` until the last) works only because each `/*`-prefixed line either continues the open
  comment or reopens one; `gencode.c:810-826` relies on the same trick and each line's
  trailing `*/` happens to close it. Editing one of those lines silently uncomments code.

### The makefiles

- **`oneproc.mk` never defines `OFILES`.** Its default target is
  `as:	$(OFILES)` with `	$(CC) -o as $(OFILES) -lm` (lines 9-10) and there is no
  `OFILES=` line anywhere in the file — `makefile:10-12` is the only place that list
  exists. Run as-is, `oneproc.mk` links `cc -o as -lm` with no inputs: a default target
  that builds nothing.
- `oneproc.mk:3` passes `-D$(MAC)` but **never assigns `MAC`**, so it compiles with a bare
  `-D`. `makefile:4` has `MAC = ABWORMAC`.
- **`$(LIBDIR)` is never defined in either makefile**, so `$(LIBDIR)/cm4defs` resolves to
  `/cm4defs` — the filesystem root. The rules are also **unreachable**: nothing depends on
  them; not `as`, not `install`, not `clean`, and there is no `all`.
- **The makefile pleads ignorance about a destination the program hardcodes.** `makefile:52`
  is `# I dunno where these go; they aren't documented for the 32000, only the 32100 -rob`,
  while `pass0.c:517` initialises `*regdef = CM4DEFS` and `../inc/paths.h:57` defines
  `CM4DEFS "/lib/cm4defs"`. And `paths.h` is listed as a dependency of `pass0.o`
  (`makefile:21`), so the answer was one file away from the comment.
- **`/usr/jerq/bin/` does not exist anywhere in this tree.** `git ls-files v10/usr/jerq/`
  yields only `demo font icon include mbin sgs src` (plus dotfiles) — no `bin`, no
  `bin/vax`. `mbin/` holds the *terminal-side* `.m` binaries; the VAX-side cross-tools have
  no shipped bin directory here. Both install rules write into directories that must be
  created first, and `oneproc.mk`'s `ln` needs `bin/vax` too.
- **Both `clean` targets delete committed source.** `makefile:60-61`
  `-rm -f $(OFILES) parse.c parse.h y.output core as`; `oneproc.mk:57-59` the same plus
  `lint.out`. In this repository `parse.c` and `parse.h` are tracked files that only yacc
  can regenerate. `clean` removes `y.output` but not the `y.debug` that
  `parse.c:841` names.
- **`-DFBO` is a no-op in this directory.** `FBO` appears in no `.c` or `.h` here (only the
  word `DBO` in a `swagen.c` comment); `../inc/sgs.h:9` is `#define MAGIC FBOMAGIC`
  unconditionally, and `obj.c:113` uses `MAGIC` directly. So `DBO = FBO` selects nothing.
- **`-DNOCALLPCREL` is never tested either.** Every test is `#ifdef CALLPCREL` /
  `#ifndef CALLPCREL`; the flag works only by *not* defining `CALLPCREL`, so any other
  value of `PCCALL` would behave identically.
- **`VAX` is not defined, on the machine this cross-assembler runs on.** `codeout.h:13`,
  `code.c:171`, `codeout.c:106`, `obj.c`, `pass0.c:326`, `symlist.c:251` all have
  `#if VAX` paths, and no `-DVAX` appears in either makefile. `codeout.h:11-22` means the
  `codebuf` intermediate record is the portable layout (`unsigned short caction/cindex/cnbits`)
  and `code.c:174` stores `cindex = sym==NULL ? 0 : 1+(sym-symtab)` — a symtab index, not a
  raw pointer. That is correct for records written to a temp file; the point is that the
  `#if VAX` fast paths, including the `-j`/`ljas` re-exec, are all dead here.

### Same-name / near-name hazards

- **`obj.c` and `obj.oc` are the same size (22878 bytes each) and are NOT the same file.**
  `cmp` says `differ: char 1148, line 49`; separate inodes (166825024 / 166825025). The
  whole difference is one constant:
  ```
  -#define MAXSTK	20        (obj.oc, 1984-07-06, mode 444)
  +#define MAXSTK	50        (obj.c,  1984-10-19, mode 644)
  ```
  — which is why the byte counts match. `.oc` reads as "old c". Only `obj.c` is built;
  `MAXSTK` sizes `stack[MAXSTK]` (obj.c:108), the symbol-scope stack that `push()` guards
  with `if (sttop == MAXSTK - 1) aerror("Symbol Table Stack Overflow");`. Both files are
  byte-identical to their `v8/jerq/sgs/as/` counterparts.
- **`ABWRMAC` and `ABWORMAC` differ by one letter and mean opposite things.**
  `systems.h:16 #if ABWRMAC` sets `M32RSTFIX 1` (the RESTORE chip-bug workaround);
  `systems.h:25 #if ABWORMAC` sets the same list *minus* `M32RSTFIX`. The names read as
  AB-With-Restore-MAC and AB-WithOut-Restore-MAC. `obj.c:259-261` sets the object-header
  flag only for the former:
  ```
  #if ABWRMAC
  	filhead.f_flags |= F_BM32RST;
  #endif
  ```
  The makefile says `MAC = ABWORMAC`, so `M32RSTFIX` is off, `restorefix()` (swagen.c:374-399)
  is not compiled, `-r` is not accepted, and `F_BM32RST` (0010000, `../inc/filehdr.h:55`) is
  not set. That is self-consistent — but `grep ABWORMAC` over the sources returns only
  `makefile` and `systems.h`, so the reader who greps for the makefile's spelling finds
  nothing and concludes the flag is unused.
- **Two `flags()` definitions, in `addr2.c:336` and `swagen.c:402`.** Only `swagen.c`'s is
  unconditional; `addr2.c`'s is `#if !ONEPROC`. Under the makefile's `-DONEPROC` exactly one
  survives — but the two behave differently (`addr2.c` calls `yyerror`, `swagen.c` calls
  `werror` with a formatted message), so a build without `ONEPROC` gets the other one.
- **`swapb2`/`swapb4` (addr2.c:35,46) and `swap_b2`/`swap_b4` (gencode.c:379,390) are four
  functions with identical bodies and near-identical names**, all linked into the same
  binary. An underscore is the only distinction.
- **Two variables named `bitpos`.** `code.c:8  short bitpos = 0;` is the global that
  `parse.y:54` declares extern and `parse.y:1648` (`fillbyte`) reads; `codeout.c:37` has a
  file-`static short bitpos = 0`. Pass 1 and pass 2 each track a bit position under the same
  name in the same program, and only `static` keeps them apart.
- **`errmsg` is both a global function and a local array.** `errors.c:83  errmsg(str1,str2)`
  is called from `pass2.c:590`; `swagen.c:406  char errmsg[28];` shadows it inside
  `flags()`, where `werror(errmsg)` passes the array.
- **`type` is declared as a scalar in one file and defined as an array in another.**
  `parse.y:1396` / `parse.c:210` is `short	type[] = { EOF, … };` while `addr1.c:37-38` has
  `extern short` … `	type,` — a scalar. `addr1.c` never uses it, and a K&R linker does not
  notice.

### Bugs in code the makefile does enable

- **`swagen.c:792` and `:813` emit hex 0x12 (= 18) where the comment and every neighbouring
  constant say 12.** In `er16fix()`:
  ```
     incrstk(12);                                     (line 753)
        /* SUBW3  &12,%sp,c_arg1	*/                (line 784)
        c_arg1->adexpr.expval = -12;                   (line 788)
        generate(8, NOACTION, 0x12L, NULLSYM);         (line 792)
  ```
  and again at 804/808/813 (with `expval = -8` rather than `-12`), then `decrstk(12)` at 837.
  `incrstk`/`decrstk` take decimal 12; the two `generate` calls emit `0x12`. `ER16FIX` **is**
  enabled by `ABWORMAC` (`systems.h:28`), and `parse.y:421-427,448-452` calls `er16fix()`
  for every three-operand mul/div/mod.
- **`parse.y:620-621` tests the same operand twice.**
  ```
  #if	EXPFIX
  			if( ( $4.newtype != NOTYPE ||
  			    $4.newtype != NOTYPE ) && workaround )
  ```
  in the `SPRTOP3 immode COMMA mem COMMA mem` rule (SPOPS2/SPOPD2/SPOPT2) — the second test
  should be `$6`, so the third operand's expand byte is never checked. Reproduced verbatim in
  the generated parser at `parse.c:1572-1573` (`yypvt[-2]` twice). `EXPFIX` is enabled by
  `ABWORMAC` (`systems.h:29`). Compare `parse.y:718-719` (the CALL rule), which correctly
  tests `$2` then `$4`.
- **`return;` inside yacc actions abandons the parse.** `parse.y:585, 589, 598, 602, 617, 628`
  do `yyerror(…); return;` — inside `yyparse()`, so the rest of the input file is silently
  dropped. `pass1.c:446` calls `yyparse();` and ignores its value; the truncation is caught
  only indirectly, because `yyerror` bumped `anyerrs` and `pass1.c:577 if (!anyerrs)` then
  routes to `delexit()`.
- **`parse.y:1396-1414`'s `type[]` has 129 entries and is indexed by any input byte.**
  One `EOF` plus sixteen rows of eight = indices 0..128, i.e. characters −1..127. Every
  lexer read is `type[(c = getc(fdin)) + 1]` (`parse.y:1432, 1435, 1458, 1491, 1514, 1541,
  1607`), so a byte ≥ 128 in the source reads past the end of the array.
- **Two unterminated-input infinite loops.** `parse.y:1594` `while (getc(fdin) != '\n');`
  — a `#` comment on a final line with no newline spins on `getc` returning −1 forever;
  `parse.y:1568` `while ((c = getc(fdin)) != '"')` does the same for an unterminated string
  (and keeps `putc`ing to `fdstring` under `!ONEPROC`).
- **`yylex` reports two errors and then uses the bad pointer anyway.**
  `parse.y:1527-1531` (`case REG`) and `1612-1616` (`case LT`) do
  `if ((istp.itp == NULL) || …) yyerror(…);` and then unconditionally
  `yylval.uuinsptr = istp.itp; return(REGISTER);` — no `return(ERR)`. `case ALPH`
  (1555-1558) does return `ERR`. So an invalid register name or operand specifier hands the
  grammar a null `instr *` that the actions dereference.
- **`float.c` defines `log2()` itself** (line 231-236) while also declaring it `extern`
  (line 17). Harmless against 1984 libm, a redefinition against any libm that has `log2`.
- `float.c:123,133,137` deliberately route `double`→`long` through a `float` temporary
  (`ftmp = floor(dtmp); mantissa = ftmp;`) with the comment `/* takes the place of a cast */`
  — a 24-bit mantissa in the middle of a 52-bit conversion, by design, per the comment at
  lines 29-36.

### Include-path and header hazards

- **Angle-bracket includes for files in the current directory.** `float.c:8`
  `#include <symbols.h>	/* needed for instab.h */` and `instab.c:4-5`
  `#include <instab.h>` / `#include <parse.h>` — all three headers exist only in `.`, not in
  `../inc`. They resolve solely because of `-I.` in `CFLAGS`. Drop `-I.` and those two files
  stop compiling.
- **A quoted include that works only because `-I` is searched for `""` too.**
  `symbols.c:7  #include "syms.h"` for a header in `../inc/`, while `symlist.c:5` writes
  `#include <syms.h>` for the same file — two spellings of one dependency.
- **`symlist.c` names a directory layout this tree does not have.** Lines 63-64 say changes
  must follow `../../inc/common/storclass.h`; `git ls-files` shows only
  `v10/usr/jerq/sgs/inc/storclass.h` and there is no `inc/common/` anywhere under `sgs/`.
  The makefile agrees with the tree (`$(INC)/storclass.h`, `INC = ../inc`); the comment
  preserves the original AT&T SGS layout.
- **A makefile dependency the source does not have.** `makefile:46`
  `symlist.o:	symbols.h $(INC)/syms.h $(INC)/storclass.h gendefs.h systems.h` — but
  `symlist.c` never includes `storclass.h`. `C_EXT`, `C_STAT`, `C_ENTAG` arrive transitively
  because `../inc/syms.h:6` is `#include "storclass.h"`. Correct by luck, not declaration.
- **`parse.h` has an ordering requirement no makefile states.** It declares
  `typedef union { long uulong; rexpr uuexpr; symbol *uusymptr; instr *uuinsptr;
  addrmode uumode; char *uustrptr; } YYSTYPE;` — so `symbols.h` (for `symbol`, `instr`) and
  `instab.h` (for `rexpr`, `addrmode`) must be included first. `instab.c`, `gencode.c` and
  `swagen.c` all get the order right; nothing enforces it.
- **`INTEXPFIX` is dead code calling identifiers that do not exist.** `parse.y:500-502`
  `#if INTEXPFIX / expandc($1, &($2), destmem);`, carried into `parse.c:1436-1437`. A
  `grep -rn 'INTEXPFIX\|expandc\|destmem'` over `as/` and `../inc/` finds exactly those four
  lines: no definition of the macro, the function, or the variable anywhere.

### Table / counter mismatches

- **`NINSTRS` undercounts `ops.out` by eight, both ways, and the hash table pays for it.**
  `symbols2.h:6` claims `NINSTRS	= number of legal assembler instructions (from ops.out)`,
  and sets `394` with `FLOAT`, `358` without. `ops.out` actually holds **402** entries
  (366 outside `#if FLOAT` plus 36 inside). `symbols2.h:23` then derives
  `#define	NSYMS	(NHASH - NINSTRS)` = 4999 − 394 = 4605, and `symbols.c:64-67` sizes
  `symtab[NSYMS]` and `hashtab[NHASH]`. Worst case the hash table must hold 402 mnemonics
  plus 4605 user symbols = 5007 entries in 4999 slots, so `lookup()` can cycle back to its
  start and hit `aerror("Hash table overflow")` (symbols.c:206-207) *before*
  `newent()`'s `aerror("Symbol table overflow")` (symbols.c:87-89) ever fires. `ops.out` and
  `symbols2.h` carry the same date (`1.8 12/10/83` and `1.3 12/10/83`), so neither is
  "newer"; and both files are byte-identical to `v8/jerq/sgs/as/`, so the mismatch is
  upstream, not introduced here.
- **`TRIOP3` is a declared token with no production.** `parse.y:89` declares
  `%token <uuinsptr> TRIOP1 TRIOP2 TRIOP3`; `parse.c:102` assigns it 273; no grammar rule
  uses it and no `ops.out` row names it. The generated `yyexca[]` proves it — `parse.c:506-508`
  runs `271, 7,` / `272, 7,` / `274, 7,`, skipping 273 entirely.
- **Two `ops.out` opcodes are missing the `L` suffix every other row carries.**
  `ops.out:99  {"movdh",	INSTRD,		FPDYAOP1-256,	8,	0xb5},` and
  `:100  {"movtdh", … 0xc5},` — assigned into `long opcode` (`symbols.h:45`), so an implicit
  int→long conversion where all 400 siblings are explicit.
- **`gendefs.h:16-20` documents an edit that must be made in two places, one of them a
  comment.**
  ```
  #define OUTWTYPE	char
  /* if the previous line changes the following line should be change to look like
   * #define	OUT(a,b)	fwrite((char *)(&a), sizeof(OUTWTYPE), 1, b)
  */
  #define	OUT(a,b)	putc((a), b)
  ```
  Widening `OUTWTYPE` silently keeps writing one byte, because the replacement `OUT` exists
  only as prose.
- **`errors.c`'s temp-file cleanup is bounded by a constant the array outgrows.**
  `errors.c:47  char	*filenames[16];` but `errors.c:120` is
  `for (i = 2; i < NFILES; ++i) unlink(filenames[i]);` with `gendefs.h:34 #define NFILES	9`.
  Under `MULTSECT` (`pass0.c:419-425`, `code.c:235-281`) indices 9-14 are also temp files and
  would be left behind. `MULTSECT` is not defined by either makefile.
- **`pass0.c:51`'s flag budget is written as arithmetic on two undocumented sizes.**
  `#define	MAXFLAGS	15 - 9	/* sizeof(xargp)-num of args required for pass1 */`
  — six flags. `xargp` is `static char *xargp[16]` (pass0.c:119) and `NFILES` is 9, so the
  comment's two numbers are 16 and 9 but the expression uses 15 and 9. `#if !ONEPROC` only.

### Dead files and dormant code

- **`symbols1.c` and `symbols2.c` compile `symbols.c` as if it were a header, and neither is
  built.** `symbols1.c` is `#define PASS1 1` then `#include "symbols.c"`; `symbols2.c` is
  `#undef PASS1` then `#include "symbols.c"`. They exist to produce two differently
  configured objects for the `/lib/as1` + `/lib/as2` layout. `OFILES` names `symbols.o` —
  `symbols.c` compiled *directly*, with `PASS1` undefined — so the `#if PASS1 || ONEPROC`
  guards carry it and both wrappers are dead.
- **The doc comments describe a three-process program that this build is not.**
  `pass1.c:16` `		as1 [flags] ifile ofile t1 t2 t3 t4 t5 t6 t7` and `pass2.c:18`
  `		as2 [flags] ifile ofile t1 t2 t3 t4 t5 t6 t7`, plus pass2.c's 120-line account of
  which temp file holds what at each stage (lines 360-507). Under `-DONEPROC` `main()` becomes
  `aspass1()` (pass1.c:376-380) and `aspass2()` (pass2.c:512-516) and none of the exec'ing
  happens — the prose is the only place the file layout is written down, and it describes the
  other build.
- **Behaviour depends on the name the program is invoked as, twice, and both are compiled
  out.** (a) `pass0.c:326-333`, `#if VAX`: `-j` does
  `if (strcmp(xargv[0],"ljas")) { execvp("ljas",xargv); aerror("cannot exec ljas"); };`
  — re-exec a different assembler by PATH. (b) `pass0.c:380-385` and `pass1.c:402,581`,
  `#if !ONEPROC`: the next pass's name is derived from `argv[0]` by appending `'1'` then
  substituting `'2'`, so a multi-process build renamed at install time (to `3as`, say) looks
  for `3as1`/`3as2`, not `/lib/as1`.
- **`pass0.h:14 #define TEMPLATE	"/m32as?XXXXX"` is never used.** `pass0.c`'s `tempnam()`
  builds its own `seed` + `"XXXXXX"` pattern (lines 187-193). A stale constant that looks like
  the answer to "how are the temp files named".
- **`addr1.c:99 setmagic()` is in no dispatch table.** `addr2.c:302-333` builds
  `int (*(modes[NACTION+2]))()` from 27 named routines; `setmagic` is not among them and no
  file in the directory calls it.
- **`addr1.c:106 setfile(sym,code)` takes `upsymins sym` — a union — by value**, while
  `codeout.c:114` dispatches every action as `(*(modes[code.caction]))(sym,&code)` with `sym`
  a `symbol *`. It works because `upsymins` is a union of two pointers on a VAX.
- `addr2.c:329` puts a routine named `inline` at slot 26 of `modes[]`, where
  `gendefs.h:64` names that slot `SETEXPAND`. Fine for 1984 C; `inline` is a keyword now.
- Dormant portability branches with no `-D` behind them: `MULTSECT` (code.c, pass0.c,
  pass1.c), `MC68` (obj.c:544, pass2.c:612), `B16` (obj.c:15,521), `pdp11` (symbols2.h:17),
  `AR16WR`/`AR32W` (obj.c:247,253), `DCODGEN` and `TRANVEC` and `DEBUG` (all zeroed in
  `systems.h`), `NODEFS` (pass0.c:515), and `#if 0` blocks at `swagen.c:144-324`
  (`trimulcheck`, with the reason given: `/*	The following routine is ifdef'ed out because
  it is not * needed in DBO Mask 2 chips. */`), `gencode.c:880-883` (the optimised `cmpw`,
  disabled `/* DONT generate optimized "cmpw" because of Interrupt * After TSTW Chip Bug. */`),
  and the `#if 0	/* trimul software workaround */` brace pairs at
  `parse.y:413/420/437/439` and `443/447/461/463`.
- **`pswcheck()` is the one chip-fix routine with no `#ifdef CHIPFIX` guard.**

### Committed build products

- **`parse.c` and `parse.h` are committed build products, and here they are the real
  inputs.** `v8/jerq/sgs/as/` ships neither — `git ls-files v8/jerq/sgs/as/` has `parse.y`
  and no `parse.c`/`parse.h`. In `v10` both are present and dated 1986-07-26, i.e. **newer
  than `parse.y` (1984-07-06)**, so `make` will not re-run yacc and the committed generated
  files are what gets compiled. They were regenerated two minutes after `gendefs.h` was
  edited (02:23:57 → 02:25:32 → 02:25:53), so they encode the 1986 `gendefs.h`.
- The sibling `v10/usr/jerq/sgs/comp/` keeps its yacc output under the default name
  `y.tab.c` instead of renaming it; `as/` renames to `parse.c`. Two conventions in one tree.
- `YYMAXDEPTH` is left at yacc's default `150` (`parse.c:195-197`), sizing both
  `YYSTYPE yyv[150]` (line 854) and `short yys[150]` (line 860); `YYSTYPE` contains an
  `addrmode`, so the two parser stacks are not small.
