# chunk 007

Scope: `v10/usr/blit/src/` — the DMD/Blit terminal userland. 85 files, all read in full,
all text (no binaries in the list). Six packages: the top-level `.m`/host programs,
`4pi/`, `68ld/`, `Jpic/`, `blitblt/`, `cip/`, `font/`.

The single most important structural fact: **this chunk installs into `/usr/blit/*`, but
its oldest makefile still installs into `/usr/jerq/*`.** Both `v10/usr/blit/` and
`v10/usr/jerq/` exist in the distribution, so the prefix is not a typo — but
`v10/usr/jerq/lib` and `v10/usr/jerq/bin` **do not exist** (jerq has only
`src/ icon/ font/ sgs/ demo/ mbin/ include/`), while `/usr/blit/` has
`bin/ lib/ mbin/ font/ include/ m/`. See contradictions C1.

## documented build steps

**`v10/usr/blit/src/` (top level) — `makefile.5`**
Two toolchains in one makefile: `$(MCC)` (= `/usr/jerq/bin/mcc`) for the 68k targets
`crabs hp version vitty`, and `$(CC)` for the host targets `ismpx jermcap jterm jwin`.
`all: $(TARGETS)`, then a separate `install:`. Every rule is phony (no dependencies on
sources), so `make` always recompiles and never notices a missing source. Filename is
`makefile.5`, not `makefile` — `make` will not find it without `-f`.
`CFILES=crabs.c hp.c ismpx5.c jermcap.c jterm.c jwin.c version.c vitty.c` — but
`ismpx5.c` **is not in the directory** (see C4). Nine other programs in the same
directory (`emux.c icon.c iconcatg.c icontxtr.c m33.c magnet.c mopt.c pen.c scope.c`)
have no rule at all, though `m33.m`, `icon.m`, `pen.m` and `scope.m` are in the installed
`/usr/blit/mbin`.

**`4pi/`** — no build. One README, whose entire content is an instruction *not* to build
this package: use jerq's `pi` instead, and `3pi` is meaningless.

**`68ld/`** — `68ld: 68ld.o proto.o pcheck.o`, linked with `$(CC) $(LFLAGS)`.
Requires `-I/usr/blit/include` (`68ld.c` includes `"a.out.h"` and `<jioctl.h>`, neither
of which is in the directory). `pcheck.c` is conditionally compiled three ways —
`#ifdef vax` uses the VAX **`crc` machine instruction** via `asm()`, `#ifdef mc68000`
substitutes hand-written 68k `asm()`, and the plain path is portable C; `68ld.c:11-22`
similarly needs one of `pdp11`/`vax`/`u3b` defined to set `swapb`/`swapw`. Tools beyond
cc/as/ld: `lint`, `pr`, `pp`, `dcan`, `cpio`, `/bin/rm`. `print:` and `cpio:` read a
manifest named `files` that is not in the directory.

**`Jpic/`** — needs **yacc with `YFLAGS = -d`** (to emit `y.tab.h`) and **lex**
(`picl.l`), plus `-lm`. Default target is `a.out`:
`cc -o a.out picy.o picl.o $(OFILES) -lm`. `$(OFILES): pic.h` is the only header
dependency; every `.c` also includes `"y.tab.h"`. Separate targets build the 68k side
(`jp`, `x`) with `/usr/m/bin/mcc` + `/usr/m/bin/mld` and `-lj`, and `epic` with plain
`cc`. `memo:` needs `refer`, `pic`, `eqn`, `troff -ms`. `grapic:` needs `-lplot -lm`.
`Export` is a distribution script, not a build step: `for i in picy.y picl.l pic.h *.c
makefile / do (echo Jpic file $i: ; echo; cat $i) | Mail $1` — it **mails** the sources
to `$1`.

**`blitblt/`** — three independent products, three compilers:
`blitblt` is host-side and needs the Datakit library — `cc blitblt.c -ldk -o blitblt`;
`bbterm.m` is the 68k image — `mcc $(BBOBJ) -o bbterm.m` over
`bbterm.o sendbitmap.o sendch.o buttons.o kbdstring.o mice.o`; `bcan.out` and `bdump`
are plain `cc`. `bcan.out` shells out to **`ipr`** at runtime (`bcan.c:70`). There is no
`install` target — the README's destinations are prose only.

**`cip/`** — 68k only: `CC=mcc`, `CFLAGS=-j`, `mcc -j -o cip $(OBJ)`; `$(OBJ): cip.h`.
`install:` copies to `/usr/blit/lib/cip.j`. `lint` target passes `-bu … -lj`. `print:`
pipes to `alice lp0` — a named remote machine.

**`font/`** — `all: mtod dtoc showbits view finv`, each `mcc $(CFLAGS) -o <t> <t>.c`
with `CFLAGS=-g`. These are 68k programs that run **on the terminal**, so each carries
its own invocation in a comment, all via **`jx`**: `usage: jx dtoc < fontfile > junk.c`
(`dtoc.c:4`), `usage: jx finv < font > invfont` (`finv.c:4`), `usage: jx mtod > file`
(`mtod.c:4`), `usage:	jx showbits < bytes` (`showbits.c:4`). No `install` target;
the only statement of where fonts live is in the *consumer*, `cip/things.c:315`
(`/usr/blit/font/`).

## contradictions and traps

**C1. `makefile.5` installs into a prefix that does not exist.** Its `LIB=/usr/jerq/lib`
and `BIN=/usr/jerq/bin` are the only `/usr/jerq/{lib,bin}` references in the chunk, and
neither directory exists in `v10/usr/jerq/` (which has only
`src icon font sgs demo mbin include`). The installed distribution puts exactly these
artefacts elsewhere: `crabs.m hp.m vitty.m` are in `/usr/blit/mbin/`, and
`jterm jwin ismpx` are in `/usr/blit/bin/`. Every sibling package in this chunk
(`68ld/`, `cip/`) installs under `/usr/blit`. `makefile.5` is the stale one.

**C2. `blitblt/README` and `blitblt.c` disagree about `bbterm.m`, in the same package.**
README:15 — `bbterm.m	lives in /usr/jerq/mbin`. `blitblt.c:11` — the path compiled into
the program that downloads it — `char *jpgm = { "/usr/blit/mbin/bbterm.m" };`. The
installed tree has it at `/usr/blit/mbin/bbterm.m`, so the README is wrong. README:13
likewise puts `blitblt` in `/usr/jerq/bin` while the installed copy is
`/usr/blit/bin/blitblt`. Note `blitblt.c:94` gets `/usr/blit/bin/68ld` right — the same
file is authoritative for one path and its README wrong for another.

**C3. `Jpic` is not `pic`, but its makefile installs it as `pic`.**
`Jpic/pltroff.c:1-3` is `/* jerq driver */` and emits jerq drawing commands (`m`, `c`,
`~`, `t`, `E`), not troff; `pltroff.c:37` is `#define JERQRES 100` and `openpl()` forces
`res = JERQRES`. Yet `Jpic/makefile:35-36` is `cp pic /usr/bin` + `strip /usr/bin/pic`
and `:32` is `cp makefile pic*.[ylch] pltroff.c driver.c /usr/src/cmd/pic` — running
either target overwrites the *system* pic binary and the system pic sources with the
jerq-only variant. The real destination is stated by the consumer:
`cip/commands.c:92` runs `/usr/blit/bin/Jpic`, and `Jpic` is present in the installed
`/usr/blit/bin/`. Compounding it, the default target produces **`a.out`**, not `pic`, so
`make bin` copies a file no rule builds.

**C4. `makefile.5` requires a source file that is absent.** `CFILES` and `TARGETS` both
name `ismpx`/`ismpx5.c`, and there is an `ismpx:` rule (`$(CC) -o ismpx ismpx5.c`), but
`git ls-files v10/usr/blit/src` shows no `ismpx5.c` and no other ismpx source. `all:`
would fail on it. (`ismpx` *is* present as an installed binary in `/usr/blit/bin`.)

**C5. Three different 68k toolchain prefixes for the same job.** `makefile.5:4` uses
`/usr/jerq/bin/mcc`; `Jpic/makefile:46-51` uses `/usr/m/bin/mcc` and `/usr/m/bin/mld`
with `/usr/m/lib/libc.a`; `blitblt/Makefile`, `cip/makefile` and `font/Makefile` invoke
bare `mcc`, and `68ld.c:428` and `blitblt.c:94` use `/usr/blit/bin/{mld,68ld}`.
`/usr/blit/bin/` holds `mcc mld mopt mnm msize mstrip mlorder`, and there is a
`/usr/blit/m/` tree. `/usr/m` appears nowhere in the distribution.

**C6. `Jpic/epic.c` hardcodes a personal directory.** `epic.c:30-31` run
`/usr/bwk/pic/jp` and `/usr/bwk/pic/pic` — bwk's home, not an install path, and
inconsistent with both `/usr/bin/pic` (its own makefile) and `/usr/blit/bin/Jpic` (its
consumer). `epic` is built by `Jpic/makefile:53-54` but installed by nothing.

**C7. `Jpic/pic1.c` is a stale whole-program copy that must not be compiled.** It is
absent from both `OFILES` and `CFILES`, and it duplicates `main()`, `setdefaults()`,
`getdata()`, `reset()`, `print()`, `dotline()`, `dotbox()`, `dotext()`, `boxgen()`,
`circgen()`, `arcgen()`, `linegen()`, `splinegen()`, `movegen()`, `textgen()`,
`savetext()`, `troffgen()`, `makeattr()`, `setdir()`, `getcomp()`, `printexpr()`,
`tostring()`, `makevar()`, `lookup()`, `makepos()`, `getpos()`, `gethere()`,
`getlast()`, `getfirst()`, `fixpos()`, `makenode()` and `extreme()` — every one of which
also exists in `main.c`, `print.c`, `misc.c`, `symtab.c`, `troffgen.c`, `boxgen.c`,
`circgen.c`, `arcgen.c`, `linegen.c`, `movegen.c` or `textgen.c`. It is a *generation
older*: it uses an integer-slot symbol table (`getvar(lookup("boxht"))`,
`symtab[SYMTAB]` as an array) where the shipped files use string keys
(`getvar("boxht")`) and a malloc'd per-block chain (`symtab.c`). It carries its own
`#define MAXOBJ`/`MAXTEXT`/`SYMTAB`/`DEV202` block shadowing `pic.h`, and its line 12-14
comment is the evidence someone already noticed:
`/* But there's one of these in pic.h? -Bart` … `#define	MAXOBJ	400` … `*/`.
Adding it to a build gives duplicate definitions throughout.

**C8. `Jpic/y.tab.h` is a committed build product with a live dependency on yacc.**
Every Jpic `.c` does `#include "y.tab.h"`, the makefile declares `y.tab.h: picy.o` (i.e.
generated by yacc from `picy.y`), and `pic.ydef:` exists to detect when it changes
(`-cmp -s y.tab.h pic.ydef || cp y.tab.h pic.ydef`). The committed copy assigns
`PRINT 269 … UMINUS 329`; a yacc that numbers differently silently changes every token
value the hand-written `.c` files compare against. `pic.ydef` is not in the directory,
so the guard cannot fire on a first build.

**C9. `Jpic/makefile` references eight files that do not exist.** `lineseg`/`lineseg.o`
(:14-15), `gout.c` (:25), `gin.c` (:28), `grapic.c` (:41), `x.c` (:48-51), `picmemo`
(:39), and `WISH`/`UNDOC` (:23). Only `Export arcgen.c blockgen.c boxgen.c circgen.c
driver.c epic.c jp.c linegen.c main.c makefile misc.c movegen.c newspline pic.h pic1.c
pic2.c picl.l picy.y pltroff.c print.c symtab.c textgen.c troffgen.c y.tab.h` are
present. Also note `driver.c` is copied by the `src:` target but is in neither `OFILES`
nor `CFILES`, and it redefines `main()`, `getdata()`, `print()`, `extreme()`,
`dotline()` — a second stale near-duplicate, of the standalone `pltroff` front end.

**C10. `cip` has two calls to functions that are never defined — it cannot link clean.**
`cip/buttons.c:150` calls `clearKeyboard();` and `commands.c:112` calls
`clearKeyboard();`, but the definition at `buttons.c:202` is spelled
`clearKeyaboard()`. `readPic.c:102` calls `extractFontandPointSize(t);` while the
definition at `readPic.c:249` is `extractFontansPointSize(t)`. Per the project's own
note, V10's `ld` writes its output anyway with undefined symbols reported and the
execute bits cleared — so `cip.j` will appear to build and then be non-executable, and
`make install` will happily `cp` it to `/usr/blit/lib/cip.j`.

**C11. `68ld` has three copies of the same CRC-16 routine, and the makefile links one.**
`pcheck.c` (linked) holds it as C plus VAX and 68k `asm()` variants; `pcheck.sm` holds
the same 68k assembly standalone; `load.sm:120-263` embeds a third copy inside the
bootstrap. Neither `load.cm`, `load.sm` nor `pcheck.sm` is referenced by
`68ld/makefile` — `load.cm` is the C bootstrap (`/* Bootstrap for 68ld */`) and
`load.sm` its hand-assembled 68k translation, and nothing in the makefile builds or
installs either, though `68ld` cannot boot a bare terminal without the bootstrap being
resident. `load.sm` also re-declares `set PTYP,0xc0 / ACKON,0x80 / ACKOFF,0xc0 /
NOCRC,0x40` and `SEQMASK`, duplicating `proto.h:25-31` — except `proto.h:29-31` records
that the obvious `SEQMASK` is wrong (`/*#define SEQMASK ((~PTYP)&0xff) doesn't work */`,
replaced by `((~PTYP)&0x3f)`), and `load.sm:18` still carries the broken
`#define SEQMASK ((~PTYP)&0xff)`.

**C12. `blitblt` offers four print pipes; the README documents two, and none of the
scripts is in the tree.** `bbterm.c:28-31` menu items are `pipe to bcan`, `pipe to
3bcan`, `pipe to 4bcan`, `pipe to 8bcan`, and `blitblt.c:13-16` maps them to
`/usr/bin/{bcan,3bcan,4bcan,8bcan}`. `README:23-24` names only `bcan` and `4bcan`. The
directory contains `bcan.c` (which builds `bcan.out`, the *remote* half) but no `bcan`,
`3bcan`, `4bcan` or `8bcan` shell script, so the whole `/usr/bin` half of this package
has no source here. The README also states the remote half must be installed on two
*other* machines by name (`panther`, `ikeya`) — an install destination this build cannot
satisfy at all.

**C13. Two `jioctl.h` in two prefixes, and this one directory uses both.**
`emux.c:1` and `jermcap.c:2` include `/usr/jerq/include/jioctl.h`; `jterm.c:1` and
`jwin.c:1` include `/usr/blit/include/jioctl.h`. Both files exist
(`v10/usr/jerq/include/jioctl.h`, `v10/usr/blit/include/jioctl.h`). Four sibling
programs built by one makefile therefore compile against two separately maintained
copies of the header that defines `JEXIT`, `JTERM`, `JMPX` and `JWINSIZE`. Absolute
includes also mean `-I` cannot redirect them: these four files hardcode where the
running system's headers must be.

**C14. `jermcap` emits a termcap entry that depends on another entry existing.**
`jermcap.c:8` prints `li=#%d:co=#%d:tc=vitty:` — a `tc=` continuation of a `vitty`
capability. The only definition of `vitty` in this chunk is a *comment* in
`vitty.c:5-8`. Nothing installs it; if the termcap database has no `vitty`, jermcap's
output resolves to nothing.

**C15. `font/` builds five of its seven sources, and `char.h` describes a different
font format.** `Makefile:4` is `all: mtod dtoc showbits view finv` — `fd.c` (which has
its own `main()` printing `defont.n` and the strike geometry) has no rule, and `char.h`
is included by nothing here. `char.h` declares
`extern struct dispatch{ short *c_addr; char c_wid; char c_ht; char c_blank; }dispatch[];`
— the older PDP-11 `dispatch[]` font layout, not the `Font`/`Fontchar`/`Bitmap` triple
that every `.c` in the directory uses via `<font.h>`. It is a leftover.

**C16. Committed build products sit beside their sources.** Not in this chunk's file
list, but in these same directories and directly relevant: `v10/usr/blit/src/m.out`
(exactly the default output name `mopt.c:82` writes — `outfname = "m.out"`),
`v10/usr/blit/src/blitblt/bdump` (the target of `blitblt/Makefile:13-14`), and
`v10/usr/blit/src/font/defont` (the font data `mtod.c` dumps and `dtoc.c` reads). A

**C17. Runtime data paths point at a tree this chunk never populates.**
