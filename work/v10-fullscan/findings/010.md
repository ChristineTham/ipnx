## documented build steps

### `libj` (`makefile`, 92 lines) — `libj.a`, the Blit graphics/stdio library
- Tools: `CC=mcc`, `AS=mas`, `AR=ar`, `DCAN=dcan`; `CFLAGS=-O -m`. The `-m` flag is what
  makes objects use the ROM/`Sys` entry table; `README` in `mpx/term` warns those
  binaries all break if the table is reordered.
- Default target is the archive itself: `$L: $(OBJ)`, built member-at-a-time by two
  pattern rules (`$L(%.o): %.s` and `$L(%.o): %.c $(INCL)/jerq.h`), each doing
  `$(CC) -c … && $(AR) r $L $%.o && rm -f $%.o`.
- One special member rule: `texture.o` is `/lib/cpp -P texture.s > goo.s` then compiled
  (`makefile:54-56`).
- `new:` target (`makefile:49-52`) rebuilds ordering: `$(AR) uv $L \`mlorder $(FILES) | tsort\``
  then `$(AR) ma clip.o $L line.o` — i.e. **`line.o` must sit immediately after `clip.o`**
  in the archive. Extra tools needed: `mlorder`, `tsort`, `mstrip`, `mnm`, `mld`, `mopt`,
  `dcan`, `pp`, `qed`, `join`, `sort`, `sed`, `lint`.
- `.PRECIOUS: $L` (`makefile:91`) — the archive survives an interrupted make.
- 57 members in `OBJ`; per-member header dependencies are listed explicitly
  (`makefile:67-89`).

### `libmj` (`makefile`, 63 lines) — `libmj.a`, the *layered* (mpx) variant
- Same tools, but `CFLAGS=-O` **without `-m`**.
- Only 26 members. The `j*` entry points are re-implemented to go through
  `transform()`/`Drect`/`muldiv` so a program draws into its layer rather than the raw
  screen (compare `libmj/jcircle.c` with `libj/jcircle.c`).

### `life` — no makefile in the tree
`life.c` is the host half (reads/writes files on behalf of the Blit program) and
`mlife.c` the Blit half. The build is implied only by `life.c:21`, which downloads
`/usr/jerq/mbin/life.m`; nothing states how `mlife.c` becomes `life.m`.

### `lsh` (`makefile`, 12 lines) — list/create layers from the shell
- `term:` compiles `term.c` with `mcc -g`, runs `mopt a.out|grep "%"`, removes `a.out`,
  and renames `m.out` to `term`. So **`mopt` is a required step and it renames the
  output**; the built name is `term`, the installed name `lsh.m`.
- `host:` is `cc -g -o host host.c`.
- `install:` depends on `host term` and does the two `cp`s above.
- `script` is a two-line test input for `term` (four numbers + a command per line).

### `maze` (`makefile`, 47 lines) — a 4-player Blit maze game
- `.SUFFIXES: .c .o` with `.c.o: mcc -g -c $<`; `maze.m` links with `mcc -g -o maze.m $(OFILES)`.
- Host programs are built with plain `cc`; `Mazewar` additionally needs `-ldk`
  (`makefile:41`) — the Datakit library.
- `PROGS = maze.m mazewar Mazewar rmtmaze ump`; `all: $(PROGS)`.
- Two install targets, deliberately distinct: `install` (umpire host) and `rmtinstall`
  (non-umpire host).
- `$(OFILES): maze.h` (`makefile:36`).

### `mpx` (`makefile`, 63 lines) — the host-side layer multiplexer
- `CFLAGS = -I$(PDIR) -I$(JINCL) $(SFLAGS)` where `PDIR=proto`, `JINCL=/usr/blit/include`.
- Default target `mpx` links `mpx.o` plus the five protocol objects; `LIBS =` is empty.
- Three debug variants, each a **recompile of the same sources with different `-D`s**:
  `smpx` (`-DPSTATISTICS -DPSTATSDESC` on the protocol, `-DPSTATISTICS -DMPXSTATS
  -DPSTATSDESC` on `mpx.c`), `ssmpx` (`-DEBUG`), `tmpx` (`-DTRACING -DEBUG`). The
  `smpx.o`/`tmpx.o` rules `mv` the ordinary `mpx.o` aside and back, so the variants and
  the default target cannot be built concurrently.
- **No `install:` target.** Destination comes only from `README:4`.

### `mux` (`makefile`, 63 lines) — the successor to `mpx`
Structurally identical to `mpx`'s makefile with the names changed. Also has no
`install:` target. `mux.c` needs `NSYSFILE` (`mux.c:832`), hence the extra
`#include <sys/param.h>` at `mux.c:5`.

### `mpx/proto`, `mux/proto` (`makefile`, 26 lines each, identical) — `Plib.a`
- `CFLAGS = -O`; `Plib.a: $(OBJS)` then `ar rv Plib.a $(OBJS)` **followed by `ranlib Plib.a`**.
- `man: proto.3c` runs `nroff -man -Tlpr proto.3c >man` (`makefile:23`), and `print:`
  depends on `man`. `files` (the directory's own manifest) lists 12 names and **omits
  `man`** — confirming `man` is generated, not source.
- Note: nothing in `mpx/makefile` or `mux/makefile` ever builds or links `Plib.a`; they
  compile the five `proto/*.c` files individually. `Plib.a` is only reachable by running
  make inside `proto/`.

### `mpx/term` (`makefile`, 95 lines) — the Blit-resident terminal program
- Tools: `CC = mcc`, `AS = /usr/blit/bin/mas`, linker `mld`, `mnm`, `mstrip`.
- `CFLAGS = -g -O -m -DMPXTERM -I$(PDIR) -DBlit` — `-DBlit` switches the shared protocol
  sources into their no-`signal`/no-`alarm`/`spl1()` form (see `psend.c:20-24,43-45`,
  `ptimeout.c:22-24,63-66`, `precv.c:37-48`), and `pcheck.o` alone is compiled
  `-DROMCRC` (`makefile:70-71`) so the CRC table comes from ROM.
- Link: `mld -o mpxterm -b 256 Pl.o $(OBJS) rom.o -llayer -lsys -lj -lc` — **base
  address 256** and a fixed library order.
- Ordering the makefile *asserts by hand*: after linking it runs
  `mnm -g mpxterm | grep Sys` and prints `: Should be 0106` (`makefile:26-27`). That is
  the documented verification step; nothing enforces it.
- Multi-stage generated startup, in this order:
  1. `goo.s: makelocore /usr/blit/include/mpx.h /usr/blit/include/jerqproc.h Pl.template`
     — `makelocore` runs `qed - -x makelocore.q -e $MPXH` to renumber the entry table in
     `mpx.h`, sed's the entries into `Pl.template` after the `defont` line, then writes
     and assembles `notsolow.s` **into `/usr/jerq/lib/notsolow.o`**.
  2. `Pl.o: goo.s` — `$(CC) -S procsize.c`, then
     `sed 1s/999/\`sed -n '/short/s/.*\t//p' < procsize.s\`/ < goo.s > Pl.s`, then
     `$(CC) -c Pl.s`. So `PROCSIZE` is `sizeof(struct Proc)` extracted from a compiler
     listing.
  3. `rom.s: romroutines` — `sort romroutines | sed 's/\(........\).*/\1/' | join -j2 3 - romterm.nm | sed -f romsed.f > rom.s`.
     Needs `sort`, `sed`, `join`; `romterm.nm` (an `mnm` dump of the terminal ROM, 400
     lines) is the address source and `romroutines` the selection list (comments and `#`
     lines act as exclusions).
- `install: mpxterm` → `cp` + `mstrip` at the destination.
- `clean:` removes `*.o *.hup* goo.s core` — note it does **not** remove `Pl.s` or `rom.s`,
  both of which are committed.

## contradictions and traps

1. **`maze.m` is installed to `/usr/blit/lib` but looked for in `/usr/blit/mbin`.**
   `maze/makefile:16` `cp maze.m ump rmtmaze /usr/blit/lib`, but
   `maze/mazewar.c:20` `char *maze="/usr/blit/mbin/maze.m";`. A naive
   `make install` followed by running `mazewar` fails. `mazewar` does accept an override
   as `argv[1]` (`mazewar.c:21-22`), which is presumably how it was actually used.

2. **Two different programs install under the same name.** `maze/makefile:17` installs
   `mazewar` (built from `mazewar.c`) as `/usr/blit/bin/mazewar`; `makefile:24` installs
   `Mazewar` (built from `Mazewar.c`, `-ldk`) as `/usr/blit/bin/mazewar`. `install` and
   `rmtinstall` are mutually exclusive on a given machine and the makefile does not say so
   — only `READ_n_WEEP:5-8` explains it.

3. **`Mazewar.c` does not exist under that name in this tree.** `maze/makefile:26,40-41`
   reference `Mazewar.c`; `git ls-files v10/usr/blit/src/maze/*` shows
   `v10/usr/blit/src/maze/u_Mazewar.c` (the extractor's case-collision rename, against
   `mazewar.c`). `make all` / `make Mazewar` / `make pp` all fail as written. Note
   `u_Mazewar.c` is **not** in this chunk's list, so it is unread here.

4. **`libmj/makefile`'s `new:` target updates the wrong archive.** `libmj/makefile:1` is
   `L=libmj.a`, but lines 30-31 read `$(AR) uv libj.a \`mlorder $(FILES) | tsort\`` and
   `$(AR) ma clip.o libj.a line.o` — hardcoded `libj.a`, copied from `libj/makefile`
   without renaming. Running `make new` in `libmj` corrupts `libj.a` with `libmj` objects.
   (`libj/makefile:50-51` uses `$L` correctly.) The same paste also leaves
   `libmj/makefile:41,53,55` depending on a bare `line.h` where `libj` uses `$(INCL)/line.h`,
   and lines 44,53-56,61-63 declare dependencies for `defont.o`, `jlineto.o`, `jstring.o`,
   `line.o`, `menu.o`, `string.o`, `strwidth.o`, `wait.o`, `clip.o` — **none of which are
   members of `libmj.a`**.

5. **`libj`'s `texture.o` rule archives a file it never produced.** `libj/makefile:54-56`:
   `/lib/cpp -P texture.s > goo.s && $(CC) -c $(CFLAGS) goo.s && $(AR) r $L $%.o` —
   compiling `goo.s` yields `goo.o`, but `$%` is `texture.o`. `mpx/term/makefile:86-88`
   has the *same* rule done correctly: `mcc -c goo.s && mv goo.o texture.o`. The `libj`
   rule as written cannot succeed.

6. **A stale `goo` in `libj` is from the wrong machine.** `libj/goo` is left over from
   that cpp/compile dance, but its content is not texture at all: line 1 is
   `.file	"arith.c"` and the body is **WE32100** assembler (`save &.R1`, `addh2 0(%r1),0(%r0)`,
   `%fp`, COFF `.def/.val/.scl` directives) — the 3B/630 compiler's output, not the
   MC68000 `mcc`/`mas` syntax every other `.s` in `libj` uses. It is dead, and it is
   evidence somebody compiled `arith.c` here with a different toolchain.

7. **`printf.s` shadows `printf.c` through the pattern rules.** `libj/makefile:44` declares
   `$L(%.o): %.s` *before* line 46's `$L(%.o): %.c`, and `libj/printf.s` exists —
   a committed `mcc -S` listing (`stabs "printf.c",…`). Under first-match pattern
   selection `printf.o` builds from the stale assembler, not from `printf.c`.
   `libj/printf.out` is a second copy of the same listing with the C source interleaved as
   comments plus a leading `#  line 99999`. Neither `printf.s` nor `printf.out` appears in
   `CFILES`. `bitblt.s` and `texture.s` *are* the intended `.s` inputs (they are in
   `CFILES`), so the rule ordering is deliberate — which is exactly why the stray
   `printf.s` is dangerous.

8. **`oline.c` is a stale duplicate of `line.c` and defines the same symbol.** Both define
   `_line()`; `diff` shows `line.c` is `oline.c` plus the hand-written `asm("dbgt …")` DDA
   loops (its own comments call the removed version *"old, slower, but right"* and *"old
   stuff, cc makes it worse"*). Only `line.c` is in `OBJ`/`CFILES`. `oline.c` must not be
   compiled into the archive.

9. **`libj/jeldisc.c` is the `libmj` version.** It is byte-identical to
   `libmj/jeldisc.c` (`cksum` 
   match) and uses the layered convention — `eldisc(&display, transform(p), muldiv(a, Drect.corner.x-Drect.origin.x, XMAX), …)`
   — while every other `libj/j*.c` passes raw coordinates (`libj/jdisc.c` is just
   `disc(&display, p, r, f);`). `libj` is compiled `-O -m` with no `-DMPX`, so the
   `transform`/`Drect`/`muldiv` symbols it needs are not `libj`'s to supply.
   It also declares `extern Point Jtransform();` and then calls `transform()` — a
   name mismatch shared by all six `libmj/j*.c` files.

10. **`mux/proto/` is a byte-for-byte copy of `mpx/proto/`.** All 13 files match on
    `cksum` (`files`, `makefile`, `man`, `packets.h`, `pcheck.c`, `pconfig.h`, `pinit.c`,
    `precv.c`, `proto.3c`, `proto.h`, `psend.c`, `pstats.h`, `ptimeout.c`). Building both
    produces two identical `Plib.a`s; a fix applied to one silently misses the other.
    `mpx/mpxstats.h` and `mux/mpxstats.h` are likewise identical. Only `msgs.h` genuinely
    differs (`mpx/msgs.h` has `C_BRAINDEATH 6`; `mux/msgs.h` drops it and adds
    `C_KILL 9`, `C_PUSHLD 10`, `C_POPLD 11`).

11. **The man page and the header disagree on the packet size.** `proto.3c:203-204`
    (and `proto/man:156`) say `MAXPKTDSIZE` / `32 (limited by buffering in system)`;
    `proto.h:14` says `#define	MAXPKTDSIZE	(64 * sizeof(Pbyte))`. `psend.c` and
    `mpx.c:445-446` size real buffers from the header, so the documented 32 is wrong.

12. **The man page documents an include path the build does not use.** `proto.3c:5` is
    `#include <proto.h>`, but every source uses `#include "proto.h"` and the makefiles
    supply `-I$(PDIR)` / `-I../proto`. Nothing in this chunk ever installs `proto.h` into
    an include directory, so the documented usage is unsupported as shipped.

13. **`psend`'s documented signature is not the one that gets compiled.** `proto.3c:17-23`
    and `man:21-24` give `int psend(channel, ptr, size)`; under `-DBlit` (which
    `mpx/term/makefile:3` always passes) `psend.c:23` is `psend(channel, bufp, count, type)`
    — a fourth argument, and `mpx/term/control.c:126` calls it with four. A linear read of
    the man page gets the host-side branch and misses the terminal-side one; the same
    `#ifndef Blit` / `#else` split governs `pinit` (`pinit.c:24-27,58-61` — no
    `MAXPCHAN` check, no `signal(SIGALRM)`), `precv` (`precv.c:37-48` — one char at a
    time, not a buffer), and `ptimeout`.

14. **`pcheck.c` has three mutually exclusive bodies and the fall-through is not the
    common case.** `#ifdef vax` gives a `crc` built on the VAX `crc` instruction with an
    `asm("	crc	_crc16t,$0,8(ap),*4(ap)	")`; `#else` + `#ifndef mc68000` gives portable
    C; `#else mc68000` + `#ifndef ROMCRC` gives inline 68000 `asm(…)`. Under the terminal
    build (`-DBlit … -DROMCRC`, `mpx/term/makefile:71`) **all three are compiled out** and
    `crc` comes from ROM — `mpx/term/display.c:4-5` supplies it as
    `asm("set	crc,	0x4036c")` / `asm("global	crc")`. Reading `pcheck.c` alone and
    concluding `crc` is defined there is wrong for the terminal program. Note also that
    `pcheck.c:133-134` closes with `#endif	mc68000` then `#endif	ROMCRC` — the labels are
    swapped relative to the `#ifdef` order.

15. **Committed build products sitting beside their generators, in `mpx/term`.** Every
    stage of the startup chain is checked in:
    - `Pl.template` (`set PROCSIZE,999`, no entry table) → `goo.s` (still
      `set PROCSIZE,999`, entry table inserted, and ending with a leftover
      `#endif	MPX_H` at line 88 from the sed of `mpx.h`) → `Pl.s` (`set PROCSIZE,2312`).
      `goo.s` is what `clean:` deletes; `Pl.s` is not, and both are committed.
    - `notsolow.s` is a committed copy of the heredoc `makelocore:15-33` writes, with the
      entry numbers already substituted (`mov.l	17 * 4 + 0406, %a0` for `jinit`,
      `14 * 4 + 0406` for `exit`), so it is output, not input.
    - `procsize.s` is the committed `mcc -S` of `procsize.c`, carrying `short	2312`.
    - `rom.s` is the committed output of the `sort|sed|join|sed` pipeline.
    - `x.c` / `x.s` are a scratch pair (`main(){ foo(&P->stack[STKSIZ-4]); }` and its
      listing) referenced by no rule.
    - `git ls-files` also shows `v10/usr/blit/src/mpx/term/mpxterm` (the linked Blit
      binary) and `v10/usr/blit/src/mux/mux` committed in these directories, plus
      `v10/usr/blit/src/libj/f` and `libj/h` beside `f.c`/`h.c`. None of these six are in
      this chunk's list.

16. **Three different hardcoded `sizeof(struct Proc)`-derived offsets.** `procsize.s:7`
    says `short	2312`; `mpx/term/x.s:13` says `add.l	&2308,%a0` for
    `&P->stack[STKSIZ-4]`; and `mpx/term/boot.c:111,119` hardcode
    `lea.l	2298(%a0), %sp	/* &P->stack[STKSIZ]-4 */` in inline asm — a value the build
    never derives and never checks. If `struct Proc` changes, only `Pl.s` follows.

17. **`bigrom.s` is an unreferenced alternative to `rom.s`.** No rule mentions it. It
    covers a different ROM: it *adds* `auto1`, `cursallo`, `cursinhi`, `cursinit`,
    `cursrest`, `cursswit`, `nap`, `lbitblt`, and *comments out* `defont`, `jstrwidt`,
    `menuhit`, `strwidth` (`bigrom.s:57-58,93-94,119-120,171-172`) — exactly the four that
    `romroutines` leaves enabled and `rom.s` therefore defines. Using it would silently
    change which symbols resolve to ROM and which to `libj.a`.

18. **`rom.s` (and `bigrom.s`) define `aciainit` twice.** `rom.s:21-24`:
    `set aciainit, 0x40204` then `set aciainit, 0x4128e`, both `global`. It is not a
    typo in the generator — `romterm.nm:152-153` genuinely lists two `aciainit`
    (`40204 t` and `4128e T`), and the `join`+`sed` pipeline has nothing that picks one.
    Whichever the assembler keeps decides where ACIA init lands.

19. **`romroutines` uses `#` both as a section comment and as an exclusion.**
    `romroutines:1,6,19,29,39,52,67,72,73,77,85,92,95,102,111,114` are headings, but
    `:56 #lbitblt`, `:68 # string`, `:86-89 #cursinhibit/#cursallow/#cursinit/#auto1`,
    `:94? #cursswitch` are deliberate omissions. The pipeline's `sort` puts both kinds
    together and `join` drops all of them, so the two meanings are indistinguishable from
    the file alone.

20. **`makelocore`'s own usage message names a file that does not exist.**
    `makelocore:7` prints `echo usage makelocore Pl.s jpx.h Pl.template mas` — `jpx.h`,
    where the caller (`mpx/term/makefile:41`) passes `/usr/blit/include/mpx.h` and
    `README:8` calls it `mpx.h`. Also, the script writes `notsolow.s` into the **current
    directory** and its object into `/usr/jerq/lib`, mixing the two roots the rest of the
    directory keeps separate.

21. **`/usr/jerq` and `/usr/blit` are used as the same root by different files in the same
    tree.** `libj/makefile:2` and `libmj/makefile:2` compile against `/usr/jerq/include`;
    `mpx/term/makefile:1` compiles the program that links `libj.a` against
    `/usr/blit/include`, and `mpx/term/makefile:23` expects `libj.a` in `/usr/blit/lib`.
    `mpx/term/README` (same directory as that makefile) speaks only of `/usr/jerq/src/lib`,
    `/usr/jerq/src/mlib`, `/usr/jerq/src/sys`, `/usr/jerq/include`. `lsh/makefile` installs
    to `/usr/jerq/{mbin,lib}` while `maze/makefile` installs to `/usr/blit/{lib,bin}` — and
    `maze/mazewar.c:20` reads `/usr/blit/mbin`, the `mbin` convention from the `jerq` side.
    The tree is mid-rename from `jerq` to `blit` and no file states the mapping.

22. **`mpx` has no install rule; `README` is the only authority, and it disagrees with
    the runtime path.** `mpx/README:4` says the host binary goes to `/usr/jerq/bin/mpx`,
    while everything that binary touches at runtime is under `/usr/blit`
    (`mpx.c:23,716`). `mux` has neither an install rule nor a README.

23. **`mpx/term`'s `Mpxterm` target is built and never installed.** `makefile:34-38`
    produces `Mpxterm` (linking `display.o` instead of `rom.o`, and with `-lsys -llayer`
    in the opposite order to `mpxterm`'s `-llayer -lsys`), but `install:` (line 90) depends
    only on `mpxterm`. `display.c` is the non-ROM display definition; `rom.o` is the ROM
    one. Which of the two is "the" terminal program is not stated.

24. **`mpx/term/makefile:86-88` has a `texture.o` rule for a file that is not in this
    directory.** `texture.s` lives in `libj`. Nothing in `mpx/term` requests `texture.o`
    either. Dead rule, carried over from `libj/makefile`.

25. **`libj/exit.c` and `libmj/exit.c` differ in a way that matters.**
    `libj/exit.c:5` is `exit()` with no parameter and calls `fclose(f)` then `reboot()`;
    `libmj/exit.c:5-7` is `exit(i)` with **`i` declared both as the parameter and as a
    `register int` local**, calls `fflush(f)` and ends with `Tvoid(14)()` — an indexed
    call through the `Sys` entry table. `Pl.s:26` confirms slot 14 (0-based from `add` at
    slot 0... counting from `Sys[2]`) is `Uexit`. The two libraries are not
    interchangeable and neither file says so.

26. **`/dev/pt/*` error messages name the wrong node.** `maze/rmtmaze.c:15,17` opens
    `/dev/pt/maze` and reports `perror("/dev/pt/ump")`; `mazewar.c:28,30` does the same;
    `toump.c:15,19` opens `/dev/pt/maze` and reports `perror("pt18")`. A failure here
    sends you looking at the wrong device node.

27. **`libj/dprintf.c`, `f.c`, `h.c` are in the directory and in no list.** `dprintf.c` is
    a near-copy of `printf.c`'s `_doprnt` (it duplicates the `sprintn` definition, so it
    cannot be linked alongside `printf.o`); `f.c` and `h.c` are two scratch `main()`s that
    scribble XOR lines on the display, each with `#undef MPX` at line 2. None appear in
    `OBJ`, `FILES` or `CFILES`. Their committed compiled forms (`libj/f`, `libj/h`) sit
    beside them.

28. **`libj/bitblt.C` and `libj/texture.C` are the C originals of the shipped `.s` files.**
    `CFILES` lists `bitblt.s` and `texture.s`; the `.C` files are not listed anywhere.
    `bitblt.C` is C with 60-odd `asm("…")` strings interleaved (it relies on `mcc` putting
    named locals in specific registers — `/* %a2-%a5 */`, `/* %d2,%d3,%d4 */` at lines
    13-15, and warns `register Pkt_p pkp; /* WARNING *** used as r10 in "asm" below */`
    in `psend.c:40`). Compiling the `.C` instead of the `.s` would be a different program.
    On a case-insensitive filesystem `bitblt.C`/`texture.C` would collide with a
    hypothetical `bitblt.c`/`texture.c`; `git ls-files` confirms only the `.C` spellings
    exist, so there is no `u_` twin here.

29. **`mpx/pconvs.adb` is an `adb` script, not source.** Eight lines of `adb` format
    directives (`./"pkt0 "36b`, `+/"state "b" timo "b" size "b" retrys "b`, …) that dump a
    `struct Pchannel`. Named `.adb`, listed in no makefile, and matched by
    `mpx/makefile:57`'s `pp -tmpx *.h *.c proto/*.?` only by accident of the `.?` glob
    (`proto/*.?` matches `proto.h` and the `.c`s, not `.adb`).

30. **`mpx/term/procsize.c` cannot be compiled to an object usefully.** It is
    `#include <jerq.h>` + `int x=sizeof(struct Proc);`. The build only ever runs
    `$(CC) -S procsize.c` (`makefile:44`) to read the number out of the listing. If a
    harness "builds procsize.c" it has done nothing the build wants. Note also that the
    committed `procsize.s:2-3` carries `comm Jdisplay,4` / `comm Drect,8` — so the sed
    that extracts `/short/` would match `short	2312` at line 7 and nothing else, which is
    the only reason the one-liner works.
